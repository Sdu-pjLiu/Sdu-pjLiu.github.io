AI-Agent工程学习-LLM基础学习(一)

发表于 2026-07-13 更新于 2026-07-15 分类于 计算机
LLM 底座名词（一）：Transformer、Attention、Tokenization、Embedding、Context Window，以及与 Agent / RAG 的关系。

从LLM基础知识到Agent工程的学习记录

1. Transformer

什么是Transformer？

通俗来讲，Transformer是一种让AI理解一整段文本中所有词之间关系的神经网络架构。他最核心的能力是通过 Self-Attention（自注意力机制），让模型能够理解输入序列中不同 Token 之间的关系。

负责：理解输入 -> 建立上下文关系 -> 生成输出

主要解决的问题为：

  1. 长距离依赖。
  2. 并行计算
  3. 更容易拓展

1.1 Encoder / Decoder / Decoder-only

原始 Transformer 有两类结构：

  1. Encoder：偏向「读懂整段输入」（如 BERT 一类理解任务）。
  2. Decoder：偏向「按位置逐步生成下一个 Token」。

现代生成式 LLM（GPT、Llama 等）几乎都是 Decoder-only：只有 Decoder 堆叠，一边读已有 Token，一边预测下一个 Token。不要把「通用 Transformer 论文结构」和「现在聊天用的 LLM」直接等同。

1.2 Position Encoding

Token Embedding 只表达 Token「是什么」，不表达「在序列中的位置」。Position Encoding 补上位置信息，使模型能区分同一 Token 出现在不同位置时的不同含义。

常见做法：

  1. 绝对位置编码：给第 1、2、3… 个位置各自一套固定或可学习的位置向量。
  2. RoPE（Rotary Position Embedding）：用旋转方式把位置写进 Attention 的 Q/K，Llama 等模型常用。对更长 Context、位置外推通常比朴素绝对位置更友好。

工程上谈「长上下文能力」，既看 Context Window 大小，也和 Position Encoding 能否外推有关。

1.3 Transformer Block

实践中一个 Block 通常不是「算完 Attention 再算 FFN」的裸堆叠，而是带 残差连接（Residual） 与 层归一化（LayerNorm） 的子层：

要点：

  1. Self-Attention：算 Token 之间关联（见第 2 节）。
  2. FFN：对每个位置做特征加工。
  3. Residual（残差）：把子层输入加回输出，减轻深层网络难训练、信息难传递的问题。
  4. LayerNorm：稳定各层数值尺度，利于训练与推理。

（Pre-Norm / Post-Norm 只是 Norm 放在子层前或后的变体，名词级先记住「Attention / FFN + 残差 + Norm」即可。）

2. Attention Mechanism

Attention Mechanism 是一种让模型动态决定当前 Token 应该关注哪些其他 Token 的机制。简单来讲是模拟人的注意力。

Self-Attention（自注意力）

一个序列内部：每个 Token 都可以关注其他 Token。

2.1 Causal Attention（因果注意力）

生成式 Decoder-only 模型里，预测第 t 个位置时，只能看第 1～t 个 Token，不能看未来 Token。实现上通常给 Attention 加 mask，因此也常称 Masked / Causal Attention。

这是自回归生成的前提，也是 KV Cache 能成立的原因：历史 Token 的 Key / Value 算完就固定了，新 Token 只需增量计算自己的 Q，再与已有 K、V 做 Attention。

2.2 QKV 机制

Attention 的核心是 Query（Q）、Key（K）、Value（V）。

Query（Q）：当前 Token 想寻找什么信息。例如「他」在找——谁是这个人。

Key（K）：其他 Token 提供什么特征。例如「小明」提供——人物信息。

Value（V）：Token 实际包含的信息。例如「小明」对应的具体语义内容。

2.3 Attention 计算过程

2.4 Attention 数学机制

核心公式：

$$\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\left(\frac{QK^{T}}{\sqrt{d_k}}\right)V$$

其中：

  1. $QK^{T}$：Query 与所有 Key 的匹配分数。
  2. $\sqrt{d_k}$：按 Key 维度缩放，避免点积过大导致 Softmax 梯度消失。
  3. $\mathrm{softmax}(\cdots)$：把分数转成和为 1 的 Attention 权重。
  4. 再与 $V$ 加权求和，得到新的 Token 表示。

Softmax（补充）：一种把一组实数变成 概率分布 的函数——输出每项在 $(0,1)$，且总和为 1。Attention 里用它把「匹配分数」变成「关注权重」；第二篇选下一个 Token 时，也会对 Logits 做 Softmax 得到词表概率。同一数学工具，两处用途不同。

2.5 Multi-Head Attention

不是只算一组 QKV，而是并行多组（多个 head），每组关注不同类型的关系，再拼起来。工程资料里说的 Attention，多数指 Multi-Head Self-Attention。

2.6 Attention 的计算复杂度

Self-Attention 复杂度为 O(n²)，n = Token 数量。每个 Token 都要和其他 Token 算关系。

例如：1000 Token → 1000×1000 次；100000 Token → 100000×100000 次。这是 Context Window 不能无限增大的主因（见第 5 节）。

2.7 Attention 优化技术

Flash Attention：不改变数学结果，通过分块与减少高带宽显存读写加速 Softmax Attention；降显存、提速。

Sparse Attention：只关注局部窗口或部分位置，降低长序列计算量。

Linear Attention：改写 Softmax / 核形式，把复杂度从 O(n²) 降到接近 O(n)（常有精度折中）。

KV Cache：生成时缓存历史 K、V；新 Token 只算自己的 Q，再与缓存做 Attention，避免重复计算历史状态。

2.8 Transformer 与 Attention 的关系

  1. Transformer 是整体架构。
  2. Attention 是 Transformer Block 的核心计算。

Transformer ≈ 大脑结构；Attention ≈ 注意力计算机制。

3. Tokenization（分词）

Tokenization（分词）是指：将人类语言文本转换成大语言模型能够处理的 Token 序列的过程。不同模型的 Tokenizer，结果可能不一致。

例如「人工智能」可能切成「人工 / 智能」，再变成 Token ID（如 1234, 5678）。模型最终处理的是数字序列。

3.1 Tokenization 的作用

  1. 将自然语言数字化：文字变成 Token ID。
  2. 控制输入长度单位：Context Window 以 Token 计数（详见第 5 节）。
  3. 建立语言统计规律：Tokenizer 根据语料里高频字符组合决定子词切分；高频更紧凑，低频 / 新词可拆成已知子词。

3.2 Tokenization 类型

Character Tokenization（字符级）：每字一个 Token。词表小、无未知词；但 Token 数多、长文本效率低。

Word Tokenization（词级）：整词一个 Token（如 I / love / AI）。语义完整；词表巨大。

Subword Tokenization（子词）：现代 LLM 主流（如 un / believe / able）。词表适中、能处理新词、效率较高。GPT、Llama 等主要采用这种方式。

3.3 常见 Tokenizer 算法

BPE（Byte Pair Encoding）：GPT 系列常用；不断合并高频字符组合；简单高效。

WordPiece：BERT 使用；按统计概率选最优子词。

SentencePiece：常用于 Llama、多语言模型；直接处理原始文本、不依赖空格；适合中文、日文、多语言。

3.4 Token 数量与成本关系

LLM API 通常按 输入 Token + 输出 Token 计费。例如输入 10000 + 输出 2000 = 总计 12000 Token。

3.5 Token 与中文英文区别

不同语言 Token 效率不同。英文 Artificial intelligence、中文 人工智能 都可能约 2 Token，但复杂中文常切得更碎，Token 更多，从而更占 Context、费用更高。切分规则由 Tokenizer 决定，不是「一字一 Token」。

3.6 Tokenization 对 Agent 的影响

Agent 大量消耗 Token 的环节：Prompt、Tool 结果、历史消息、RAG 文档、思考过程。优化可与第 5 节 Context 管理配合：Prompt / Context 压缩、RAG 检索、Memory 总结。

4. Embedding（向量表示）

什么是 Embedding？

把文本、Token、图片等信息转换成高维向量。简单理解：把「语言」放到「数学空间中的位置」。语义相近（如猫与狗）的向量距离也近。

4.1 Embedding 的作用

  1. 理解语义：靠向量远近表达相似关系。
  2. 语义搜索：文字不同也可判为相近（如「如何降低广告成本」与「降低 PPC 花费的方法」）——比较的是向量相似度，不是字面是否相同。
  3. 支持 RAG：用向量检索相关内容后再塞进 Context（流程见 4.6）。

4.2 Embedding 工作机制与 Embedding Matrix

核心：Token ID 查找 Embedding Matrix 得到向量。

Matrix 本质是大表：例如词表 100000、维度 4096 → 矩阵 100000 × 4096，每一行是一个 Token 的向量。

Embedding 在训练中被调整：如「猫喜欢吃鱼」中「猫」常与动物相关词共现，训练后向量会靠近相关概念。

4.3 两类容易混淆的 Embedding

类型 是什么 典型用途
LLM 内的 Token Embedding 模型词表里的查表向量，进入 Transformer 生成式 LLM 内部计算
Embedding Model（句子 / 文档向量模型） 独立或专用的向量化模型 / API，输出句向量、段向量 语义搜索、RAG、向量数据库

RAG 检索用的通常是后者，不是把 LLM 词表里的 Token Embedding 直接当检索向量。下文 Sentence Embedding / Document Embedding 多指 Embedding Model 这一路。

4.4 Embedding 类型（按粒度）

Token Embedding：单个 Token → 向量；供 Transformer 使用。

Sentence Embedding：一句话 → 一个向量；用于搜索、分类、相似度。

Document Embedding：整篇 / 大段 → 一个向量；用于知识库等。

4.5 向量相似度计算

向量库常见几种：

  1. Cosine Similarity（余弦相似度）：看夹角；越接近越相似。
  2. 内积（Dot Product）：方向与模长共同影响；部分向量库默认用此排序。
  3. 欧氏距离（L2）：看直线距离；距离越小越相似。

选型取决于 Embedding Model 与向量库配置，需与入库时一致。RAG 中：问题向量与 Chunk 向量比相似度，取 Top-K 写入 Context Window。

4.6 Embedding 与 LLM、RAG、Tokenization

与 LLM：进入 Transformer 之前，主要是 Token Embedding（Token ID → Matrix → 向量），链路见第 3 节开篇。

与 RAG：文档切 Chunk → Embedding Model 向量化 → Vector Database；提问同样向量化 → 搜相似 → 返回知识。

与 Tokenization：Tokenization 把文字变数字；Embedding 把数字（或整句）变语义向量。

4.7 Embedding 优化方向

  1. 更高维：表达更强，存储更贵。
  2. 更好的 Embedding Model：通用 vs 行业场景，能力差很多。
  3. Chunk 优化：过大信息混杂，过小缺上下文。

5. Context Window（上下文窗口）

什么是 Context Window？

一次推理中，模型能同时处理的最大 Token 数量。例如 128K ≈ 最多约 128000 Token。

输入 + 输出都要占窗口：Prompt、历史、检索占输入侧；生成回答占输出侧。调 API 时常见做法是：总窗口里先给输出预留额度，剩下的才给输入，否则答到一半会截断。

5.1 Context Window 的作用

  1. Prompt 上限：System Prompt + 用户输入 + 历史消息都占 Context。
  2. 对话「记忆」：所谓记住前文，本质是应用把历史再放进本次 Context。
  3. Agent 复杂度：目标、步骤、Tool 结果、中间状态、检索内容都靠它装；越大越能撑复杂任务。

5.2 工作机制

5.3 本质与限制原因

本质：Transformer 能参与 Attention 的最大 Token 序列长度（处理的是 Token，不是「一段文字」这几个字本身）。

限制主因是 Self-Attention 的 O(n²)（详见 2.6）：Context 越长，计算与显存越贵。

5.4 Context 增大的问题

  1. 显存涨：Attention、Hidden State、KV Cache 都变大。
  2. 更慢：输入越长，耗时越长。
  3. Lost in the Middle：太长时中间信息可能用不上（如百页文档问到中间页）。

5.5 Context Window 与 Memory

Context Window Memory
定义 当前一次推理可见的信息 长期保存的信息
特点 临时、随请求结束 可跨任务
类比 工作记忆 长期记忆

关系：Memory → 检索相关信息 → 加入 Context Window → LLM 推理。

5.6 Context Window 与 RAG

知识库太大，无法整库塞进 Context。做法：只检索 Top-K 相关内容写入窗口（检索与向量化详见 4.6）。RAG 是「用检索换 Context 容量」的典型方案。

5.7 优化方法与 Agent

常见优化：

  • Context Compression：如 10000 Token 压成 1000 Token 摘要。
  • Summarization Memory：历史先总结再保存，避免对话无限变长。
  • Sliding Window：只保留最近 N 轮（如 20 轮）。
  • Retrieval：不整存，需要时再取。

Agent：搜索 → 读网页 → 分析 → 调工具 → 写报告，会堆出大量 Tool 结果、中间状态、思考过程，是 Context 高消耗场景。管理上除上述手段外，常加 Context Selection（只留重要内容）与 Context Isolation（不同 Agent 用不同 Context）。

总结

Transformer：Decoder-only 为主；Token Embedding → Position Encoding（含 RoPE 等）→（Attention + FFN，各带残差与 LayerNorm）→ 预测 Token。

Attention：QKV + Causal mask；Softmax 把分数变成权重；O(n²)；Flash / Sparse / Linear / KV Cache 用于加速或降本。

Tokenization：文本 → Token ID；定长度单位与费用；Agent 场景下消耗大。

Embedding：LLM 内 Token Embedding ≠ RAG 用的 Embedding Model；相似度可用 Cosine / 内积 / 欧氏距离。

Context Window：输入 + 输出共享上限，输出需预留；与 Memory、RAG、压缩策略一起管长任务。
