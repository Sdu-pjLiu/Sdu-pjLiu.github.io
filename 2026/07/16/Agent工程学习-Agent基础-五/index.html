AI-Agent工程学习-Agent基础(五)

发表于 2026-07-16 更新于 2026-07-17 分类于 计算机
Skills/Tools 膨胀、Context 压缩时机、记忆故障模式与 Runtime 旁路坑；Skill 认名见（三）。

接Agent 基础（四）：会选型、会评测之后，补三类高频工程坑。

0. 本篇位置

一～四已覆盖：闭环与 State、推理/规划模式、记忆四层与 Runtime、轨迹评测与 Research 地图。

本篇只回答三件事：

  1. 能力目录（Tools / Skills / Procedural）膨胀时怎么管
  2. Context 何时压缩、压什么、如何与 State 对齐
  3. 记忆写错 / 读脏时有哪些失败模式

回链：失败模式（一）、轨迹指标（四）。

1. 能力膨胀（Tools、Skills、Procedural）

Skill 认名见（三）§1.4；结构深化与 MCP 见（六）§1。本篇只讲目录过大时如何治理。

产品侧常叫 Skills；协议侧是 Tools；工程层落在 Procedural。三者膨胀时症状相同。

1.1 问题现象

  1. 选型准确率下降：无关工具被反复点名。
  2. System / tools 列表本身占满窗，挤掉 Goal 与硬规则（Lost in the Middle）。
  3. 描述相似 → 参数幻觉、「假调用」增多。

1.2 分层：始终在窗 / 目录 / 按需加载

原则：目录可以大，同时可见的 Action Space 必须小。L0 建议控制在少量核心工具；其余走 L1→L2。

1.3 治理策略

策略 适用 代价
按任务类型裁剪白名单 任务类型清晰 要维护路由表
元工具（如 find_skill / list_tools） 技能库大 多一轮；需防空转
Progressive disclosure（先目录后全文） Skill 类资产多 描述「何时用/不用」必须写清
拆专员 / Handoff 领域互斥 交接触上下文（见 §4）

1.4 描述质量与回归

每条 Tool / Skill 至少写清：何时用 / 何时不用。Schema 描述含糊 → 选错工具或参数幻觉；执行前仍做 Validation（工具治理（三））。

加技能后要用轨迹指标回归是否变差（（四））：

  • Tool Accuracy（选型） 是否掉点
  • Unnecessary Tool Calls 是否上升

2. Context 生命周期：何时压缩、压什么

2.1 与已学的分工

已学 负责
LLM 一 · 5.7 压缩 / 摘要 / 滑动窗 / 检索（手法认名）
PE 一 · 4.3 预算不够时先砍什么
（三）· 2.2 硬规则不可摘要

本篇补：触发条件 + 与 Working state / Checkpoint 对齐。

2.2 触发条件

触发 示例阈值（可调） 动作
窗口水位 输入占用 > 60%～70% 预算 压缩冷 Trace / 旧 Observation
步数 / 阶段边界 每 K 步或 Planner 阶段结束 阶段摘要 + 更新 Working state
单次 Observation 过大 Tool Result 超 Token 阈值 先裁剪再写回
阶段切换 搜索 → 分析 → 成稿 隔离：成稿不带原始网页全文
预算告急 剩余 steps / tokens 低于阈值 强制压缩 + 禁止新开大检索

场景片段： 当前输入已占窗口 68%，且搜索阶段结束 → Runtime 将旧网页压成摘要、更新 done[]，再进入分析阶段。

2.3 压 / 不压清单

必须保留（全文或结构化字段） 可压成摘要
Goal、验收标准、安全/权限硬规则 冗长 Thought
工具白名单要点、未完成副作用记录 早期成功的 Tool 原文
当前 open[] / 关键实体 ID 重复历史轮次
Checkpoint 恢复所需字段 已完成节点的详细 Observation

2.4 压缩后一致性

风险：摘要丢掉禁止事项 → 行为漂移（回链（三））。

旁注：中途无差别重写大段历史，可能影响 Prompt / KV Cache 命中；长任务优先 追加摘要 + 滑动丢掉原文，少做全量重写。

2.5 压缩 vs 检索 vs 隔离

手段 何时优先
Sliding / 摘要压缩 单会话轨迹变长
Retrieval 再注入 事实在外存，不必常驻
Context Isolation 多阶段 / 多角色，避免串味

3. 记忆故障手册

分层定义回链（三）§1，此处只谈失败模式。

3.1 失败模式字典

模式 症状 防护
写污染 幻觉当事实入库，后续越用越错 写入需 Observation / 用户确认；高风险字段 HITL
脏读 / 过期 旧偏好或旧事实盖住新结论 时间戳 + 来源优先级；冲突显式规则
检索噪声 Top-K 挤掉当前 Instruction 注入限额；低相关先砍（PE 一 4.3）
摘要漂移 压缩丢掉硬约束 不可摘要字段；压缩后校验清单
Checkpoint 误用 用故事日志当运行态续跑 Checkpoint = 可恢复 state；Trace = 复盘
偏好越权 「用户说过」突破安全边界 偏好不得覆盖 system 硬规则

场景片段： 模型猜测「用户偏好英文」并写入 Memory，后续会话持续错误地输出英文 → 防护：无用户确认或工具证据时，不允许持久化该偏好。

4. Runtime 旁路坑（短）

与前三节咬合的最小门禁（细节回链（一）停止条件、（三）Runtime）：

  1. 工具死循环：同一 tool + 同参连续 N 次 → 打断并换策略。
  2. 假完成：无 Observation 支撑禁止标 Success。
  3. 澄清循环：Ask User 次数设上限，超限则停止或降级。
  4. 重规划上限：避免每步推翻地图（（二）Dynamic Planning）。
  5. Handoff 必带：Goal 摘要 + 已完成/未完成 + 硬规则引用（多 Agent 认名级）。

正向设计（可机检合同、验证门、优雅收尾）见 Loop Engineering（一）、（二）。

总结

能力膨胀：目录可大，同时可见工具集要小；L0 核心 + L1 目录 + L2 按需；用选型与无效调用指标回归。

Context 生命周期：按水位 / 步数 / Result 大小 / 阶段切换触发；硬规则与运行态字段不压；压缩后同步 State 并记 Trace。

记忆故障：防写污染、脏读、噪声、摘要漂移、Checkpoint 误用、偏好越权；写入要有依据。

Runtime 旁路：死循环、假完成、澄清与重规划上限、Handoff 带齐字段。
