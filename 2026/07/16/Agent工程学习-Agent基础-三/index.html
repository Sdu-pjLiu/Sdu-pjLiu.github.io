AI-Agent工程学习-Agent基础(三)

发表于 2026-07-16 更新于 2026-07-17 分类于 计算机
Agent 记忆四层（含 Skill 认名）、RAG 挂法、工具治理、Runtime（预算/HITL/护栏/可观测），以及多 Agent 认名。

接Agent 基础（二）：Loop 与规划会跑之后，弄清记忆从哪来、工具怎么管、Runtime 如何兜底。

1. 记忆：工程四层（不是模型超能力）

始终记住：没有写入本次 messages 的内容，本轮看不见。Memory 是 工程机制：决定把什么检索出来、塞进 Context Window。

1.1 四层总览

工程层 存什么 典型实现
会话内 Context 近期对话、当前约束、刚发生的工具结果摘要 滑动窗口、保留最近 K 轮
任务轨迹 Trace 「这次任务」步骤与 Observation；可恢复检查点 回合日志、Checkpoint
外存知识 可检索事实 / 文档块 向量库、FAQ、实体库
Procedural / 技能 怎么做：流程模板、工具用法、失败重试策略 代码函数、Prompt Registry；Skill 认名见§1.4，深化见（六）

Long-term = 跨会话持久化策略，通常覆盖「外存知识 + 部分轨迹摘要 + 偏好字段」，而不是再发明一个说不清边界的第五层。

1.2 Checkpoint

在步骤边界持久化 可恢复运行态（计划进度、已完成节点、副作用记录）。用途：崩溃恢复、长任务暂停、人工审批后继续。

与「情景故事」日志：Checkpoint 偏运行态；Trace 摘要偏复盘与 few-shot。

1.3 名词对照表（认名即可）

学界/产品文案不一，对照到工程层即可：

常见叫法 更靠近哪一层
Short-term 会话 Context
Working Memory 结构化任务 state（Goal、open[]、done[]）
Episodic Trace / 任务故事
Semantic 外存知识（常接 RAG）
Procedural 技能与流程
Long-term 跨会话持久化（多种并写）

1.4 Skill 认名（Procedural 的产品形态）

Skill = 可发现、可版本、按需注入 Context 的程序性知识包。产品侧常叫 Skills；协议侧是 Tools；记忆层是上文 Procedural。不是同义词。

最小结构（产品无关）：

字段 作用
name 目录与路由标识
description 何时用 / 何时不用（选型最关键）
body 步骤、约束、检查清单
可选 allowed-tools 本 Skill 允许调用的工具子集

与相邻概念（简对照）：

概念 解决什么
Skill 这类任务怎么做（程序性）
Tool 执行什么动作
RAG 文档 事实与材料是什么
Prompt Template 某一步的输入合同

生命周期、编写评测、目录膨胀治理分别见（六）§1、PE 四、（五）§1。

2. Retrieval 与 Compression

2.1 Memory Retrieval

  1. 触发：每步 / 规划前 / 用户提及时
  2. 键：query 改写、任务类型、实体 ID
  3. 注入：原文 / 摘要 / 仅 ID+标题（防爆窗）
  4. 冲突：多条矛盾时规则谁优先（时间、来源权威、用户确认）

2.2 Memory Compression

为何：Context 预算、费用、关键信号占比（见 PE 一裁剪顺序、LLM 一 5.7）。

手法：摘要、抽要点、热数据全文 / 冷数据摘要。

风险：摘要丢掉权限与禁止事项 → 行为漂移。硬规则（安全边界、工具白名单说明）标为 不可摘要，每次保留全文或短哈希引用。

压缩何时触发、与 Working state 如何对齐，见本系列（五）§2。

3. RAG 在 Agent 中的两种挂法

Embedding / RAG 流程 已讲；此处只钉位置：

挂法 特点
Retrieval Tool 进 Action Space；适合「是否检索」本身要决策
预注入 Workflow 味更重；延迟固定、行为更可预期

降幻觉主手段仍是 RAG / 工具 + 引用，不是低温 alone（LLM 三）。

4. 工具治理（理论级）

协议闭环见 LLM 四 §6，此处补选型与安全视角：

  1. 只读 vs 有副作用：查询可自动重试；写库 / 发信需更严门禁与审计。
  2. 幂等、超时、错误码：Runtime 才能区分「可重试」与「需换策略」。
  3. 结果裁剪：Result 占 Context；过大先截断 / 摘要再写回。
  4. Schema 描述质量：描述含糊 → 选错工具或参数幻觉；执行前仍做 Validation。

易错：模型输出「已发送邮件」但从未真正 Execute——必须以 Observation 为准。

副作用分级与审批档（自动/确认/禁止）、沙箱见（六）§3。

5. Runtime 治理

五件套里 Runtime 是「操作系统」。最少具备：

5.1 Budget

max_steps、max_tokens、墙钟、费用。与模型级停止条件分层：EOS / max_tokens 停单次生成；Budget 停整个 Agent。

5.2 Human-in-the-loop（HITL）

高风险 Action 前审批；信息不足时向用户追问（接 PE 一可截断）。

5.3 Guardrails

工具白名单、参数校验、越权拒答；失败记 Trace。安全维度与 PE 三评测 对齐。

5.4 可观测性（认名）

每步日志：选了啥工具、参数、耗时、错误、Token。轨迹评测（下篇）依赖这些 Trace。

5.5 Final Answer 协议

内部 Thought / 工具草稿 ≠ 用户可见输出。用户侧走 Format / Schema；规划、填参、总结宜分 Prompt（PE 一）。

6. 多 Agent（认名，半节）

模式 一句话
Supervisor 一个协调者分派子 Agent
Handoff 专员做完交下一专员（如「搜索员 → 写手」）

基础阶段知道「研究后期可能拆角色」即可；Subagent 与 Handoff 展开见（六）§4。默认先把 单 Agent + 分层规划 做稳。

选型小表

需求 优先
本轮对话连贯 会话 Context + 结构化 Working state
跨天偏好 / 知识 外存 + 受控写入
公司文档问答 RAG（Tool 或预注入）
「上次怎么做的」 Trace 压缩
「永远按这套流程」 Procedural（代码 / Registry）；技能库变大时的目录与按需加载见（五）§1
跑很长任务 Checkpoint + Budget + Trace

自学检查

  1. Semantic Memory 一定是「模型记在脑子里」吗？
  2. RAG 作 Tool 与预注入 Context 如何选？
  3. 为何硬规则不能随轨迹一起乱摘要？
  4. Skill 与 Tool 差在哪？加载 Skill 时 Context 发生什么变化？

总结

记忆四层：会话 Context、Trace（含 Checkpoint）、外存知识、Procedural。

Skill 认名：程序性知识包；按需注入 Context；≠ Tool；最小字段 name/description/body。

检索与压缩：控制进窗内容；硬规则不可摘要。

RAG：工具化或预注入，二选一或组合。

工具治理：副作用分级、错误码、结果裁剪、Schema+校验。

Runtime：Budget、HITL、Guardrails、可观测、Final Answer 分离。

多 Agent：认名即可；单 Agent 分层规划优先。
