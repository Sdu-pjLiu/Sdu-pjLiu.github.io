AI-Agent工程学习-Loop Engineering(二)

发表于 2026-07-16 更新于 2026-07-17 分类于 计算机
内环/验证环/外环、硬顶与软任务预算、无进展策略、压缩后续传预算、软着陆。

接Loop Engineering（一）：有了 Contract 与 Gate 之后，学习环怎么分层、预算怎么管、撞顶怎么优雅退出。

1. 嵌套环：内 / 验证 / 外

朴素 while 只有一层「选型→执行」。可收敛的系统通常是 三层：

环 职责 典型产出
内环 短步执行、拿 Observation Tool Result、局部状态更新
验证环 客观判断「是否更接近 Done」 pass / fail / 缺口列表
外环 无进展时改策略或停下 Replan、降级、人工、放弃

内环失败 ≠ 整任务失败：验证环报缺口后，外环决定重试、换工具还是 HITL（回链Dynamic Planning）。

2. 退出类型

退出 条件 落地动作
收敛成功 Contract 谓词为真 Final Answer / 提交产物
硬顶 max_steps / 费用 / 墙钟触顶 优雅收尾（见 §4）
无进展 同 tool 同参 N 次，或合同指标不改善 换策略 / 丢弃脏轨迹后重启 / HITL
不可恢复 缺权限、合同冲突、环境不可用 放弃并说明原因

每一种都是 计划内路径，不是异常崩溃。

3. 双层预算：硬顶与软任务预算

3.1 硬顶（Runtime 必做）

接 Agent（三）Budget：

  • max_steps、max_tokens（或费用上限）、墙钟 timeout
  • 与模型级 EOS / max_tokens 分层：一层停单次生成，一层停整个 Agent
  • 硬顶由 Runtime 强制执行，不依赖模型自觉

预算逐步消耗轨迹（max_steps=5，max_tokens=8000）：

步 事件 steps_left tokens_left 说明
0 启动 5 8000 加载 Contract
1 Reason + search 4 7200 −800 prompt+completion
2 Observe 写回 4 6800 内环不扣步（仅扣 token）
3 Reason + search 3 6000 第二次取证
4 验证环 fail 3 5800 Gate 报缺口，外环决定 replan
5 Reason + 成稿 2 4200 软预算提示「剩余 2 步」
6 Gate pass → Success 2 4000 提前收敛，未触硬顶

若第 6 步仍 fail 且 steps_left=0：走 硬顶优雅收尾（落盘 Trace + handoff），而非 silent 断连。

3.2 软任务预算（认名）

现代 Agent 平台常见 整环可见的 token/工作量 countdown（产品名各异，思想一致）：

硬顶 软任务预算
作用域 整个 Loop（Runtime） 整个 Loop（模型可感知节奏）
约束强度 强制截断 / 停环 建议性 pacing；可能略超
目的 防跑飞烧钱 促使提前收尾、排优先级

工程原则：

  1. 软预算不能替代硬顶——始终保留 Runtime 天花板。
  2. 压缩 / compaction 后必须 forward remaining（续传剩余预算与 Contract 字段）；否则治理被重置（回链Agent 五 · 压缩）。
  3. 厂商参数名会变；本系列只认「软 countdown + 硬顶兜底」分层。

4. 优雅收尾（预算耗尽时的软着陆）

硬顶触达时禁止静默死掉（行业常称 soft landing / 软着陆：有计划地停，而不是崩溃）：

  1. 持久化 Checkpoint（计划进度、已完成/未完成、副作用记录）——Agent 三
  2. 写 handoff note（交接说明）：当前缺口、已尝试策略、建议下一步
  3. 向用户返回 部分结果 + 未完成项，而不是假装 Success

预算耗尽 = 计划内退出，与收敛成功并列。

5. 无进展检测与出路

接（五）工具死循环：

信号 例子
重复动作 同一 tool + 同参连续 N 次
指标不降 lint 错误数、失败用例数、open[] 长度不减
验证环空转 Gate 连续 fail 且 Observation 无新信息

出路（外环决策）：

  1. 换策略：改 query、换工具、缩小子目标
  2. 丢弃脏轨迹后重启：保留 Contract，清空可能被污染的 Trace（慎用）
  3. HITL：交给人判或补约束

禁止：同错无限重试烧 Token。

6. 单步形状与 loop-until-dry

6.1 微循环 plan / act / verify

每一步尽量：

与 ReAct 对齐；Verify 可以是轻量规则，不必每步全量跑合同。

6.2 loop-until-dry（认名）

一类收敛模式：每轮处理「当前最高价值的一项缺口」（一个失败用例、一条 lint、一个未覆盖问题），直到一整轮扫描 零缺口。

适合缺口可枚举、可计数的任务；与「一次生成整份大答案再自评」相比，更易接确定性 Gate。

自学检查

  1. 内环、验证环、外环各管什么？
  2. 硬顶与软任务预算差在哪？为何压缩后要 forward remaining？
  3. 预算耗尽时优雅收尾最少要留下哪两样东西？
  4. 无进展时三种出路是什么？

总结

嵌套环：执行 / 验证 / 策略分层，避免单层 while 既做又自评。

退出：成功、硬顶、无进展、不可恢复——皆为计划内路径。

双层预算：Runtime 硬顶 + 可选软 countdown；压缩续传剩余量。

优雅收尾（软着陆）：Checkpoint + handoff note（交接说明）。

进展：可度量；同错不无限重试；loop-until-dry（逐项清缺口直到一轮为零）认名。
