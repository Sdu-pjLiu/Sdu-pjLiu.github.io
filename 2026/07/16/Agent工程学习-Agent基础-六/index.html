0. 本篇位置

一～五已覆盖：闭环、规划模式、记忆/Runtime（含 Skill 认名（三）§1.4）、评测、工程坑（含能力膨胀治理）。

本篇 深化 Skill 边界，并补齐 MCP、权限/沙箱、Subagent；接 PE 四 · Injection 的数据边界。

1. Skill 深化与边界

若未读 （三）§1.4，请先回读认名（Skill 是什么、最小结构、Skill≠Tool）。

1.1 与 Tool / Template / RAG 完整对照（复习）

概念 解决什么 典型载体 是否改世界
Tool 模型可发起、Runtime 执行的动作 JSON Schema + 函数 是（查询/写入）
Skill 教 Agent「这类任务怎么做」 程序性文档包（按需注入 Context） 否（指导如何用 Tool）
Prompt Template 某一步的输入合同 Registry 版本化模板 否
RAG 文档 事实与材料 向量库 Chunk 否

能力目录过大时的 L0/L1/L2 治理见 （五）§1；本篇讲 生命周期与编写评测。

1.2 生命周期

与 Procedural 层：Skill 是 Procedural 的 可版本、可发现、可注入 产品形态（认名见三 §1.4）。

1.3 编写与评测

  1. description 决定会不会被误选——与 Tool Schema 的 description 同等重要。
  2. 安全写法见 PE 四。
  3. 变更后回归 Tool Accuracy 与 Unnecessary Tool Calls。

2. MCP / 外部能力总线（认名）

为何需要： 工具与资源不应全写死在 Agent 单进程；团队/第三方能力宜通过标准总线接入。

MCP 三件套认名：

MCP 概念 工程映射
Tools 可调用动作（对齐 Tool Schema）
Resources 可读资源（文件、URI 内容——不一定是函数）
Prompts 可复用提示模板（与 PE Registry 思想相近）

与 LLM 四 Tool Calling：MCP 提供能力描述与接入；执行闭环仍是 Invocation → 应用执行 → Result 写回。MCP 不替代 Runtime 校验与权限。

场景片段： 输入「查询订单 A102」→ MCP Tool get_order 返回状态；读取政策则使用 MCP Resource → Runtime 写回 Context，模型输出订单状态与政策说明。

本系列不写具体 SDK；实现模块再讲连接、鉴权与部署。

3. 权限、沙箱与审批档

扩 （三）Runtime · HITL / Guardrails：

3.1 三档审批

档位 含义 例子
自动 只读、幂等、低风险 查天气、读公开文档
确认 有副作用或外联 写文件、发 HTTP、改库
禁止 不可自动执行 读密钥、任意 shell、未授权网络

Prompt 写「禁止」不能替代 禁止档——须 Runtime 硬拦（回链 PE 四）。

3.2 沙箱（认名）

隔离 文件系统、网络、进程 的可见范围；缩小 Action Space 的实际破坏面。与 HITL 组合：沙箱内自动，越界须确认。

4. Subagent 与 Agent-as-Tool

扩 （三）多 Agent 认名：

模式 一句话
Subagent / Agent-as-Tool 主 Agent 委派子任务；子 Agent 有 独立 Context
Handoff 专员做完交下一专员

要点：

  1. Context Isolation（LLM 一 5.7）：子任务 Trace 不要无限灌回主窗。
  2. Handoff 必带（回链五 §4）：Goal 摘要、已完成/未完成、硬规则引用。
  3. 默认策略：单 Agent + Skill + 分层规划做稳，再考虑多 Agent——避免过早拆角色丢上下文。

场景片段： 主 Agent 输入「检查项目安全风险」→ 委派安全 Subagent 独立扫描 → 子 Agent 只返回风险摘要与证据路径，避免完整 Trace 挤占主 Context。

5. Environment 扩展认名（半节）

除搜索、DB、HTTP 外，常见扩展：

形态 特点
Code Interpreter 执行代码片段；Observation 可很大
Browser / Computer Use UI 操作；Action Space 与风险面扩大

共性：权限档要上移；Tool Result 须裁剪再写回（五 §2）；Injection 风险更高（PE 四）。

6. Hooks（认名半节）

Hooks 是 （三）§6 Harness 的 扩展插槽——在关键节点插入逻辑，不改 LLM 协议：

钩子 典型用途
工具执行前 参数校验、权限档判断
压缩前 校验不可摘要字段是否保留
步数/预算 死循环检测、强制停止

实现层对应 LangChain Middleware、Deep Agents Middleware 栈（见 LangChain / Deep Agents 系列）；invoke 生命周期中的挂载点见（三）§6.3。

7. Harness 谱系与后续框架

（三）§6.4 已在概念层列出 Harness 形态；此处补上 后续实现模块 的对应关系：

Harness 形态 后续模块 入口 / API（认名）
薄 Harness LangChain create_agent + Middleware
编排 Runtime LangGraph StateGraph；Harness 的底层
自定义拓扑 LangGraph 手画 Node/Edge；CompiledSubAgent 嵌入
厚 Harness Deep Agents create_deep_agent 预装栈
Knowledge / RAG RAG 系列 LangChain Retriever + RAG（一）～（五）
外部能力总线 MCP 工程 MCP Server + Client 适配器

全路径一句话： Agent 基础之后，Loop / LangChain / LangGraph / Deep Agents 不再学新 Agent 理论，而是学 同一 Harness 架构的不同落地；RAG / MCP 为 Knowledge 与 Tool 总线垂直模块。四条实现线工程对比见 实现框架对比。

与 Loop Engineering 的关系： Loop Engineering 约束 Harness 的 Done 判据与验证门——何时算完成、哪些 Observation 才算证据、Budget 耗尽如何降级（见 LE（一））。Harness 负责跑环；LE 负责环 该不该停、停之前验什么。

总结

Skill：深化生命周期与编写评测；认名见（三）§1.4；≠ Tool。

MCP：外部能力总线；Tools/Resources/Prompts；执行仍走 Tool Calling 闭环。

权限沙箱：自动/确认/禁止三档 + 隔离；与 HITL、Injection 防御配合。

Subagent：委派 + Context 隔离；默认单 Agent + Skill 优先。

Environment 扩展：代码/浏览器等放大风险与 Observation 体积。

Hooks：（三）§6 Harness 扩展点；LangChain / Deep Agents Middleware 展开。

Harness 谱系：薄 / 厚 / 自定义拓扑；后续系列为实现层。
