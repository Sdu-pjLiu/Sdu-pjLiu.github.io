AI-Agent工程学习-Agent基础(四)

发表于 2026-07-16 更新于 2026-08-20 分类于 计算机
Agent 轨迹级评测、Research 实践地图 L0–L2、发版回归 Checklist；工程坑见（五）。

接Agent 基础（三）：把「好不好」从单次 Completion 升级到整条轨迹，并用 Research Agent 把一～三串成地图。

1. 评测分层：节点 → 轨迹 → 任务 → 安全

Prompt Evaluation 已覆盖：黄金集、规则校验、LLM-as-Judge、人工抽检、离线/线上。本篇 不重讲，只升级对象。

层 评什么 例子
节点 单步 Prompt / 工具参数 Schema 合法率（回链 PE 三）
轨迹 循环是否健康 平均步数、重复工具率、假完成
任务 最终是否达验收 Task Success Rate
安全 有害 / 越权 禁调工具拦截率

发版时：节点级沿用各 Template 的黄金集；Agent 级另建 Scenario 集（同一问题 + 工具桩 / fixture）。回归固定：模型版本 + Prompt versions + Tool Schema versions（PE 三 Registry）。

2. 增量指标字典

指标 工程口径 怎么算
Task Success Rate 达验收标准的比例 黄金任务通过数 / 总数
Hallucination Rate 无依据断言占比 无 Observation 支撑的断言 / 总断言（接幻觉）
Tool Accuracy 工具用得对不对 可拆：选型准确 · 参数合法 · 结果被正确使用

可选补充：

  1. Avg Steps / Cost per Success：成功一单平均步数与 Token（接多次 Completion 累加）
  2. Tool Error Recovery Rate：工具失败后是否换策略而非空转
  3. Unnecessary Tool Calls：无增益的重复调用

工具侧协议仍以 Tool Calling 闭环 为准：参数错先算节点失败，再归因 Schema 或 Prompt。

上述轨迹指标可接到 Runtime 验证门（假完成率、重复工具率等），把「评完再改」变成「环内硬拦」——见 Loop Engineering。

2.1 假想轨迹数字演算（5 条 Scenario）

固定黄金集 N = 5，工具桩与 Rubric 已配置：

# 轨迹摘要 Task Success Tool 选型 参数合法 结果被使用 假完成？
1 search×2 → 成稿，事实可指向 Observation ✓ ✓ ✓ ✓ 否
2 未调工具直接写「已调研完毕」 ✗ ✗ — ✗ 是
3 search 成功但报告未引用任何 Observation ✗ ✓ ✓ ✗ 部分
4 调错工具 send_email 而非 search ✗ ✗ ✓ — 否
5 search 参数 JSON 缺字段 ✗ ✓ ✗ — 否

聚合（非空定义）：

  • Task Success Rate = 1 / 5 = 20%
  • Tool Accuracy（选型） = 3 / 5 = 60%（#2 未调用计失败）
  • Tool Accuracy（参数合法） = 4 / 4 次调用 = 100%（#2 无调用不计入分母）
  • 假完成率 = 1 / 5 = 20%（#2；#3 若 Gate 要求「每条关键事实有 Observation 指针」也会拦下）

演算说明：指标必须绑定 可观测轨迹字段（tool_calls、Observation id、Final 文本），不能只看自然语言「我觉得做完了」。

3. Judge / Human / Rubric：Agent 场景差在哪

细节回链 PE 三 2.1–2.2。Agent 增量：

  1. LLM-as-Judge：可对报告结构、依据引用打分；Judge Prompt 也要 version；防与任务模型「同家族同错」。

  2. Human Evaluation：专业正确性、品牌口径、安全——仍要用 Rubric，适合黄金集与线上抽检。

  3. Rubric：为开放任务写可打分量规，例如 Research：

    • 是否覆盖问题
    • 关键事实是否可指向某次 Observation
    • 是否区分事实与推测
    • 结构是否完整
    • 无依据断言扣分

5. 实践阶梯 L0 → L2

级别 做什么 证明你会了什么
L0 2～3 个 mock search；手写 while + Tool 协议走通 Loop Agent Loop
L1 真搜索 + Planner 出 3～5 步静态计划 规划式执行
L2 空结果 / 冲突时改 query 或 Replan Dynamic Planning

再进阶（本阶段不强制）：跨会话 Memory、Checkpoint 续跑、完整评测流水线。

验收四条（Research 最小成功定义）：

  1. 报告中关键事实能指向某次 Observation（防假完成 / 幻觉）。
  2. 在步数 / Token 预算内结束（不空转）。
  3. 工具失败有可见 Recovery，不假装成功。
  4. 同一问题两次跑：结构稳定（Prompt / Schema 版本固定）。

  • Middleware / Verification Gate / Budget 策略

6.3 通过 / 阻断

类型 规则
阻断（BLOCK） 安全 fixture 失败、Citation Gate 失败、越权未拦、假完成率 >0

评测：节点回链 PE 三；本篇补轨迹与任务指标。

Research：问题 → 拆解 → 搜索 → 分析 → 报告；映射一～三组件。
