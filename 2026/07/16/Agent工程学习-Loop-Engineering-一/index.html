AI-Agent工程学习-Loop Engineering(一)

发表于 2026-07-16 更新于 2026-07-20 分类于 计算机
Loop Engineering 开篇：与 Loop 语义边界、可机检 Contract、Verification Gate 与 Maker-Checker。

接Agent 基础（六）：组件与安全边界齐备之后，把 while 循环本身当成工程对象——如何收敛、如何验证、如何安全停下。

0. 本篇位置

Agent（一） 讲清 Loop 长什么样（Thought → Action → Observation）。

本模块讲 Loop Engineering：如何设计触发、行动、验证与停止，使 Agent 在约束下自主推进并客观结束。

依赖（已学）：

  1. Agent Loop / 停止条件
  2. Runtime Budget / HITL
  3. 轨迹评测指标
  4. 工程坑：假完成 / 死循环

1. Loop Engineering 是什么

定义： 工程「触发 → 行动 → 验证 → 停止」，使目标驱动的循环在预算内可收敛、可证明、可放弃。

Prompt Engineering Loop Engineering
工程对象 单次 / 分步输入合同 整条 Agent 循环
核心问题 写什么、怎么评版本 何时算 Done、如何验、如何停
失败形态 格式错、事实错 空转、假完成、烧预算

一句话：单位是 Loop，不是单次 Prompt。

2. 与 Loop 语义、Workflow 的分工

形态 解决什么 何时够用
Workflow / Chaining 路径预先写死 步骤可预见
Agent Loop 语义（一） 边观察边选型 路径需试探
Loop Engineering（本模块） 让开放路径仍然可验收、可封顶 上了 Agent 就要工程化停下

不知何时上 Agent，见（一）选型；上了 Agent 却无合同与门，等于昂贵的 while True。

3. 收敛合同（Contract）

合同 = 循环开始前写清的 成功 / 失败 / 放弃 标准，且尽量 机器可检查。

差合同（目标模糊） 好合同（可检）
「把报告写好」 「关键事实均可指向某次 Observation；含对比与不确定声明」
「改进这个模块」 「auth/ 单测全绿 + lint 0 错误 + 指定 endpoint 返回 200」
「调研完成」 「至少 3 个独立来源；冲突处已标注；步数 ≤ N」

原则：

  1. Done 可机检优先：规则、Schema、测试、HTTP 状态、计数器 —— 优于仅靠自然语言/主观文字判断「完成」（后者无法用程序稳定复现）。
  2. 开放任务用 Rubric；能自动化的部分不要只靠 Judge。
  3. 合同同时定义 失败与放弃（连续工具失败、缺权限、目标冲突），避免只会「成功或空转」。

可机检 Contract Checker（JSON 输出 + 规则）：

预期：坏态 pass=False，缺口含来源不足、无 observation_id、步数超限；好态 pass=True。

4. 验证门（Verification Gate）

信任梯度（高 → 低）：

等级 形式 例子
1. 确定性检查 代码/规则，模型难以伪造 单测、Schema Validation、HTTP 200、diff 计数
2. 独立 Checker 另一套 Prompt/模型或规则引擎 只读评审员、结构化 checklist
3. 同模型自评 生成者判断「我做完了」 「看起来可以」——最弱

禁止： 仅靠「模型宣称完成」标 Success（假完成）。自评若使用，必须叠加硬顶步数，且不得单独作为结束循环的条件。

与（四）LLM-as-Judge：Judge 适合离线/抽检；环内门禁优先用等级 1～2。

5. Maker–Checker

角色 职责 权限建议
Maker 规划、调工具、改世界 按审批档执行
Checker 对照 Contract 验收 宜只读；无写库/发信权

分离方式（任选其一即可）：

  1. 同进程两次 Completion：生成 → 固定 Checker Prompt
  2. 子 Agent / 专员：验收员 Context 隔离（回链Agent 六 Subagent）
  3. 纯确定性 Gate：无第二模型，只跑测试/规则

要点：验收者不能与制作者共享「自己评自己」的激励；否则 Gate 退化成自评。

总结

LE：工程整条循环的收敛与停止，不是再写一篇 Prompt。

Contract：可机检的成功/失败/放弃；「把报告写好」这类模糊目标句不够。

Gate：确定性 > 独立 Checker > 自评；禁止把自评当作结束循环的唯一条件。

Maker–Checker：生成与验收分离。
