AI-Agent工程学习-Agent基础(二)

发表于 2026-07-16 更新于 2026-07-17 分类于 计算机
Agent 推理与规划：ReAct、规划式（Decomposition/DAG/Dynamic/Hierarchical）、Reflection/Self-Refine，以及 Debate/Tree Search 认名与选型。

接Agent 基础（一）：在会跑 Loop 的基础上，学习常见推理/规划模式与选型。

1. ReAct（Reason + Act）

什么是 ReAct？

Thought 与 Action 交替；工具结果作为 Observation，再进入下一 Thought。它是 Agent Loop 最简实用形态。

1.1 与原生 Tool Calling

现代路径优先用 Tool Calling：模型输出结构化 Invocation，应用执行后写回 tool 消息。经典 ReAct 用「Thought:/Action:」纯文本格式；工程上 语义相同，协议更硬。

与纯 CoT 对比：

纯 CoT ReAct
中间证据 模型自说 工具 Observation
纠错机会 弱 每步可据结果改道
成本 单次偏短 多次 Completion

1.2 适用 / 不适用

适用：中短任务、工具品种不多、路径难预先写死。

不适用：步骤完全固定（用 Workflow）；只要填严格工具参数（低温 + Schema，少写自由文本 Thought，见 PE 二选型）。

2. 规划式 Agent（Plan-and-Execute 及规划技法）

定义： 先产出计划（Planner），再按步骤执行（Executor）；计划可静态，也可在 Observation 后修订。

与 ReAct：ReAct 边想边走；规划式 先地图再走。Prompt 侧亲戚：Decomposition / Least-to-Most、规划/执行/总结分 Template。

2.1 Planner 输入 / 输出

内容
输入 Goal、约束、可用工具清单、已知 Memory
输出 步骤列表或 DAG、成功标准、风险点
不做 直接写最终长报告（交给 Executor / Writer）

2.2 Goal Decomposition vs Task Decomposition

Goal Decomposition Task Decomposition
问什么 成功意味着什么（验收） 做哪些动作达成
例子 「报告可信」→ 有来源、有对比、有不确定声明 「搜论文 → 摘论据 → 写章节」

先定 Goal 验收，再拆 Task，后面评测才站得住（见本系列（四））。

2.3 DAG Planning

节点 = 子任务；边 = 依赖。好处：无依赖节点可并行；进度可视。某节点失败 → 影响下游 → 局部重规划。

Research Agent 常见：多源搜索可并行；「综合成文」依赖搜索完成。

2.4 Dynamic Planning（重规划）

触发：Observation 与预期不符、发现新约束、预算告急。

策略：局部替换节点 vs 全局推翻。设 重规划频率上限，避免每步都重画地图。

2.5 Hierarchical Planning

层次越高越稳定；底层允许 ReAct 灵活试错。

坏计划一路执行到底：必须有中间校验与 Replan 触发——这是规划式相对 ReAct 的主要风险。

3. 反思与迭代

3.1 Reflection

在 Action 或草稿之后，增加「批评者视角」评估，再决定继续 / 修正 / 停止。

常见挂载：

  1. 对 中间步骤（选错工具、参数离谱）纠偏
  2. 对 最终答案（成稿后再改）

Reflection 本身也是一次 Completion，计入 Budget。

3.2 Self-Refine

生成 → 反馈 → 改写，迭代固定轮次或直到评分达标。

Reflection Self-Refine
重心 判断对错与缺口 基于反馈迭代改进产物
产物 评估 / 决策 多版 Answer / Plan
亲戚 评审员 修订循环

可用固定 Rubric 驱动何时停止 refine（方法见 PE 三 Evaluation）。

4. 附录认名：Debate 与 Tree Search

基础阶段只认名与选型，不展开公式。

4.1 Debate

多角色（正方 / 反方 / 裁判）对同一问题生成对立观点再汇总。需角色 Prompt、发言次序、终止规则。成本高；适合高不确定判断，不适合每步填工具参数。

与 Self-Consistency：后者多样本同角色；Debate 异角色对抗。

4.2 Tree Search Reasoning

维护候选状态树：扩展 → 评估 → 剪枝 → 回溯。Prompt 侧亲戚：Tree of Thoughts。

工程分层：

  1. 纯 Prompt ToT：全靠模型开树（最贵）
  2. Runtime 管树 + LLM 打分（更常见）
  3. 有搜索 / 测试工具时，优先 工具空间探索

5. 选型总表

任务特征 优先模式
少量工具、路径未知 ReAct
步骤可预见、要可追踪 规划式（Plan-and-Execute + DAG）
成稿质量敏感 + Reflection / Self-Refine
高争议判断 Debate（慎用）
大搜索空间、可评估 Tree Search（预算可控时）
路径完全固定 不要 Agent，用 Workflow / Chaining

自学检查

  1. ReAct 与「先计划再执行」如何选型？
  2. Goal 分解与 Task 分解差在哪？
  3. Research Agent 为何常用「高层计划 + 底层 ReAct」？

总结

ReAct：Thought/Action 交替 + Observation；Loop 的默认实用形态。

规划式：Planner → Executor；含 Goal/Task 分解、DAG、Dynamic、Hierarchical——与「推理模式 Plan-and-Execute」是一条线。

反思迭代：Reflection 偏评判；Self-Refine 偏改写循环。

高级认名：Debate、Tree Search；有外部工具时少用纯 Prompt 空想式树搜。

选型：固定路径用 Workflow；试探路径用 ReAct；长任务用分层规划。
