AI-Agent工程学习-DeepAgents(四)

发表于 2026-07-20 更新于 2026-08-20 分类于 计算机
Delegation：write_todos、Subagent 全系、与 LangGraph 对比、best practices。

接 Deep Agents（三）：Context 管「知道什么」；Delegation 管「如何拆任务、如何把重活隔离出去」。

0. 本篇位置

Delegation = Task planning（write_todos）+ Subagents（task 工具）。

官方：Subagents · Async subagents · Dynamic subagents

Subagent 的核心价值：Context quarantine——主 Agent 只收 final report，不收中间十几次 search/read。理论层对应 Multi-Agent（二）Worker + （四）Message Passing（Handoff 摘要而非全文 Trace）；实现对比见 LangGraph（六）Handoff。

1. Task Planning：write_todos

Harness 内置 write_todos 工具，Agent 在运行中维护结构化任务列表。

属性 说明
状态 pending / in_progress / completed
持久 存在 agent state
定位 轻量跟踪，不是独立 Plan-Execute-Verify 引擎

推荐工作流：

不要把它理解成自动「生成计划 → 拆分子任务 → 检查 → 修正」的状态机——检查与修正仍靠 模型推理 +（可选）HITL（见（五））。

2. Subagent 模型与 task 工具

主 Agent 通过 task 工具创建 临时 Subagent 执行子任务。

特性 含义
Fresh context 每次调用新建实例，独立 context
Autonomous execution Subagent 独立跑到完成
Single handoff 只回传一份 final report 给主 Agent
Stateless messaging 不能多次 message 回父 Agent
Token efficiency 重活隔离在子 context，压缩为短结果

主 Agent 在同一 turn 可发 多个 task() 并行（同步 Subagent 阻塞到完成）。

何时用 / 不用

用 Subagent 不用 Subagent
多步 research / 大量 tool 输出 单步简单任务
需 specialized tools + prompt 必须保留全部中间 context
并行独立子任务 委托开销 > 收益

3. general-purpose Subagent

除非已有同名同步 Subagent，Deep Agents 自动添加 general-purpose：

  • 默认带 FS 工具
  • 继承主 Agent skills
  • 可通过 subagents=[{"name": "general-purpose", ...}] 整体替换
  • 禁用：GeneralPurposeSubagentProfile(enabled=False) + 不传同步 subagents（勿 excluded_middleware 删 SubAgentMiddleware）

4. Custom 与 CompiledSubAgent

4.1 SubAgent 字典

字段 说明
name 唯一 ID；task(subagent_type=...) 使用
description 主 Agent 选谁委托的依据（要 action-oriented）
system_prompt 子 Agent 指令；不继承主 Agent
tools 可选；指定则 覆盖继承，否则继承主 Agent
model 可选覆盖
middleware 不继承主 Agent；按 name 替换子栈默认
interrupt_on 可选；默认继承主 Agent
skills 可选；不继承（GP 除外）
response_format 结构化输出 → 父收到 JSON ToolMessage
permissions 可选；替换父 FS 权限

不存在独立的「Agent Routing 框架」——路由 = 主 Agent 读 description 后选 subagent_type。

5. Async 与 Dynamic Subagents

5.1 Async subagents

  • 长任务、并行工作流、需 中途 steering / cancel
  • 独立 Middleware 路径（AsyncSubAgentMiddleware）
  • 与同步 task() 并存；禁用同步 subagent 不影响 async

详见 async-subagents。

5.2 Dynamic subagents（Beta）

需 Subagents + CodeInterpreterMiddleware；Agent 从 QuickJS 代码里 batch dispatch task()（循环、分支、并行批）。

  • 触发：请求里含 「workflow」 等词时倾向走 interpreter 编排
  • 适用：目录内每文件 review、批量 ticket、多视角分析
  • CodeInterpreterMiddleware(subagents=False) 可强制只走普通 task 路径

6. vs LangGraph Multi-Agent

维度 LangGraph Supervisor / Subgraph Deep Agents Subagent
拓扑 显式 Node/Edge Harness 内置 task 工具
状态映射 自行设计 state / Store 自动隔离 + single handoff
中间 context 可保留在父图 默认不回流细节
适用 确定性编排 + 图级 LE 长任务 + context 卫生
组合 可 CompiledSubAgent 嵌入 Deep Agents 外层 Deep Agents，内层 LangGraph

需要 每步图级门禁 或 复杂 handoff 合同 → LangGraph；需要 快速委托重 research → Deep Agents Subagent。

7. Best practices

  1. description 要具体：✅「Analyzes financial data and generates investment insights」❌「Does finance stuff」
  2. system_prompt 要求 concise output：限制字数、禁止 raw data
  3. 最小 tool set：只给子任务需要的工具
  4. 按任务选 model：长文档 vs 数值分析可用不同 model
  5. 主 Agent system_prompt 明确要求委托：「复杂任务用 task()，保持自身 context 干净」

Troubleshooting

问题 对策
Subagent 不被调用 加强 description；主 prompt 写「必须 delegate」
Context 仍膨胀 子 prompt 要求摘要；大数据写 FS
选错 Subagent 差异化 description（quick vs deep researcher）

8. Streaming 与 LangSmith

  • stream.subagents 跟踪每个委托（见（二）§6）
  • 每条 run metadata 含 lc_agent_name（如 research-agent）
  • LangSmith 过滤：has(metadata, '{"lc_agent_name": "research-agent"}')

9. L1 实验（完成）

步骤 操作
1 同一任务：无 subagent 跑一轮，记录主 Agent messages 条数/字符
2 有 research subagent 再跑，对比主 Agent messages
3 LangSmith 按 lc_agent_name 只看 subagent span
4 验证 single handoff：父 ToolMessage 仅一条子结果

Done 判据：主 Agent context 明显变短；能解释 single handoff。

总结

Planning：write_todos 轻量跟踪；非独立 Planner。

Subagent：task 工具；fresh context + single handoff。

类型：general-purpose / Custom / Compiled / Async / Dynamic。

路由：description 驱动；无独立 Routing API。

对比 LangGraph：委托 vs 显式拓扑；可 CompiledSubAgent 组合。
