AI-Agent工程学习-DeepAgents(二)

发表于 2026-07-20 更新于 2026-08-20 分类于 计算机
Execution Environment：Tools/MCP、虚拟 FS、Backends、Permissions、Sandbox/Interpreter、Streaming。

接 Deep Agents（一）：四层能力中的 Execution environment 是 Agent 行动的场所——Tools、虚拟文件系统、Backend 与代码执行层。

0. 本篇位置

Execution environment = Tools + Virtual FS + Permissions + Code execution + Streaming。

官方：Tools · Backends · Permissions · Sandboxes · Interpreters

FilesystemMiddleware 在默认栈中 始终存在（见（一）§5）。

1. Tools 与 MCP

1.1 自定义 Tools

除 Planning、FS、Subagent 等 harness 内置工具外，通过 tools= 传入：

  • Python 函数（自动转 Tool）
  • LangChain @tool / BaseTool
  • MCP 服务器提供的工具

1.2 MCP 接入

Deep Agents 完整支持 Model Context Protocol：数据库、API、远程文件系统等经标准接口接入。

需安装 langchain-mcp-adapters。stdio、OAuth、工具过滤等见官方 MCP 指南。

2. 虚拟文件系统

Harness 提供 可插拔 Backend 支撑的虚拟 FS；模型可见一组文件工具（由 FilesystemMiddleware 注入 system prompt 说明）。

2.1 内置文件工具

工具 作用
ls 列目录（含 size、modified time）
read_file 读文件；支持 offset/limit；多模态（图片/音视频/pdf 等）
write_file 创建或覆盖文件
edit_file 精确字符串替换（可 global replace）
delete 删文件或递归删目录（≥0.7.a1）
glob 模式匹配找文件
grep 内容搜索（files / content / count 模式）
execute Shell 命令（仅 Sandbox 类 Backend）

虚拟 FS 同时服务 Skills、Memory、代码执行与 Context offloading（大结果落盘，见（三））。

3. Backends 体系

Backend 决定虚拟路径背后 数据存哪、能否 execute。

Backend 作用域 典型场景
StateBackend thread 内（checkpointer） 默认；working memory
FilesystemBackend 本地磁盘 Coding agent；virtual_mode=True 限制在 root 内
LocalShellBackend 本地盘 + 主机 shell 开发机；高风险
StoreBackend 跨 thread 用户级长期数据
CompositeBackend 路径路由 项目文件 vs agent 内部数据分离
ContextHubBackend LangSmith Hub 团队共享上下文
Sandbox backends 隔离 VM/容器 生产代码执行 + execute

3.1 默认：StateBackend

3.2 CompositeBackend（推荐模式）

store= 传给 create_deep_agent，不是 Backend 构造参数。LangSmith Deployment 可省略 store（平台自动 provision）。

3.3 Sandbox

Sandbox 实现 SandboxBackendProtocolV2 时 harness 自动暴露 execute。提供商包括 LangSmith Sandbox、E2B、Modal、Daytona、Runloop、Vercel 等（见 Sandboxes）。

Sandbox vs LocalShellBackend：Sandbox 在隔离环境执行；LocalShell 直接在主机上跑命令——仅适合受控开发环境。

4. Filesystem Permissions

声明式规则控制 built-in FS 工具 的读写（first-match-wins）：

每条规则含 operations（read / write）、paths（glob）、mode（allow / deny）。

注意：Sandbox 的 execute 不受 permissions 约束（可 arbitrary shell）；敏感环境用 Sandbox 策略 hook 或限制 Backend 类型。Subagent 可设独立 permissions 列表，完全替换父 Agent 规则。

5. Code Execution：Sandbox vs Interpreter

方式 工具 能力 适用
Sandbox execute shell、装依赖、跑测试、OS FS 编码 Agent、CI 式任务
Interpreter eval QuickJS 内 JS；程序化 tool calling 批处理、循环 dispatch、轻量变换

需 pip install "deepagents[quickjs]" 与 langchain-quickjs>=0.2.0。Dynamic subagents（（四））依赖 Interpreter。

6. Streaming

Deep Agents 在 LangGraph streaming 之上增加 stream.subagents：每个委托任务独立 handle（.name、.messages、.tool_calls、.output）。

Typed 投影：messages、tool_calls、values、subagents 可独立迭代。

7. L0 实验（动手）

目标：证明 harness + FS + trace 跑通。

步骤 操作
1 create_deep_agent + 1 个伪 Tool
2 提示 Agent「用 write_file 写 /notes/plan.txt 再 read_file 读回」
3 检查返回 state 中 files 或 messages 含 Tool 轨迹
4 LANGSMITH_TRACING=true 打开 trace，确认 Filesystem 工具 span

Done 判据：一次 invoke 内出现 FS 工具调用且 trace 可回放。

本模块自检与面试

学完本篇后，请到 Deep Agents · 自检与面试 完成学习自检与面试题（含推荐回答）。

总结

Tools：自定义 + MCP；与 harness 内置工具并列。

虚拟 FS：八工具 + multimodal read；offloading 载体。

Backends：State 默认；Composite 分离内部/长期数据；Sandbox 给 execute。

Permissions：声明式 allow/deny；Sandbox execute 另论。

代码执行：Sandbox（shell）vs Interpreter（QuickJS）。

Streaming：stream_events + stream.subagents。
