发表于 2026-07-20 更新于 2026-08-20 分类于 计算机
Steering、HITL、Harness Profiles、Middleware 覆盖、LangSmith、L0-L2 实践阶梯、选型收口。

接 Deep Agents（四）：Delegation 拆任务；Steering 让人在运行时 审批、限制、按 provider 调优 harness。

0. 本篇位置

Steering = Human-in-the-loop + Filesystem permissions + Harness Profiles + Middleware 定制。

官方：Human-in-the-loop · Profiles

本篇同时 收口全系列：实践阶梯、三产品选型、生产认名。

1. Human-in-the-loop

interrupt_on 映射 工具名 → 中断配置；集成 LangGraph interrupt（见 LangGraph（五））。

Checkpointer 必填——否则无法 pause/resume。

配置值 含义
True 默认 approve / edit / reject / respond
False 不中断
{"allowed_decisions": [...]} 限制可选决策

Subagent 可通过 interrupt_on 覆盖继承值。对齐 LE Gate：高风险副作用走确定性门禁，不只靠 prompt。

2. SystemPromptConfig 与 Harness Profiles

2.1 System prompt 组装

system_prompt 字符串 = prefix（prepend 到 base 前）。

SystemPromptConfig 字典（deepagents>=0.7.0a6）：

键 作用
prefix base 之前
base 替换内置 base；None 去掉 base
suffix base 之后

组装顺序：prefix → base → suffix → profile suffix。

2.2 Harness Profiles

按 model provider 注册可复用默认 bundle（base prompt、GP subagent、excluded_tools、provider middleware…）：

tool_description_overrides 可只改 task 工具描述，而无需替换整个 SubAgentMiddleware。

3. Middleware 覆盖规则与陷阱

  • 传 middleware=[X] 且 X.name 匹配默认 → 替换（非 merge）
  • 替换 FilesystemMiddleware / SummarizationMiddleware 等须 自带完整配置（尤其 backend=）
  • 主 Agent 的 override → general-purpose Subagent 继承；declarative subagent 不继承 → 在其 middleware 字段单独传
  • 禁止 excluded_middleware 删 FilesystemMiddleware / SubAgentMiddleware
  • 隐藏 FS 工具：excluded_tools 或 FilesystemMiddleware(tools=[...])
  • 禁用 subagents：GeneralPurposeSubagentProfile(enabled=False) + 无同步 subagents

4. LangSmith 观测

  • 设置 LANGSMITH_TRACING=true + API Key
  • Deep Agents run 含 model / tool / middleware / subagent span
  • Subagent 过滤：metadata lc_agent_name
  • 建议了解 LangSmith Engine（监控 trace、问题检测）；Deployment 属平台篇

调试 Subagent 委托问题：先看主 Agent 是否调用 task，再展开 subagent 子 trace。

6. 三产品终极选型

需求 推荐
标准单 Agent + 少量 Middleware LangChain
确定性步骤 + 复杂分支 + 自定义拓扑 LangGraph
长任务 + 开箱 FS / Skills / Subagent / 压缩 Deep Agents
Deep Agents 能力不够 + 需图级 LE LangGraph 自建或 CompiledSubAgent
只要 MCP + 2 个 Tool 短环 LangChain 即可，不必 Deep Agents

7. 实践阶梯 L0 → L2（完整版）

L0 · 最小 Deep Agent

步骤 内容
1 create_deep_agent(model, tools=[...])
2 invoke 3 步以上任务；触发 write_todos
3 触发 write_file / read_file
4 LangSmith trace 可见 harness 工具

证明：harness 跑通。

L1 · 上下文 + 委托

步骤 内容
1 memory=["/AGENTS.md"] + seed
2 skills=["/skills/"] + SKILL.md
3 1 个 research subagent
4 对比有/无 Subagent 的主 Agent messages 体积
5 CompositeBackend：/memories/ → Store

证明：厚 harness 降低主 context 膨胀。

L2 · 可治理长任务

步骤 内容
1 interrupt_on={"write_file": True} + MemorySaver
2 permissions 限制 /workspace/
3 （可选）Sandbox backend + execute 跑 pytest
4 stream_events + stream.subagents 监控委托
5 LangSmith lc_agent_name 过滤

证明：敏感操作可审批；委托可观测；FS 有边界。

8. L2 实验（动手清单）

9. 全路径收口

Deep Agents 系列覆盖官方四层能力：Execution / Context / Delegation / Steering，入口统一为 create_deep_agent + 默认 Middleware 栈 + LangGraph Runtime。

长任务发版时，Context 压缩与 Loop 指标见 Agent（四）§6 发版回归 Checklist 的 Context / Loop 域。LangChain / LangGraph / Deep Agents / CrewAI 选型对比见 实现框架对比。

下一模块：RAG（一）· 定位与基础管线——在 LangChain 积木之上垂直深化检索系统。

与 RAG 的挂法（一句）： 把检索封装成 Tool（如 search_knowledge_base）后，经 create_deep_agent(..., tools=[retriever_tool]) 挂入即可；长任务用 FS/Subagent 管材料，检索质量与评测仍以 RAG 系列为准。其后 MCP（一） 负责外部能力标准接入。

总结

Steering：interrupt_on + permissions + profiles。

定制：SystemPromptConfig；Middleware 按 name 替换。

观测：LangSmith + lc_agent_name。

阶梯：L0 跑通 → L1 厚能力 → L2 可治理。

选型：长任务厚 harness 用 Deep Agents；精细拓扑用 LangGraph。
