AI-Agent工程学习-DeepAgents(一)

发表于 2026-07-20 更新于 2026-08-20 分类于 计算机
Deep Agents 开篇：四层能力模型、create_deep_agent、默认 Middleware 栈、与 LangGraph 关系。

接 Multi-Agent · 自检与面试：五角色与 Worker/Subagent、Message Passing 理论已系统化学完；当需要 开箱即用的规划、虚拟文件系统、Skills 与 Subagent 委托 来支撑长任务时，进入 Deep Agents——Agent（六）§7 谱系中的 厚 Harness 一种产品形态（理论映射见 Multi-Agent（五）§4）。

0. 本系列在学习路径中的位置

理论已学：

  • Multi-Agent（一）～（五） — Worker / Subagent、Message Passing、映射 canonical
  • LangGraph（六） — Supervisor / Subgraph 图级实现

LangChain 负责：Model + 可定制 Harness（create_agent + Middleware）。

LangGraph 负责：低层编排 Runtime——StateGraph、持久化、Interrupt、Multi-Agent 拓扑。

Deep Agents 负责：预装厚能力的 Agent Harness——Planning、Virtual FS、Skills、Memory、Subagent、Summarization 等一体交付。

产品 层级 本系列深度
LangChain Agent framework 已学
LangGraph Orchestration runtime 已学
Deep Agents 厚 harness 主线

官方：Deep Agents overview · Customization · Products 对比

1. 厚 Harness 实现

Harness 完整定义见 Agent（三）§6；谱系定位见 （六）§7。本篇讲 厚 Harness 一种产品形态——预装长任务常见能力，而非重新定义 Harness。

Harness 特点
LangChain create_agent 薄 Harness；Middleware 按需叠加
Deep Agents create_deep_agent 厚 Harness；Planning、FS、Skills、Subagent、Summarization 等预装

Deep Agents 不是替代 LangGraph 的新 Runtime——它 基于 LangChain 积木 + LangGraph Orchestration Runtime（见 （三）§6.5），把长任务 Agent 常见能力打包成默认栈。

何时选 Deep Agents（信号）：

需求 Deep Agents 提供
长任务需 todo 跟踪 内置 write_todos
大 tool 输出污染 context 虚拟 FS + offloading + Subagent 隔离
领域流程/知识按需加载 Skills（progressive disclosure）
跨会话偏好与规范 Memory（AGENTS.md）
委托重研究/编码子任务 task Subagent
敏感写操作需审批 interrupt_on + checkpointer

何时 不 选：拓扑需精细确定性控制、每步都要图级门禁、或只需 2–3 个 Tool 的短环——继续 LangChain 或 LangGraph 自建（见（五）选型表）。

3. 快速上手：create_deep_agent

要点：

  • model 支持 provider:model 字符串或已初始化的 ChatModel。
  • system_prompt prepend 到内置 base prompt 之前（base prompt 教模型如何使用 harness 工具）。
  • 返回类型为 CompiledStateGraph，即 LangGraph Runnable。

带 Memory / Skills 参数的骨架（细节在（三）展开）：

4. create_deep_agent 参数地图

参数 作用 触发 Middleware / 能力
model= 模型 Prompt caching（Anthropic/Bedrock 等）
tools= 领域工具 与内置 harness 工具并列暴露给模型
system_prompt= 自定义指令 prepend 到 base prompt
memory= AGENTS.md 路径列表 MemoryMiddleware
skills= Skills 目录 SkillsMiddleware
backend= 虚拟 FS 后端 FilesystemMiddleware 存储
permissions= FS 读写规则 FilesystemMiddleware 内 enforcement
subagents= 自定义 Subagent SubAgentMiddleware + task 工具
middleware= 额外/覆盖 Middleware 按 .name 替换默认实例
interrupt_on= HITL 工具映射 HumanInTheLoopMiddleware；需 checkpointer
response_format= 结构化输出 主 Agent 输出 schema
state_schema= 自定义图状态 扩展 DeepAgentState
context_schema= 运行时上下文 向 Subagent 传播（见三）
checkpointer= 持久化 LangGraph checkpoint
store= 跨 thread 存储 StoreBackend 等
name= Agent 名称 trace metadata

完整签名见 customization · Full function signature。

5. 默认 Middleware 栈（重点）

Deep Agents 的「Runtime 感」 largely 来自 预装 Middleware 顺序。理解顺序才能正确覆盖、调试 Prompt caching 与 Memory 交互。

5.1 主 Agent 默认栈（first → last）

序 Middleware 条件
1 TodoListMiddleware 始终
2 SkillsMiddleware 传了 skills=
3 FilesystemMiddleware 始终（脚手架，不可 excluded）
4 SubAgentMiddleware 官方默认栈通常挂载（GP Subagent 默认开启）；禁用全部同步 subagent / 隐藏 task 后的栈形态以当前 customization 文档为准

上表「条件」列为教学向简化；以 Deep Agents Customization 默认栈为准，版本演进时请核验。
| 5 | SummarizationMiddleware | 始终 |
| 6 | PatchToolCallsMiddleware | 始终 |
| 7 | AsyncSubAgentMiddleware | 配置了 async subagents |
| 8 | 用户 middleware= | 按 .name 替换默认或插入 |
| 9 | Harness profile extras | 按 model provider |
| 10 | Excluded-tool filtering | profile 配置 |
| 11 | Prompt caching | Anthropic / Bedrock |
| 12 | MemoryMiddleware | 传了 memory= |
| 13 | HumanInTheLoopMiddleware | 传了 interrupt_on= |

Memory 放在 Prompt caching 之后，是为减少 memory 更新 invalidate 缓存前缀（官方 implementation 注释）。

5.2 同步 Subagent 内层栈差异

  • 无 SubAgentMiddleware（子图内不能再 task 委托）。
  • Skills 在 PatchToolCalls 之后（主 Agent 上 Skills 在 Filesystem 之前）。
  • 其余 broadly 与主 Agent 同形（Todo、FS、Summarization、Patch、caching…）。

5.3 覆盖规则

  • 传 middleware=[SummarizationMiddleware(...)] 且 .name 匹配默认 → 替换该默认实例（非 merge）。
  • 替换 FilesystemMiddleware 时须自带 backend=（及 permissions=），不会继承 create_deep_agent 的 backend=。
  • 禁止用 excluded_middleware 删 FilesystemMiddleware / SubAgentMiddleware → 会 ValueError；隐藏 FS 工具用 excluded_tools 或 FilesystemMiddleware(tools=[...])。

与 LangChain（六） Middleware 生命周期对照：Deep Agents 把 Todo、FS、Subagent、Summarization 等 默认启用，LangChain 需自行叠加等价 middleware（成本高）。

6. 与 LangGraph Runtime 的关系

能力 来源
Durable execution LangGraph Runtime
Checkpointer / thread 传 checkpointer=（HITL 必填）
Store 跨 thread store= + StoreBackend
Streaming stream / stream_events
Interrupt / Resume interrupt_on → LangGraph interrupt

Deep Agents 不画拓扑：标准「模型 ↔ 工具」环 + Middleware hooks，由 harness 编译成图。需要 确定性多节点编排 时仍用 LangGraph；需要 CompiledSubAgent 可把 LangGraph 图嵌入 Deep Agents 委托层（见（四））。

State 中常见字段（认名，分篇展开）：

字段 生命周期 篇
messages 对话 + tool 轨迹 全系列
todos write_todos 写入 （四）
files 虚拟 FS（StateBackend） （二）（三）

7. 实践阶梯预告

级别 做什么 证明
L0 Quickstart + FS 工具 + LangSmith trace harness 跑通
L1 memory + skills + subagent；对比 context 膨胀 厚 harness 价值
L2 interrupt_on + permissions + stream_events 可治理长任务

总结

定位：Deep Agents = Agent（六）§7 谱系中的 厚 Harness；Harness 定义见 （三）§6；底层 LangGraph Orchestration Runtime + LangChain 工具环。

四层能力：Execution / Context / Delegation / Steering。

入口：create_deep_agent → CompiledStateGraph（Runnable）。

Middleware 栈：Todo → Skills? → FS → SubAgent? → Summarization → Patch → … → Memory? → HITL?

选型：长任务 + 开箱 FS/Skills/Subagent 优先 Deep Agents；精细拓扑用 LangGraph。
