AI-Agent工程学习-DeepAgents(三)

发表于 2026-07-20 更新于 2026-08-20 分类于 计算机
Context Management：Skills、Memory、Summarization、offloading、Prompt caching、context_schema。

接 Deep Agents（二）：Execution 解决 Agent 在哪行动；Context management 解决 Agent 知道什么、能跑多久、跨会话保留什么。

0. 本篇位置

Context management = Skills + Memory + Summarization + Offloading + Prompt caching +（运行时）context_schema。

官方：Skills · Memory · Context engineering

纠偏：Memory（AGENTS.md）≠ Context Compression（Summarization）。前者是启动全量注入的持久偏好；后者是对话/大结果的压缩。

1. 上下文四层流

官方 Context engineering 将长任务上下文分为：

四者组合支撑 超出单窗口 的多步任务，减少手工 trim。

2. Skills

Skills 打包 领域工作流、知识与自定义指令（遵循 Agent Skills 标准：目录 + SKILL.md + 可选脚本/模板）。

2.1 Progressive disclosure

阶段 加载内容
启动 读各 SKILL.md frontmatter（名称、描述）
任务需要时 读 全文 与附属资源

启动 context 保持紧凑，能力仍可按需展开。

2.2 与 Tools / Memory 分工

机制 职责 加载时机
Tools 可执行能力（API、搜索、DB） 始终在 tool list
Skills 流程说明、领域知识、模板 按需读 SKILL 文件
Memory 偏好、规范、项目约定 启动全量注入

2.3 配置

Subagent：general-purpose 继承主 Agent skills；custom subagent 用 skills=[...] 独立配置，状态 双向隔离。

3. Memory（AGENTS.md）

memory= 传入一个或多个 AGENTS.md 路径；启动时 全量加载 进 system 侧 context。

  • 内容示例：编码风格、review 规则、项目结构约定。
  • Agent 可基于交互 更新 memory（偏好随使用演进）。
  • 存储取决于 Backend：StateBackend / StoreBackend / FilesystemBackend。

与 Skills 对比：Memory 总是在 context 里；Skills 只有 frontmatter 常驻，正文按需。

4. Summarization

SummarizationMiddleware（默认栈）在对话接近 token 上限时 压缩历史，保留最近消息。

覆盖默认实例以调整阈值：

trigger 还支持 ("fraction", ...) 或 OR 组合列表。create_summarization_tool_middleware 允许 Agent 在任务间隙主动触发摘要。

对齐 LE · 压缩：摘要不得丢掉合同、预算等不可摘要字段（若放在 state 独立字段中）。

5. Context Offloading

当 tool 返回或中间产物 过大，harness 将内容 写入虚拟 FS，messages 中只保留引用或短摘要。

典型模式（可在 Subagent system_prompt 中要求）：

Offloading 与 Summarization 互补：前者卸大单次结果，后者压整条对话历史。Backend 细节见（二）。

6. Prompt Caching

对 Anthropic / Amazon Bedrock（Claude / Nova），create_deep_agent 默认对静态 system 段（base prompt、memory、skills）做 prompt caching，降低长运行 latency 与 cost。

  • 其他 provider：见 Middleware integrations 或手动挂 provider caching middleware。
  • 覆盖 TTL 示例：AnthropicPromptCachingMiddleware(ttl="1h")（见（五））。

Memory 更新可能 invalidate 缓存前缀——默认栈把 MemoryMiddleware 放在 caching 之后 partly 为此（见（一）§5）。

7. Runtime Context（context_schema）

与「上下文压缩」不同：指每次 invoke 传入的 运行时业务上下文（user_id、feature flags、租户…），经 context_schema 声明类型。

所有 Subagent 收到 相同 父 context；per-subagent 配置可用 namespaced 字段（如 researcher_max_depth）或 dataclass 独立字段。

工具内可用 runtime.config["metadata"]["lc_agent_name"] 区分是哪个 Agent 发起的调用（与 LangSmith 过滤一致，见（四））。

8. L1 实验（前半）

步骤 操作
1 配置 memory=["/AGENTS.md"] + seed 文件
2 配置 skills=["/skills/"] + 一个 SKILL.md
3 LangSmith 或日志对比：仅 memory vs memory+skills frontmatter 的首轮 system 体积
4 提问触发 skill 全文加载，观察第二轮 prompt 变化

Done 判据：能口述 Skills / Memory / Summarization 各解决什么问题。

本模块自检与面试

总结

四层流：Input → Compression → Isolation → Long-term。

Skills：按需加载的领域包；≠ Tools ≠ Memory。

Memory：AGENTS.md 全量启动；可更新。

Summarization：历史压缩；可覆盖 trigger/keep。

Offloading：大结果写 FS；配 Subagent 摘要回传。

Prompt caching：Anthropic/Bedrock 静态段缓存。

context_schema：运行时注入；≠ 窗口压缩。
