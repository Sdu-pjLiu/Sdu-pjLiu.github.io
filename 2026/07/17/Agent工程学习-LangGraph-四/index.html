AI-Agent工程学习-LangGraph(四)

发表于 2026-07-17 更新于 2026-08-20 分类于 计算机
Superstep、并行 fan-out/fan-in、Command 路由、Streaming 与节点重试。

接 LangGraph（三）：Persistence 就绪之后，理解图 如何一步步推进——超步、并行、流式与重试。

0. Runtime 架构与本篇位置

LangGraph 的执行语义是 状态机 + 超步（superstep），不是泛化的「消息总线」或「事件驱动框架」。

旁路能力从 Runtime 引出：

旁路 触发点
Streaming 每步 updates / messages / custom 投影
Interrupt 节点内 interrupt() → 挂起并 checkpoint
Time Travel get_state_history / update_state 分叉

官方：Use the graph API

1. Superstep 与事务感

  • 并行分支在 同一 superstep 执行。
  • 若任一分支抛错，整 superstep 的状态更新不提交（事务感）。
  • 使用 checkpointer 时：已成功 superstep 的结果已落盘；恢复时 不重做已成功部分。

这与「整图从头重跑」不同——企业长任务依赖这一点。

2. 并行：Fan-out / Fan-in

Fan-out：从一点到多节点并行（或多路 conditional）。

Fan-in：多路汇合；各分支 partial update 经 Reducer 合并（见二）。

典型：两路检索（向量 + 关键词）→ 汇合节点 → 生成。

设计要点：

  1. 并行写 不同键 最安全；同键需明确 reducer。
  2. 汇合节点读合并后的 state，不要假设分支执行顺序。

3. Send：运行时动态并行

静态 fan-out 的分支数在建图时已知；Send 用于运行时按数据量动态生成 N 个任务，形成 Map-Reduce。

静态 fan-out Send 动态并行
分支数 建图时固定 运行时由 state 决定
典型场景 固定双路检索 N 篇文档分别摘要、N 个主题分别研究
汇合 Reducer Reducer

Send 的每个任务可收到独立输入；结果写回共享键时，必须为该键配置可结合的 reducer。

4. Command：更新 + 路由

现代写法：节点返回 Command，同时 更新 state 并 指定下一跳（或结束）。

相对「只返回 dict + 单独 conditional edge」：Command 把 治理逻辑 收进节点，适合验证门（对齐 LE Gate）。

5. Streaming 与异步

LangGraph 与 LangChain Agent 共享 streaming 机制（见 LangChain（五））。

stream_mode 输出
values 每步后的完整 state
updates 每个节点产生的局部更新
messages LLM token + metadata 元组
custom 节点通过 stream writer 发出的进度
checkpoints / tasks checkpoint 事件 / task 开始结束（需 checkpointer）
debug 最完整调试信息，体积也最大

细粒度事件可用 graph.stream_events(..., version="v3")（独立 projection，与 stream 的 mode 参数不同）。新项目优先 v3；若文档/示例仍写 v2，以当前官方文档为准。stream(..., version="v2") 则产出统一 StreamPart，勿与 stream_events 的 version 混为一谈。

异步 I/O 密集图把节点改为 async def，并使用 ainvoke / astream。

UI 进度、可观测、提前取消依赖 streaming；图级比单 Agent 更细，可看到每个 Node 的 state 转移。

6. Loop 安全阀：recursion_limit

Loop Graph 必须有业务停止条件，同时设置图级 recursion_limit。它限制一次执行允许的 superstep 数；触顶抛出 GraphRecursionError。

注意：recursion_limit 是 config 顶层键，不放进 configurable。

与 LE 双层预算 对齐：

  1. recursion_limit 是最后的 硬顶保险丝；
  2. state 内 remaining_budget / step_count 用于提前走「优雅收尾」分支；
  3. 不要只调大上限掩盖无进展循环。

7. 节点重试 vs 整图重跑

机制 行为
节点重试 单节点失败重试；runtime.execution_info.node_attempt 等可观测
Checkpoint 恢复 进程级失败从最近 checkpoint 续跑
外层 while 重跑 简单但浪费；长任务不推荐

LangChain Middleware 的 ModelRetry/ToolRetry 在 Agent 子图内；图级仍可在节点外包 retry 策略或使用平台能力。

总结

Superstep：并行提交 + 事务感 + checkpoint 边界。

并行：Fan-out/fan-in + reducer。

动态并行：Send 按运行时数据展开 Map-Reduce。

Command：state 更新与路由一体。

Streaming：event streaming 优先；mode 侧按 values / updates / messages / custom 等选择。

循环安全：业务停止条件 + state 预算 + recursion_limit 三层。

重试：节点级 vs checkpoint 恢复，勿默认整图重跑。
