AI-Agent工程学习-LangGraph(二)

发表于 2026-07-17 分类于 计算机
State Schema、Partial update、Reducer 与 MessagesState；与 Agent/LE 状态字段对齐。

接 LangGraph（一）：会画 Node/Edge 之后，先搞清 State 怎么定义、怎么合并——这是图编排的地基。

0. 本篇位置

节点不返回「整份 state」，只返回 partial update；Runtime 按 Reducer 规则合并进共享状态。

1. State Schema

State 用 TypedDict、dataclass 或预置类型声明字段。

类型 说明
MessagesState 预置 messages 列表，适合对话/Agent
自定义 TypedDict 加 goal、step_count、artifacts 等
dataclass 同上，带默认值时注意可序列化

与 Agent（一）State 对齐：显式字段优于只靠长对话文本。

2. Partial update 与 Reducer

Partial update：节点只返回要改的键。

Reducer：同一键多次更新如何合并。

策略 行为 典型字段
覆盖 后写覆盖前写 goal、status
追加（add_messages 等） 列表合并 messages
自定义 reducer 求和、去重、取 max step_count、预算

messages 常用 add_messages reducer：新消息 追加，而不是整表替换。

MessagesState 已为 messages 配好 add_messages；继承它时只需声明新增字段。自定义 reducer 的节点必须返回与 reducer 语义匹配的 delta。

3. 与 Agent / LE 状态对齐

可把理论里的治理字段放进图 state（便于条件边与验证节点读取）：

字段示例 用途 理论回链
goal 任务摘要 Agent 规划
step_count / remaining_budget 硬顶 LE 双层预算
contract_ok 可机检 Done LE Contract
handoff_note 优雅收尾 LE 优雅收尾

压缩/摘要时：合同与剩余预算等不可摘要字段应单独保留（对齐 LE 压缩丢合同 反模式）。

4. 常见坑

坑 症状 改法
messages 被覆盖 历史丢光 用 add_messages / Annotated reducer
并行写同一键 超步内冲突 设计 reducer；或拆键
不可 JSON 化 checkpoint 失败 state 字段可序列化
隐式全局变量 多 thread 串台 状态进 state / Store，不用模块级 mutable

并行分支在同一 superstep 内写入时，Reducer 决定最终合并结果（见四）。

并行 reducer 还应满足：

  1. 可结合：不同分组顺序不改变结果，如加法、列表拼接。
  2. 顺序无关时可交换：若业务依赖先后顺序，不要让并行分支竞争写同一键。
  3. 重放安全：有副作用的数据不要只靠 reducer 去重，应使用稳定 ID 或幂等写入。

自学检查

  1. Node 返回值与 invoke 输入的 state 关系？
  2. messages 为什么需要 append reducer？
  3. 预算计数适合覆盖还是累加 reducer？
  4. 哪些字段不应被摘要节点覆盖？
  5. 使用累加 reducer 时，节点应返回累计值还是增量？

总结

Schema：TypedDict / MessagesState / 自定义字段。

Partial update：节点只改需要的键。

Reducer：覆盖 vs 追加；add_messages 是对话关键。

对齐：Goal、预算、合同、handoff 可进 state。
