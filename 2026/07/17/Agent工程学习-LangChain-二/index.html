AI-Agent工程学习-LangChain(二)

发表于 2026-07-17 更新于 2026-08-20 分类于 计算机
LCEL 与 Runnable：Sequence/Parallel/Lambda/Passthrough/Branch；确定性流水线，不是手搓 Agent loop。

接 LangChain（一）：Messages 与 Model 齐备之后，先掌握 LCEL（LangChain Expression Language）——用 Runnable 拼确定性流水线（RAG 链、路由、格式化）。

0. 本篇位置

LCEL 解决什么： 把「prompt → model → 解析 / 检索 → 再模型」写成可组合、可流式、可批次的管道。

LCEL 不解决什么： 完整的「模型选工具 → 执行 → 再想」Agent 循环。那是 create_agent 的职责。

与 Agent（一）Chat vs Workflow 一致：路径固定时用链；路径由模型动态决定时用 Agent。

1. Runnable 接口

几乎所有可组合单元（prompt、model、retriever、自定义函数）都实现 Runnable：

方法 作用
invoke / ainvoke 单次同步 / 异步
stream / astream 流式输出
batch / abatch 批量

统一接口的好处：换一截管道不必改调用方；流式与批处理「免费」继承。

2. 组合原语

2.1 RunnableSequence 与 |

顺序管道：上一步输出是下一步输入。

2.2 RunnableParallel

并行跑多支，合并为字典。旧文里的 RunnableMap 即此类能力，不必单列学习。

2.3 RunnableLambda

把普通 Python 函数包成 Runnable（清洗、截断、拼字符串）。

2.4 RunnablePassthrough

把输入原样传到下游，常与 Parallel 合用：一边保留 question，一边跑检索。

2.5 RunnableBranch

按条件选支路（简单路由）。复杂状态机留给 LangGraph。

3. Binding 与 Fallbacks（认名）

能力 作用
.bind(...) / RunnableBinding 固定部分参数（如 temperature、已 bind 的 tools）
Fallbacks 主链失败时切备用模型 / 备用链

与 LLM 四 · 限流重试、六 · Middleware 重试 同一类韧性问题：链级用 Fallbacks；Agent 环内常用 Middleware。

总结

LCEL：确定性流水线的组合语言；不是 Agent 主路径。

Runnable：invoke / stream / batch 统一接口。

原语：Sequence（|）、Parallel（含旧称 Map）、Lambda、Passthrough、Branch。

韧性：Binding / Fallbacks 认名；环内治理见 Middleware。
