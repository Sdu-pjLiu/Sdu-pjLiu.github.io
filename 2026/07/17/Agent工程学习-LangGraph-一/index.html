1. 两种 API：Graph 与 Functional

LangGraph 提供两种共享同一 Runtime 的写法：

API 核心入口 适合
Graph API StateGraph、Node、Edge 显式拓扑、条件分支、循环、可视化；本系列主线
Functional API @entrypoint、@task 尽量保留普通函数结构，同时获得持久化、流式与 HITL

两者可以在同一应用中互调。需要看清「状态经哪条边流动」时优先 Graph API；已有函数式任务流只想补 Durable / Interrupt 时可选 Functional API。本系列不展开第二套平行教程。

2. 为何需要图编排

单 create_agent 足够时：标准「模型 ↔ 工具」闭环 + Middleware 即可（见 LangChain 五）。

需要 LangGraph 的典型信号：

需求 LangGraph 提供
固定预处理 / 后处理 + Agent 多节点拓扑
长任务跨失败恢复 Durable execution + Checkpointer
任意点人工审批 interrupt() / resume
多 Agent 分工 Subgraph / Supervisor
可机检分支 Conditional Edge / 验证节点

与 Agent（一） Workflow vs Agent 一致：路径固定部分用图节点；路径由模型决定的部分可嵌 create_agent 子图（见六）。

3. StateGraph 核心构件

构件 作用
State 图内共享状态（如 MessagesState 或自定义 Schema）
Node 函数：读 state → 返回 partial update
Edge 固定下一跳
Conditional Edge 路由函数决定下一节点
START / END 入口/出口哨兵（官方 API 名；勿称 Entry/Exit Node）

create_agent 编译结果也是图——本系列学的是 自己画拓扑。

4. DAG 与 Loop

形态 特征 典型用途
DAG 无回边 ETL、审批链、检索→生成→格式化
Loop Graph 含回边 工具环、重试环、规划外环

LangGraph 强项是 有状态循环图，不只是 DAG 工作流。

总结

定位：LangGraph = 编排 Runtime；durable / HITL / persistence 是选它的理由。

构件：State、Node、Edge、Conditional Edge、START/END。

形态：DAG 流水线 vs 含回边的 Loop。

API：Graph API 是主线；Functional API 用 @entrypoint / @task 给函数式流程补 Runtime 能力。

compile/invoke：可执行图 + 配置入口。
