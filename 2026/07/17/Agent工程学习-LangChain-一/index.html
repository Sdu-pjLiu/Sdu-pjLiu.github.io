AI-Agent工程学习-LangChain(一)

发表于 2026-07-17 更新于 2026-08-20 分类于 计算机
LangChain 开篇：薄 Harness 实现、与 LangGraph/Deep Agents 边界、Messages 与 ChatModel/Embeddings。

接 Loop Engineering（三）：理论与选型齐备之后，进入 实现层——Harness 完整定义见 Agent（三）§6；本篇讲 LangChain 薄 Harness 实现，用 create_agent 把合同、工具与预算落到可运行代码。

0. 本系列在学习路径中的位置

LLM / Prompt / Agent / LE 负责：模型怎么调用、Prompt 怎么控、Agent 闭环与收敛工程。

LangChain 负责：用官方组件把上述概念写成可维护系统——Messages、Model、Tools、RAG 积木、create_agent（薄 Harness）、Middleware。

产品 一句话 本系列深度
LangChain 薄 Harness：create_agent + middleware 主线
LangGraph 低层编排：状态机、确定性 + Agent 混合 认名；下一模块
Deep Agents batteries-included（压缩、虚拟 FS、subagent） 认名；Multi-Agent 之后
LangSmith trace / eval 轻量接入（见六）

官方入口：LangChain overview。

0.1 LangChain 模块地图

把 LangChain 看成 分层组件栈，而不是「一堆 import 名」：

两条主执行路径：

路径 何时用 典型链路
确定性 Workflow 步骤固定、无需模型选路 Prompt → Runnable → Model → Parser
Agent Loop 目标驱动、需选工具 Messages → Model → ToolNode → Model → Final Answer

Runnable 统一接口：create_agent 编译产物、LCEL 链、LangGraph 编译图都支持 invoke / stream / batch——换编排方式时，调用方接口不变（详见（二）与（五））。

1. LangChain 薄 Harness 实现

Harness 完整定义见 Agent（三）§6。实现层常见表述：Agent = Model + Harness——Model 决定下一步；Harness 环绕模型循环，调度 Memory / Tools / Planning 与治理。

create_agent 是 LangChain 的 薄 Harness 入口：最简只需 model + tools；进阶能力用 Middleware 按需叠加（细节见五、六）。

与 Agent（一）Loop 对齐：Thought/Action/Observation 在实现上就是「消息历史 + tool_calls + ToolMessage」。

本系列不手搓 while-True Agent loop；也不把旧版 AgentExecutor 当主路径。

2. Messages（状态里的基本单位）

Chat / Agent 的上下文以 消息列表传递，不是一整段无结构字符串。

类型 角色 常见用途
SystemMessage 系统 角色、硬规则、长期指令
HumanMessage 用户 任务输入
AIMessage 模型 回复文本；可含 tool_calls
ToolMessage 工具 某次 tool call 的 Observation

要点：

  1. tool_calls：模型决定调用哪些工具及参数（对齐 LLM 四 · Tool Calling）。
  2. content / content_blocks：文本与多模态块；新接口常读 content_blocks。
  3. Agent 状态默认含 messages；多轮靠 checkpointer + thread_id 持久化（见五）。

3. ChatModel（主路径）

现代 Agent 只用 ChatModel，不用旧式 completion LLM（后者认名即可）。

3.1 统一接口与调用

  • 标识串："provider:model"（如 openai:gpt-4.1-mini、anthropic:claude-sonnet-4-6）。
  • 也可传入已初始化的模型实例。
  • 常用方法：invoke / ainvoke、stream、batch。

（具体 init API 以当前包版本为准；思想是 一个接口换多家 provider。）

3.2 与工具、结构化输出的绑定（认名）

API / 能力 作用
bind_tools 把工具 schema 挂到模型，支持原生 tool calling
with_structured_output 模型直接吐校验后的结构（Pydantic 等）
Agent 的 response_format harness 级结构化结果，进 structured_response（见五）

换模型时优先保持 消息格式 + 工具 schema 不变，只改 provider 串——这是 LangChain「标准模型接口」的工程收益。

回链：LLM 三 · 消息角色、LLM 四 · 调用韧性。

4. Embeddings（为检索铺垫）

Embedding Model：把文本变成向量，供 VectorStore / 相似度检索使用。

  • 与 ChatModel 分工不同：Embeddings 不做对话决策，只做语义索引。
  • RAG 积木见（四）；Agent 侧常见挂法是「retrieve 封成 Tool」。

旧式 LLM（completion）：字符串进字符串出、无消息角色；读旧教程时能认即可，新 Agent 代码不要用。

总结

定位：LangChain = 薄 Harness 实现；底层借 LangGraph Orchestration Runtime；Deep Agents 是厚 Harness。

公式：Harness 定义见 Agent（三）§6；LangChain 提供 Model + 可定制薄 Harness（create_agent + middleware）。

Messages：System / Human / AI / Tool；tool_calls 驱动闭环。

ChatModel：provider:model、invoke/stream、bind_tools / structured output。

Embeddings：RAG 向量侧；细节到（四）。
