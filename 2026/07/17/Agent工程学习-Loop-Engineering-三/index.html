AI-Agent工程学习-Loop Engineering(三)

发表于 2026-07-17 分类于 计算机
Loop 反模式、与 Agent 组件拼装、轨迹指标回归、实践阶梯；学习路径收口。

接Loop Engineering（二）：会分层与管预算之后，用反模式加固、与 Agent 组件拼装，并收口整条学习路径。

1. 反模式字典

反模式 症状 改法
无合同 while 「做完为止」却无法判断 Done 写可机检 Contract（LE 一）
自评唯一门 模型说完成即 Success Gate 用测试/规则/独立 Checker
有验证无上限 验证一直 fail 仍无限重试 硬顶 + 无进展检测
撞预算不收尾 超时直接断，无 Checkpoint 优雅收尾：落盘状态 + handoff note
压缩丢合同/预算 摘要后忘了验收标准或剩余额度 不可摘要字段 + forward remaining
内环兼验收 同一步既改世界又给自己打分 Maker–Checker 分离
Workflow 硬套 Agent 路径固定却上完整 Loop 退回 Chaining / Workflow（Agent 一）

2. 与 Agent 组件拼装

组件 在 Loop 中的角色 回链
Skill 教内环「这类任务怎么走」 Agent 三 §1.4 / 六
Tools 真正改世界 / 取证 LLM 四
Memory / Checkpoint 跨步可见状态；着陆续跑 Agent 三
权限 / 沙箱 Gate 之外的硬拦 Agent 六 §3
Hooks 工具前校验、压缩前、步数门禁 Agent 六 §6
Injection 防御 不可信 Observation 不当指令 PE 四

LE 不替代上述组件，只规定：环如何对照合同停下。

3. 用轨迹指标回归 Loop

接 Agent（四）增量指标：

指标 接到 Loop 的用法
假完成 / Hallucination 无 Gate 支撑禁止 Success；监控「自评关环」率
Unnecessary Tool Calls / 重复工具率 触发无进展打断
Avg Steps / Cost per Success 校准硬顶与软预算
Tool Error Recovery Rate 外环是否换策略而非空转

发版时：改 Contract / Gate / 预算策略 = 改 Loop 版本；用 Scenario 集回归，与 Prompt/Schema 版本一并固定。

4. 实践阶梯 L0 → L2

级别 做什么 证明你会了什么
L0 单一可机检合同（如「mock 搜索非空 + Schema 合法」）+ max_steps Contract + 硬顶
L1 内环 + 验证环（确定性检查或只读 Checker） Maker–Checker / Gate
L2 无进展换策略 + 预算耗尽优雅收尾 + 压缩后续传预算 嵌套外环与双层预算

Research / 编码 Agent 都适用同一阶梯：先有客观门，再谈复杂规划。

5. 阶段收口：应能回答的 12 问

  1. LE 与 Agent（一）Loop 语义差在哪？
  2. 好 Contract 至少具备哪三态？
  3. 验证门信任梯度是什么？
  4. 为何 Checker 宜只读？
  5. 内环 / 验证环 / 外环各管什么？
  6. 硬顶与软任务预算如何配合？
  7. 压缩后为何要 forward remaining？
  8. 优雅收尾最少留下什么？
  9. 无进展三种出路？
  10. 列出三种 Loop 反模式及改法。
  11. 假完成率如何接到 Runtime 门禁？
  12. L0→L2 各证明什么？

答不上的回 LE（一）（二）或对应 Agent 篇。

自学检查（本篇）

  1. 「有验证无上限」为何仍会烧预算？
  2. 拼装图里 Contract 与 Skill 谁先谁后？
  3. L1 与 L2 的分水岭是什么？

总结

反模式：无合同、仅靠自评结束循环、无硬顶、不收尾、压缩丢治理。

拼装：LE 规定停下方式；Skill/Tools/Memory/Runtime 提供能力与闸门。

回归：轨迹指标进门禁与发版 checklist。

实践：L0 合同+硬顶 → L1 验证环 → L2 外环与优雅收尾。
