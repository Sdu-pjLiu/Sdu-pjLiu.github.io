AI-Agent工程学习-LangChain(六)

发表于 2026-07-17 更新于 2026-08-20 分类于 计算机
Middleware hooks 与内置对照、自定义示意、LangSmith、实践阶梯；LangChain 收口并指向 LangGraph。

接 LangChain（五）：最小闭环跑通之后，用 Middleware 扩展 Harness——压缩、HITL、重试、预算、护栏——并收口本系列。

Middleware = Harness 扩展机制（理论 Hooks 见 Agent（三）§6.3、认名见 （六）§6）。

0. 本篇位置

官方：Middleware overview。

Middleware ≠ 另一套 Runtime：hooks 跑在 create_agent 编译出的 LangGraph 里；整段 Agent（含 middleware）可再嵌进更大 StateGraph（LangGraph 模块展开）。

Filesystem / Skills / Subagent 等厚能力 → Deep Agents 预装栈；本篇只认名，不展开。

1. Harness 生命周期与 Hooks

一次 agent.invoke 在 harness 内的典型请求流：

Middleware 挂载点与内置能力对照：

阶段 Hook 典型 Middleware
启动 before_agent 加载 thread 历史
进模型前 before_model Summarization、PII 脱敏
模型调用 wrap_model_call ModelRetry、动态改 tools
模型后 after_model HumanInTheLoop、Guardrails
工具执行 wrap_tool_call ToolRetry、allowlist
结束 after_agent 通知、清理

1.1 Hooks 认名

环内步骤：模型调用 ↔ 工具执行。Middleware 在关键点插入逻辑：

Hook（概念名） 典型用途
before_agent 启动时加载记忆、校验输入
before_model 截断/摘要历史、去 PII
wrap_model_call 重试、缓存、动态改 tools/prompt/model
wrap_tool_call 工具级重试、注入上下文、拦截执行
after_model HITL 审批 tool_calls、路由
after_agent 落盘、通知、清理

多枚 middleware 顺序组合：进模型前顺序执行，出模型后常反向（与 Web middleware 类似）。以当前文档为准。

2. 内置 Middleware ↔ 理论回链

Middleware 解决什么 理论回链
SummarizationMiddleware Context 将满时摘要压缩 Agent 五 · 压缩
HumanInTheLoopMiddleware 高风险工具前人工确认 Agent 三 Runtime、LE Gate
ModelRetryMiddleware / ToolRetryMiddleware 瞬时失败重试 LLM 四 · 调用韧性
Model/call limit 类 硬顶步数/调用次数 Budget、LE 双层预算
PIIMiddleware 脱敏/拦截敏感信息 Agent 六、PE 四 Injection
Guardrails（Middleware 护栏） 输入/输出合规检查、拦截违规内容 官方 overview 中的 guardrails 能力；通常挂在 before_model / after_model
TodoListMiddleware 规划清单工具 Agent 二 · 规划

压缩时注意：LE · 压缩后续传预算——摘要不得丢掉合同与剩余额度等不可摘要字段（若你在 state 中存放了它们）。

3. 自定义 Middleware（最小示意）

业务闸门（工具白名单、步数硬顶、假完成检测）用自定义 hooks，而不是改模型提示碰运气。

边界： 下列为职责示意，不可照抄运行。现行写法以官方 AgentMiddleware / @before_model / @wrap_tool_call 等为准；「Guardrails」指一类护栏能力，并非单一固定类名。

对齐 LE：确定性规则优先于「请模型自己注意」。

4. LangSmith（轻量）

4.1 Trace（单次排障）

  • 设 LANGSMITH_TRACING=true 与 API Key，即可看到 model / tool / middleware 轨迹。
  • 用途：定位错调工具、空转、压缩前后 Context 变化。
  • L2 要求：本地能打开一条 成功 与一条 失败 trace，并对照 tool_calls、exit_reason、token 用量。

4.2 Dataset + Experiment（批量回归）

概念 解决什么 与 Agent 路径对应
Dataset 固定输入集（Scenario 问题 + fixture） Agent（四）§6.4 Scenario 最小集
Experiment 同一 Dataset 上批量跑、对比 version 发版前 Task Success / Tool 指标回归
Trace 单次 run 细查 P95 延迟、Middleware 事件、Citation 字段

与 Checklist 关系：

  • Dataset 跑：Task Success Rate、假完成率、重复工具率（Loop/Agent 域）
  • Trace 查：检索 P95、avg tokens/成功、Gate 拦截记录（RAG / Context 域）

Eval 流水线在此 认名 即可；RAGAS / LangSmith Eval 分步教程属可选进阶，不在 LangChain 系列正文展开。完整发版清单见 Agent（四）§6。

官方建议同时了解 LangSmith Engine（监控与问题定位）；实现细节属平台篇，此处认名。

5. 实践阶梯 L0 → L2

级别 做什么 证明
L0 create_agent + 2～3 个 @tool + 可机检输出（或 response_format） 最小闭环
L1 checkpointer 多轮 + streaming；RAG Tool 挂上 记忆与检索入环
L2 Summarization + Retry/Limit +（可选）HITL；LangSmith 可见关键跨 harness 可治理

Filesystem / Skills / Subagent → 升到 Deep Agents，或自建等价 middleware（成本高）。

6. 边界与下一模块

需求 去向
可定制单 Agent harness 本系列（LangChain）
多节点确定性编排、复杂分支、子图 LangGraph
开箱压缩 + 虚拟 FS + subagent Deep Agents（基于 create_agent）

总结

Middleware：Harness 扩展机制（Agent（三）§6.3）；hooks 插在模型/工具前后。

内置：压缩、HITL、重试、限次、PII、Todo——对齐理论 Runtime / LE。

自定义：确定性闸门优先生 middleware。

LangSmith：Trace 排障 + Dataset/Experiment 回归（§4.2）；对齐 Agent（四）§6 Checklist。

阶梯：L0 闭环 → L1 记忆/检索 → L2 可治理。
