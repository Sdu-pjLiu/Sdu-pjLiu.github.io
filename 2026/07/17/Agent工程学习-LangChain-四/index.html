AI-Agent工程学习-LangChain(四)

发表于 2026-07-17 更新于 2026-07-23 分类于 计算机
Document/Loader/Splitter、VectorStore、Retriever 与 RAG 增强模式；检索封成 Tool 挂进 Agent。

接 LangChain（三）：Tools 齐备之后，补 检索积木。现代路径不是「另起一套 RAG Runtime」，而是把检索做成链或 Tool，再交给 create_agent。

0. 本篇位置

回链：LLM 一 · Embedding / Context、Agent 三 · RAG 挂法、Agent 五 · Context 压缩。

复杂多跳编排、多检索器状态机 → LangGraph；深化见 RAG 系列（一）～（五）；本篇只到「积木 + 挂 Agent」。

1. Document 层

组件 作用
Document page_content + metadata
Loader 从文件/网页/API 载入 Document 列表
TextSplitter 按长度/分隔符切块（控制检索粒度与噪声）

切块过粗：检索不准；过细：丢失上下文。metadata（来源、章节）供过滤与引用。

2. Embeddings + VectorStore

  1. 用 Embedding Model 向量化文本块。
  2. 写入 VectorStore（内存 / PGVector / 云向量库等）。
  3. 查询时：similarity_search（或带分数的变体）、可选 MMR（多样性，减少近重复块）。

工程注意：embedding 模型与索引必须成对版本化；换模型常需重建索引。

3. Retriever 与增强模式（模式级）

Retriever：invoke(query) -> list[Document] 的统一检索接口；VectorStore 常 .as_retriever()。

下列多为 模式 / 集成能力，不必当成「LangChain 核心必背 API」：

模式 解决什么
Hybrid Search 关键词 + 向量，兼顾专有名词与语义
Reranker 初检多召回，精排压噪声
Query Expansion 改写/扩展查询，提高召回
Context Compression 压缩进窗前的冗余（对齐 Context 治理）

选型原则：先可测的「检索命中率 / 引用正确率」，再堆增强；增强失败时要能降级到朴素 similarity。

4. LCEL 问答链（确定性）

适合：问题类型固定、只需「检索 + 生成」、无多步工具决策。对齐 Workflow，而非完整 Agent。

5. 挂进 Agent：retrieve 封成 Tool

Agent 需要「要不要检索、检索什么、检索几次」时，把检索做成工具：

要点：

  1. description 写清「何时用 / 勿滥用」（防无意义检索烧预算）。
  2. 返回长度设上限，避免单次 Observation 撑爆 Context（Agent 五）。
  3. 可机检合同可要求「最终答案必须含引用 metadata」——用结构化输出或后置 Gate（LE 一）。

中间件注入检索结果（不经 tool call）也是合法模式；本系列默认 Tool 挂法 更透明、易 trace。

本模块自检与面试

学完本篇后，请到 LangChain · 自检与面试 完成学习自检与面试题（含推荐回答）。

总结

Document 层：载入与切块；metadata 服务过滤与引用。

索引：Embeddings + VectorStore；similarity / MMR。

Retriever：统一检索接口；增强模式按需、可降级。

两条挂法：确定性 LCEL 链；或 Tool → create_agent。
