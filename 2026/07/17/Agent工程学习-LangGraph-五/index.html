AI-Agent工程学习-LangGraph(五)

发表于 2026-07-17 更新于 2026-08-20 分类于 计算机
interrupt/resume、HITL、Time Travel、durable execution；与 LE 合同/门/预算映射。

接 LangGraph（四）：会推进图之后，学 可控运行——暂停、恢复、分叉调试，并与 Loop Engineering 对齐。

0. 本篇位置

LangGraph 相对「只跑完为止的 Agent 环」的核心增量之一：在任意节点暂停，等人或外部系统，再精确续跑。

官方：Interrupts

前提（缺一不可）：

  1. Checkpointer（生产用持久化后端）
  2. thread_id in config
  3. 在需要暂停处调用 interrupt(payload)（payload 需 JSON 可序列化）

1. interrupt 与 resume

流程（概念）：

与 LangChain HumanInTheLoopMiddleware 同族：Middleware 在 harness 内封装；LangGraph interrupt() 在 自定义图 任意节点显式暂停。

恢复时必须复用同一 thread_id。Command(resume=...) 的值会成为 interrupt() 的返回值。

1.1 Interrupt 的重放规则

恢复不是从 Python 的中断行继续，而是从 该节点开头重跑。因此：

  1. interrupt() 前的逻辑必须幂等；
  2. 邮件发送、扣款等副作用放在审批通过后的独立节点；
  3. 不要用 try/except 包住 interrupt()（Runtime 依赖特殊异常完成暂停）；
  4. 一个节点内避免 while True + interrupt()；校验失败应更新 state 并通过边回到节点。

2. HITL 模式

模式 做法
审批 tool 模型产出 tool_calls → interrupt 展示 → resume 批准/拒绝
改 state 再续 人工编辑 checkpoint 中字段（Studio / API）
改路由 resume 时带不同 value，节点分支不同

对齐 Agent 三 Runtime · HITL 与 LE 验证门：Gate 不必只靠模型自评。

3. Durable execution

长运行工作流（小时/天级）：

  • 每 superstep / 节点边界 checkpoint
  • 进程重启后 thread_id 指向同一链 → 从断点继续
  • 已成功步骤不重复（配合 superstep 语义）

这是「企业级 Workflow 编排」选 LangGraph 的主因之一。

4. Time Travel：查看、重放、分叉

有 checkpoint 历史时，可：

  • 查看：get_state / get_state_history
  • 重放：用历史快照的 config 再次 invoke
  • 分叉：对旧 checkpoint 调 update_state，再用 None 续跑

update_state 不是回滚原线程，而是创建新 checkpoint 分支；更新仍经过 reducer。并行历史无法推断最后节点时，可显式传 as_node=。

用途：复现失败步、A/B 路由、审计「若当时选了 B 会怎样」。

5. 与 Loop Engineering 对照

LE 概念 LangGraph 落点
Contract（可机检 Done） 验证节点 + Command(goto=END)；response_format 子图
Verification Gate 确定性检查节点；interrupt 人工门；conditional edge
Maker–Checker 生成节点与验收节点分离（不同 Node）
硬顶 / 软预算 recursion_limit + state 中 step_count / remaining_budget（见四）
无进展 检测节点 → 换策略边或 goto 重启子图
优雅收尾 预算耗尽分支写 handoff_note + checkpoint，禁止静默断

禁止：仅靠模型宣称完成 作为唯一结束条件（LE 反模式）。

总结

interrupt/resume：精确暂停与续跑；payload 可展示给 UI。

HITL：审批、改 state、改路由。

Durable：长任务断点续跑。

Time Travel：查看、重放、update_state 分叉；原历史不被覆盖。

LE 映射：合同、门、预算、优雅收尾落到节点与边。
