AI-Agent工程学习-LangGraph(三)

发表于 2026-07-17 更新于 2026-07-23 分类于 计算机
Checkpointer vs Store、thread_id、多轮续跑与 context_schema；短时与长时记忆两分法。

接 LangGraph（二）：State 会合并之后，学 Persistence——企业级 Agent Workflow 为何能续跑、恢复、跨会话记东西。

0. 本篇位置

官方 persistence 两分法（Persistence）：

多数应用 两者都用：checkpointer 管当前对话线程，store 管用户偏好与事实。

1. Checkpointer vs Store

Checkpointer Store
存什么 图 state 快照（checkpoint） 应用自定义 KV
作用域 单个 thread 跨 thread
典型用途 多轮续聊、HITL、故障恢复、time travel 用户偏好、长期事实
访问方式 config={"configurable": {"thread_id": ...}} 节点内 Runtime 读写 store

不要把口语 Session 当官方一等概念；会话单元用 thread_id 指代 checkpointer 里的一条线程。

2. thread_id 与多轮续跑

同一 thread_id → 加载上次 checkpoint → state（含 messages）延续。

与 LangChain 五 · checkpointer 同一机制；LangGraph 层可 自定义图 并在任意节点间 checkpoint。

生产环境用 持久化 checkpointer（如官方文档中的 PostgresSaver / SqliteSaver 等数据库后端），不要只用 InMemorySaver。节点级瞬时故障可配 retry_policy（与整图从 checkpoint 恢复是两层机制）。编译期还可用 interrupt_before / interrupt_after 在指定节点边界暂停，与节点内 interrupt() 同属 HITL 族。

3. 故障恢复（认名）

Durable execution：进程崩溃后，从最近 checkpoint 恢复，已成功节点不必整图重跑（与 superstep 事务配合，见四）。

这是选 LangGraph 相对「单次 invoke ChatModel」的关键增量之一。

恢复必须同时满足：

  1. 复用同一 持久化 checkpointer 后端；
  2. 传回同一 thread_id；
  3. 节点副作用可幂等重放——恢复/Interrupt 可能使节点从开头重执行。

4. Store：跨 thread 长时记忆

Store 存任意 JSON 可序列化数据；节点通过 Runtime 访问（与 LangChain Tool 的 context 同族思想）。

与 Agent 三 · Memory 分层 对齐：Checkpointer ≈ Trace/Context 会话态；Store ≈ 外部长期记忆的一种实现。

Store ≠ VectorStore：Store 的主职责是跨线程持久化任意 KV；可配置语义索引，但不要把它与 RAG 文档向量库直接等同。

Subgraph 与父图 checkpoint 命名空间交互见六。

5. context_schema 与 per-run 配置

context_schema：每次 invoke 传入的运行时配置（user_id、租户、API 密钥引用等），不进 state 快照的业务字段 可放这里。

区分：

  • thread_id：哪条会话/checkpoint 链
  • context：本次运行的环境参数

5.1 Runtime 对象能读什么

节点函数可注入 Runtime[Context]（或通过 execution_info 读执行元数据）：

访问路径 读什么 典型用途
runtime.context context_schema 注入的 per-run 值（user_id、租户） 命名 Store namespace、权限
runtime.store 跨 thread 长期 KV 用户偏好、共享事实
stream writer 自定义进度事件 UI 进度条（stream_mode="custom"）
execution_info.node_attempt 当前节点重试次数 节点级重试与告警

Store 读写示例见 §4；execution_info 详见（四）。

5.2 何时需要 Checkpointer 还是 Store

场景 Checkpointer Store
同一对话继续 必需 非必需
Interrupt / Time Travel 必需 非必需
换新 thread 仍记住用户偏好 非必需 必需
会话状态 + 跨会话事实 两者都用 两者都用

总结

两分法：Checkpointer（thread 内）+ Store（跨 thread）。

thread_id：会话/checkpoint 指针。

恢复：durable execution 依赖持久化 checkpointer。

Store：长期 KV；Runtime 读写。

context_schema：per-run 配置，与 thread 分离。
