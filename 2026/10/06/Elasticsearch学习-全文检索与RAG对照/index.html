Elasticsearch学习-全文检索与RAG对照

发表于 2026-08-07 更新于 2026-08-20 分类于 计算机
ES 定位与倒排、mapping/分析器认名、查询与聚合边界；与向量检索/Hybrid RAG 对照及生产注意点。

RAG Hybrid 常提到「关键词一路」。本篇收 Elasticsearch（及同类全文引擎）工程认名，并与向量检索对照，避免和「唯一知识库」混为一谈。

0. 本篇位置与边界

做 不做
倒排、mapping、查询类型认名 ES 源码 / 每版 Breaking Change 清单
与向量库、RAG Hybrid 对照 某云 OpenSearch 控制台教程
索引生命周期与租户意识 ELK 日志全家桶运维

回链： RAG 二 Hybrid · RAG 五 · Redis 搜索边界 · 对象存储

口径：叙述以 Elasticsearch 8.x 心智 为主；OpenSearch 等同理。

1. 是什么

Elasticsearch = 分布式 全文检索 引擎（兼文档存储与聚合）。核心是 倒排索引：词 → 含该词的文档列表。

需求 更合适
关键词、相关性、分面聚合 ES
语义相似、embedding 向量库（或 ES dense_vector）
事务权威、强一致行锁 关系库
精确 KV、缓存 Redis

RAG Hybrid：向量一路 + 关键词一路（常 ES/OpenSearch）→ 融合 → 可选 Rerank——见 RAG（二）。

2. 核心抽象

概念 含义
Index 一类文档的集合（类比表，但不等于表）
Document JSON 文档
Mapping 字段类型与分析器；宜显式，少靠动态猜
Analyzer 分词/过滤（标准、IK 等中文方案认名）
Shard / Replica 分布式切片与副本

注意点： mapping 一旦有数据，改类型常需 reindex；text vs keyword 分清（全文 vs 精确聚合/过滤）。

2.1 text / keyword / 中文分词

类型 用途
text 分词后全文检索（match）
keyword 精确过滤、聚合、排序；tenant_id、source_id 常用
多字段 同一内容 text + keyword 子字段

中文：标准 analyzer 对中文不友好；生产常上 IK 等插件（认名）或云厂商分词。换分词 ≈ 映射变更 → 常需 reindex + 别名切换。

3. 查询认名

类型 用途
match / multi_match 全文检索
term / terms 精确（keyword、ID）
bool must/filter/should 组合；filter 不参与打分、可缓存
range 时间/数值
聚合 aggs 统计、分面；非事务报表替代品

多租户：filter: { term: { tenant_id } } 检索前硬闸——与 RAG/鉴权同口径。

导出类任务走 scroll/异步作业，勿在线深翻。

3.2 refresh 与可见性

非 MySQL「提交即读」；和 RAG Ingestion 对账时要承认窗口。

4. 与向量 / RAG 对照

ES 关键词 向量检索
强项 专名、编号、布尔组合 同义、语义相近
弱项 换说法易漏 专名/精确 ID 不稳
运维 分词、mapping、堆内存 embedding 模型与维度

文档正文可在 OSS；ES 存可检索字段与 source_id 指针——见 对象存储 · RAG 五。

5. 生产注意点

点 口径
近实时 写入到可搜有 refresh 间隔；非 MySQL 提交即读
堆与 circuit breaker 大聚合/深分页打爆堆
深分页 避免巨大 from；用 search_after
索引生命周期 ILM：热→温→删；对齐日志与知识库不同策略
版本与别名 重建索引用 alias 切流量（同 RAG index_version）

反模式： 把 ES 当唯一业务库做强事务；无 tenant filter 的全局搜；用 from=100000 深翻页。

5.1 运维口令认名

看：集群 status（green/yellow/red）、未分配分片、索引文档数异常。详细运维不展开；排障时与 Linux 性能（堆/IO）叠层。

颜色 决策一句
green 主分片+副本均已分配，可当健康生产基线
yellow 主分片齐、副本未全部分配；通常仍可读写，须尽快处理节点/副本配置，勿长期当「已健康」
red 有主分片未分配；不可当健康生产，优先恢复分片/节点再扩流量

6. 自检（短）

S1. text 与 keyword 如何选？

推荐回答： 要分词全文用 text；要精确过滤/聚合/排序用 keyword（或 text + keyword 多字段）。

S2. Hybrid RAG 里 ES 扮演什么？

推荐回答： 关键词召回与 filter；与向量互补；融合后可选 Rerank。见 RAG 二。

I1. 源 PDF 更新后 ES 与向量如何一致？

推荐回答： 同 source_id 增量更新/删除两边索引；别名切版本；对账任务。对齐 RAG 五。

总结

ES 擅长全文与过滤聚合；权威数据仍在 DB；RAG 中与向量组成 Hybrid，租户 filter 硬闸。
