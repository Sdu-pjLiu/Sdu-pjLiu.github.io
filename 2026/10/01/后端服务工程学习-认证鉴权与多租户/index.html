1. 认证：Session vs JWT

Session JWT（常见）
状态 服务端存会话 令牌自包含声明
吊销 删 session 即失效 需黑名单/短 TTL+刷新
适用 浏览器同站、易吊销 API、多端、无状态水平扩展

机制口述： 认证解决「你是谁」；鉴权解决「你能干什么」。JWT 须校验签名、exp、aud/iss；敏感权限变更要能失效旧令牌。

注意点： 把 JWT 当加密存储机密；超长 TTL 无刷新；声明过大塞权限全家桶难轮换。

2. JWT 刷新与吊销决策

手段 机制 适用
短 Access + Refresh Access 分钟级；Refresh 换发；Refresh 存服务端可吊销 API 默认推荐
黑名单 / 版本号 jti 或 token_version 进拒绝列表或用户表 强制下线、改密
纯长 TTL JWT 难立刻吊销 避免用于高敏

反模式： Refresh 也无状态且超长 → 失窃窗口巨大；把权限大全写进 JWT 又从不轮换。

4. RBAC 与鉴权点

层 职责
入口 无有效身份 → 401；无角色 → 403
业务 对象级：只能改自己租户的订单
Agent 工具 allowlist + 危险级 + HITL；声明中的 tenant 不可被模型改写绕过

注意点： 只做 UI 藏按钮不算鉴权；水平越权（改别人 order_id）靠数据层校验。

6. 服务间身份

方式 场景
mTLS 网格内服务身份
Client Credentials / 内部 JWT 服务账号调 API
API Key 简单内部或合作方；轮换与范围限制

传播：request_id / Trace context 跨服务；用户身份经可信头或 token 交换，防伪造内部头。

7. 与 Agent 叠层

Agent Worker 调业务写 API：

  1. 服务身份（Worker 自己的 Client Credentials / mTLS）
  2. 用户/租户上下文（来自原请求，不可被模型改写）
  3. 写路径：幂等键 + 审计 + 危险级 HITL——见 API 篇 · 一致性篇 · MCP（四）§2.1

总结

认证定身份，鉴权定权限，租户在查询前过滤；JWT 靠短 Access+可吊销 Refresh；服务间有独立身份，不借用用户 JWT 无限代理。
