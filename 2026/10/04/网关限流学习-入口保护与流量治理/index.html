网关限流学习-入口保护与流量治理

发表于 2026-08-07 更新于 2026-08-20 分类于 计算机
API 网关职责、限流算法认名、配额与多租户、与鉴权/熔断/429 契约对齐。

接 后端 API 契约 中的 429。本篇收 入口保护：网关做什么、限流怎么定、与鉴权/熔断如何叠层。

0. 本篇位置与边界

做 不做
网关职责、限流算法认名、配额维度 某一云厂商控制台逐步截图
与 429 契约、多租户、熔断对齐 WAF 规则全家桶、服务网格全功能
决策表与反模式 自研网关源码

回链： API 超时重试 · 鉴权 · Agent 熔断 · Redis 限流认名

1. 网关是什么

是什么： 南北向流量的统一入口：TLS 终结、路由、鉴权校验、限流、可观测、协议转换（可选）。

放网关 放服务内
全局/租户/IP 配额 业务级细粒度配额
统一鉴权验签 对象级 RBAC / IDOR
路由与金丝雀流量切分 领域逻辑

注意点： 网关鉴权通过 ≠ 业务鉴权完成；限流通过 ≠ 下游扛得住。

2. 限流算法认名

算法 机制 观感
固定窗口 每 N 秒计数清零 窗口边界可能双倍突发
滑动窗口 近似平滑计数 实现稍复杂
漏桶 恒定流出 平滑，突发被削
令牌桶 桶内令牌、允许有限突发 生产常见

实现常落在网关插件或 Redis（INCR/Lua）——计数器细节见 Redis 篇，本篇定 策略与位置。

2.1 本地限流 vs Redis 分布式限流

选型 适用
本地 单实例、粗防、可接受近似
Redis 多副本网关/服务；租户级硬顶

时序（Redis）：鉴权通过 → INCR/Lua 扣令牌 → 允许则路由；否则 429（失败策略：fail-open 还是 fail-closed 须产品决策，支付类常 fail-closed）。

2.2 Redis 键维度示例（多租户）

键必须带 租户/路由维度，避免全局一把锁误伤；与 §3 配额决策表对齐。

3. 配额维度与决策表

维度 示例 用途
IP / 设备 防爬、防爆破 匿名入口
用户 / API Key 按身份公平 登录后 API
租户 多租户 SaaS 防一家打爆全集群
路由 写接口更严 保护下单/支付
场景 策略
登录接口 IP + 用户双限；失败计数联动锁定
开放 API API Key 配额 + 租户日顶
Agent 回调/Webhook 独立配额，防重放风暴

返回 429 + 可选 Retry-After；错误体带稳定 code——对齐 API 篇。

3.1 产品认名：Nginx / Kong / Envoy

产品 限流认名 备注
Nginx limit_req_zone + limit_req（漏桶风格）；limit_conn 经典入口；配置在 server/location
Kong Rate Limiting / Rate Limiting Advanced 插件 API 网关插件化；可对接 Redis
Envoy local / global rate limit（常配外部 RLS） 服务网格/边车常见；全局需 rate limit service

本篇不贴厂商长配置；要求能口述：键（IP/租户/路由）+ 算法 + 超限 429 + 是否共享存储。

4. 与熔断、重试的关系

注意点： 网关后服务无超时 → 堆积；客户端无视 Retry-After 硬重试 → 雪崩；只限网关不限租户内某超级用户。

5. 观测与反模式

指标 用途
429 率 配额是否过紧/被打
按租户 QPS 吵闹邻居
限流丢弃 vs 排队时延 策略是否合理

反模式：

  1. 全站一个全局 QPS，大客户挤死小客户
  2. 限流键用可变 User-Agent
  3. 429 当 500，客户端乱重试
  4. 网关限流后业务仍无熔断，依赖故障拖垮线程池

6. 自检（短）

S1. 令牌桶与漏桶差在哪？

推荐回答： 令牌桶允许有限突发；漏桶更强调恒定流出。生产常选令牌桶兼顾体验与保护。

S2. 多租户限流最少几层？

推荐回答： 入口粗限 + 鉴权后租户/用户限 + 写路由更严；429 契约稳定。

I1. 开放平台被一家租户打满，如何改？

推荐回答： 按 API Key/tenant 独立配额；超额 429；观测分租户 QPS；必要时隔离集群或降级只读。

总结

网关管入口统一策略；限流按身份与路由分层；与鉴权、熔断、幂等重试同设计。
