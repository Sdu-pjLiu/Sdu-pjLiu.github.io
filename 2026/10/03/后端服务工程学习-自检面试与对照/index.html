后端服务工程学习-自检面试与对照

发表于 2026-08-07 更新于 2026-08-20 分类于 计算机
后端服务工程自检 S/I、面经与文档链接、checklist 与系列导航。

学完 API · 鉴权 · 可观测与 CI/CD 后，用本篇遮答验收。

0. 使用说明

  1. 先遮住「推荐回答」自述，再对照。
  2. 目标：能设计 带鉴权的幂等 API，能画出 日志-指标-追踪 与 CI 门禁。
  3. 与 Agent/一致性交叉题：口径须与 一致性篇、Agent 工程化 一致。

1. 分篇自检

1.1 API 与契约

S1. 错误体最少应有哪些字段？为何少用「全 200」？

推荐回答： code、message、request_id；可选 details。全 200 使客户端与网关无法按状态码统一重试/告警，除非历史契约写死。

S2. 幂等键如何工作？超时后如何处理？

推荐回答： 客户端传 Idempotency-Key；服务端首次执行并缓存响应，同键重放返回首次结果。超时不知成败 → 同键重试或先查询，禁止换键盲写。

S3. 超时如何层层设置？哪些可重试？

推荐回答： 客户端 < 网关 < 上游。可重试：幂等写、读、503/429；不可盲目重试非幂等 POST 与业务 4xx。指数退避加抖动。

S4. offset 分页与 cursor 如何选？

推荐回答： 小数据/跳页用 offset；大表时间线用 cursor/keyset。须有 size 上限；深 offset 慢且易跳行。

S5. 何时同步 API、何时 MQ？

推荐回答： 必须立刻知成败、短事务 → 同步；多下游、削峰、最终一致 → Outbox+MQ。见 API §6、一致性篇。

S6. gRPC 与 REST 怎么分工口述？

推荐回答： 对外常 REST；对内可 gRPC 强类型。错误码与超时鉴权两边都要有；不替代幂等与租户隔离。

S6b. 幂等表关键字段与「processing」如何处理？

推荐回答： tenant+key 唯一、request_hash、status、缓存响应、TTL。同键不同 body → 409；processing 等待或契约约定的进行中响应。见 API §2.1。

S6c. 超时后为何必须同幂等键重试？API 版本如何演进？

推荐回答： 超时不知成败，换键会双写。版本：兼容只加字段；破坏变更走 /v2 双跑再下线。见 API §3.1、§7。

1.2 鉴权与多租户

S7. Session 与 JWT 核心差异？

推荐回答： Session 服务端可立刻吊销；JWT 无状态但吊销需短 TTL/黑名单。认证≠鉴权。

S7b. Access/Refresh 与强制下线怎么做？

推荐回答： 短 Access + 可吊销 Refresh；改密抬 token_version 或黑名单 jti。见鉴权 §2。

S8. OAuth2 里 Code+PKCE 与 Client Credentials 各给谁用？

推荐回答： Code+PKCE：用户委托；Client Credentials：服务账号。勿把用户密码交给第三方 Client。

S9. RBAC 为何还要数据层校验？

推荐回答： 防 IDOR/水平越权；入口 403 不够，对象须属本 tenant/user。

S10. 多租户硬闸放在哪？

推荐回答： 查询/检索前强制 tenant_id；负例：A 读 B 应失败。与 RAG/记忆同口径。

S10b. tenant_id 能否信任请求 body？

推荐回答： 否。权威来自 JWT/Session 解析进 RequestContext；body 中的 tenant 最多作展示，查询必须用上下文。见鉴权 §5。

S11. 服务间身份常用手段？

推荐回答： mTLS、Client Credentials/内部 JWT、受限 API Key；禁止伪造可写的内部用户头。

S12. Agent 调写 API 时身份怎么叠？

推荐回答： Worker 服务身份 + 用户/租户上下文；工具危险级与 HITL；幂等键与审计不省。链 MCP 四、工程化三。

1.3 可观测与 CI/CD

S13. 日志、Metrics、Trace 各回答什么问题？

推荐回答： 日志：某次发生了什么；Metrics：整体是否变坏；Trace：慢/错在哪一跳。用 request_id/trace_id 串联。

S14. 本篇观测与 Agent 工程化（二）如何区分？

推荐回答： 本篇 = HTTP/业务服务；工程化二 = Agent Run/Token/Gate。用 run_id 关联，不互相替代。

S15. OTel 角色是什么？

推荐回答： 跨服务导出标准；Collector 进 APM。Agent 平台 Trace 仍可独立，ID 对齐即可。

S16. CI 最小门禁顺序？

推荐回答： build → test → image → staging 冒烟 → prod；测试失败不出包；镜像可回滚。

S16b. 金丝雀何时回滚？删列迁移顺序？

推荐回答： 金丝雀窗口错误率/P95 劣于基线则回滚上一 digest。删列：先发不读旧列的代码再 migrate。见可观测 §4.1–§4.2。

S17. 密钥与默认参数怎么分？

推荐回答： 密钥进 Secret/环境；timeout/retry 等非敏感默认可写代码。不进 Git。

S18. 线上 5xx 你怎么下钻？

推荐回答： request_id → 日志 → Trace → Metrics 判局部/全局 → 若有 Agent 开 run_id → 必要时回滚制品。

2. 面试题

I1. 设计带鉴权的幂等下单 API。

推荐回答： JWT/Session 取 tenant+user；RBAC 校验；Idempotency-Key；本地事务写订单；错误结构化；超时同键重试；可选 Outbox 通知下游。

I2. 画出日志-指标-追踪与一次发布门禁。

推荐回答： 结构化日志带 request_id；RED 指标告警；OTel Trace 下钻；CI：测试→镜像→staging→prod；密钥走 Secret。

I3. JWT 被盗怎么办？多租户串读怎么防？

推荐回答： 短 TTL+刷新、吊销列表、绑定设备/IP（按需）；查询前 tenant 硬闸 + 负例测试；敏感操作二次验证。

I4. 同步下单成功但积分没到，如何架构与排障？

推荐回答： 积分走最终一致 Outbox；查 outbox/MQ/消费幂等与 DLQ；对齐一致性篇，非回滚整笔订单 unless 业务要求。

I5. 设计 JWT + 多租户幂等下单，写出硬闸点。

推荐回答： Bearer 解析 tenant/sub；拒绝 body 覆盖 tenant；RBAC；Idempotency-Key 含 tenant；本地事务；超时同键重试。见 API §2、鉴权 §5。

3. Checklist（遮答过半即过）

  • 能写清错误码与幂等键行为
  • 能区分 Session/JWT/OAuth2 流
  • 能说明 tenant 硬闸与 IDOR
  • 能关联 request_id 与（可选）run_id
  • 能口述 CI：test 不过不上线
  • 能区分业务观测 vs Agent Run 观测 vs K8s 编排
