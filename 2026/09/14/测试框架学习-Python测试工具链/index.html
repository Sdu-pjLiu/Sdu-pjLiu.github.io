5. pytest-cov

5.1 用法

branch = true 打开分支覆盖，比单纯行覆盖更能发现「只走一侧 if」。

5.2 能说明 / 不能说明

能说明 不能说明
行/分支是否执行 断言是否有意义

并行（xdist）时注意 coverage 合并配置，避免报告失真。本地与 CI 的 source/omit/fail_under 应一致。

5.3 工程口径

7.1 最小示例

7.2 策略与控制

  • 常用：integers、text、lists、dictionaries、sampled_from、builds、composite
  • 组合：|、.filter()、flatmap；用 max_size 控成本
  • assume(cond)：过滤不满足前提的生成值（勿滥用导致有效例过少）
  • @settings(max_examples=200, deadline=None)：调次数与超时

失败会 shrink；用 @example 钉死反例。报告中的种子可协助复现。

7.3 何时用 / 不用

8. 叠用模板

  1. 纯逻辑： 等价类/边界 → parametrize；可选 @given。
  2. 服务编排： 注入 client → mocker 覆盖成功/超时/4xx。
  3. 覆盖率： --cov + term-missing，补错误分支。
  4. 集成： mark.integration，默认 PR 不跑。

9. 做什么 / 不做什么

工具 做 不做
pytest 发现、组织、断言、插件 替代用例设计思维
fixture 生命周期与注入 塞业务断言
cov 执行痕迹与防回退 证明正确性
mock 隔离外部依赖 mock 被测逻辑本身
Hypothesis 性质与边界搜索 未隔离的端到端

10. 常见坑

  1. 命名/__init__ 导致用例消失。
  2. 大 scope + 可变共享 → 污染。
  3. 顺序耦合；patch 路径错误。
  4. 弱断言 + 假高覆盖率。
  5. Hypothesis 性质过弱/过强；未 @example。
  6. xdist 并行未隔离。

总结

pytest 管发现与资源；cov 管痕迹；mock 管隔离；Hypothesis 管输入空间。设计方法回链基础篇。
