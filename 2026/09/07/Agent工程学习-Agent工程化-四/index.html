AI-Agent工程学习-Agent工程化(四)

发表于 2026-07-22 更新于 2026-08-20 分类于 计算机
Agent 工程化部署：FastAPI 契约、Worker Queue、Async/Batch/Serverless；Redis/Celery/PG/Docker 与 MQ 边界。

接 Agent 工程化（三）：韧性策略已定；本篇讲 如何把 Agent 接到线上——API 契约、队列、异步/批跑/Serverless，以及 Redis / Celery / PostgreSQL / Docker 分工。

0. 本篇位置

部署层把 Runtime（一）与观测/韧性（二）（三）落到进程与基础设施。框架托管（如 LangGraph Platform）与自托管二选一或组合；本篇给 自托管 canonical 口径，托管产品认名即可。

1. FastAPI Agent API

最小契约（名称可映射等价框架）：

端点 作用
POST /invoke 同步跑完或提交短任务；返回结果 + run_id
POST /stream SSE/WebSocket 流式 token / 事件
POST /resume HITL 或 interrupt 后续跑；带 thread_id + 决策载荷

请求上下文必带： 鉴权身份、tenant_id、可选 thread_id、预算提示。响应回传 run_id / 状态枚举（running / interrupted / success / partial / failed）。

原则： API 层做鉴权与配额；业务副作用仍走 Runtime allowlist 与幂等——回链（一）（三）。

HTTP 错误模型、幂等键、超时与版本演进的通用契约，见 后端服务工程 · API 与服务契约；鉴权与多租户见 认证鉴权篇。

2. Worker Queue

长任务（多步 research、批处理、等人审后继续）不宜堵在 HTTP 工作进程：

能力 说明
超时 任务级 soft/hard time limit
取消 协作式取消 + 冻结写工具
并发上限 按租户/全局限制，防打爆模型配额
重试 与（三）分类一致；写任务依赖幂等键

2.1 与消息队列工程口径对照

Agent Worker Queue 与 消息队列基础 同一套语义，勿各说一套：

MQ 概念 Agent Worker 落地
至少一次投递 任务可能重复执行 → 写工具 / 业务副作用必须幂等
死信（DLQ） 毒任务（坏参数、持续失败）进 DLQ，人工修复后再投
Outbox 「DB 事务成功 + 入队」用 Outbox，避免只落库未入队或只入队未落库
可见性超时 Worker 崩溃后任务重新可见；勿假设「正在跑就不会再投」

长任务上队列的原因：HTTP 超时、进程重启、HITL 等待——状态在 Checkpointer，任务在队列，二者用 run_id/job_id 关联。

3. Async Execution

模式 适用
同步 invoke 低延迟、短环、可接受阻塞
流式 对话体验；注意中断边界（三）§7
异步 job 长任务；客户端轮询或 webhook
背压 队列深度告警；拒绝或降级新请求

4. Batch Agent

离线批跑（日更报告、全量重评）：

  1. 限速（QPS / 并发）对齐供应商配额
  2. 每条样本独立 run_id；失败进 DLQ 不阻断整批
  3. 断点续跑：进度表或 Checkpoint，勿整批重来
  4. 成本单独账本，避免与在线流量混报

5. Serverless Agent

约束 对策
冷启动 减小依赖；预热；或改常驻 Worker
执行时限 长图改队列；状态外置 Checkpointer
无本地盘假设 材料进对象存储 / FS 抽象
连接复用 谨慎管理 DB/Redis 连接池

适合突发短任务；重 Multi-Agent 长跑优先常驻 Worker。

6. 技术栈职责

组件 职责
Redis Broker、缓存、分布式锁、Pub/Sub（跨服务事件）
Celery（或同类） 异步任务执行、定时、重试钩子
PostgreSQL 业务数据、Checkpointer 生产存储、审计
Docker 可复现运行时；配置与密钥经环境注入

Checkpoint 选型： 开发可用 SQLite/内存；生产优先 PostgreSQL（或框架官方推荐的持久后端）；Redis 更适缓存与队列，不宜作为唯一权威会话库（除非明确短 TTL 场景）。

密钥： API Key / DB URL 仅进环境或密钥管理；默认参数与业务常量写代码——对齐项目配置规范。正文不写真实密钥。

7. 图内 Event Bus vs 生产 MQ

图内 / Flow 事件 跨服务 MQ
示例 CrewAI @listen、LangGraph 边 Redis Pub/Sub、Celery、Kafka
范围 单应用进程/部署单元内编排 多服务解耦
须注意 不等于生产总线 幂等消费、顺序、死信、分区键

回链 Multi-Agent（四）Event Bus：Flow 事件驱动步骤；跨服务须显式 MQ，并按（三）做幂等与 DLQ。

8. 健康检查与发布

项 说明
liveness 进程存活
readiness DB/Redis/模型凭据可达后再接流量
滚动发布 先排空队列再杀 Worker；interrupt 中会话依赖外置 Checkpoint

托管平台（LangSmith Deployment 等）可替代部分运维面；能力对照见 实现框架对比。

总结

API： invoke / stream / resume + 鉴权租户 + run_id。

长任务： 队列 + Worker；取消、超时、并发上限。

Batch / Serverless： 限速续跑；状态外置；冷启动与时限清醒。

栈： Redis 管消息与缓存，Celery 跑任务，PG 管权威状态，Docker 固化环境。

事件： 图内编排 ≠ 跨服务总线。
