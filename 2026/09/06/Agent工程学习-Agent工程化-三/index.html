AI-Agent工程学习-Agent工程化(三)

发表于 2026-07-22 更新于 2026-08-20 分类于 计算机
Agent 工程化韧性：Retry / Fallback / Timeout / Circuit Breaker / Idempotency；流式边界与 DLQ。

接 Agent 工程化（二）：能观测之后，本篇讲故障时 如何不把系统拖垮——重试、降级、超时、熔断与幂等。

系列导航： （一） · （二） · （三）本篇 · （四） · 自检

0. 本篇位置

韧性策略挂在 Runtime 统一入口（模型客户端、Tool executor、队列消费者），不要只写在 Prompt 里。概念回链 LLM（四）调用韧性；本篇固化生产决策表。

1. 可重试 vs 不可重试

类别 示例 动作
可重试 429（尊 Retry-After）、网络超时、部分 5xx 指数退避 + 抖动 + 最大次数 + 总时限
不可原样重试 401/403、请求 Schema 错误、业务规则拒绝 修正、换策略或停止上报
条件重试 工具空结果、限流 改 query / 换 Worker / 降级，非盲目同参重打

Middleware 侧：ModelRetry / ToolRetry——回链 LangChain（六）。错误须结构化写回 ToolMessage，禁止吞错当空成功。

2. Retry Strategy

要点： 尊重 Retry-After；设置最大次数与墙钟总时限；大量实例失败时用抖动防惊群。

3. Fallback Strategy

层级 示例
换模型 主力超时 → 备用更快/更便宜模型
缩 scope 减 Voting N、减并行 Worker、缩短检索 top-k
只读降级 禁止写工具，仅返检索摘要 + 说明
HITL 高风险或多次失败后人工接管
明确失败 返回 partial + handoff，不假完成

Fallback 路径须进 Trace，并计入 Cost（降级也可能产生 token）。

4. Timeout Handling

层 作用
单工具超时 防单个 HTTP/DB 挂死
单模型调用超时 防生成卡死
墙钟总超时 整次 run 上限
步数 / Token 硬顶 与 LE Budget 对齐

超时后：冻结新副作用 → Checkpoint → 状态 timeout / partial，而非静默截断当成功。

5. Circuit Breaker

状态 行为
closed 正常调用下游
open 短时拒绝，直接 Fallback，避免打爆故障依赖
half-open 探测少量请求，成功则关闭熔断

适用：模型供应商、检索集群、外部 MCP Server 连续失败。与 Metrics 错误率告警联动——见（二）。

6. Idempotency

写操作（下单、改价、发邮件、扣费）重试前必须：

  1. 幂等键（invocation_id 或业务幂等键）
  2. 状态查询（是否已成功）
  3. 必要时补偿（撤销/冲正顺序明确）

读操作重试相对安全；流式已向用户吐出部分内容时，重试须避免重复拼接——见 §7。

Reducer 只合并图内 state，不保护图外副作用——回链 LangGraph（二）、Multi-Agent 自检。

6.1 写工具：权限、审计与业务幂等

维度 要求
权限分级 只读自动；写库/发消息需确认或 allowlist；资金类默认 HITL——对齐 MCP（四） 与 Agent（六）三档
审计日志 谁（tenant/user）、何时、何工具、何参数摘要、invocation_id、结果码；可追溯但脱敏
业务幂等 业务表以幂等键唯一约束；重试先查再写；与 MQ Outbox 同口径

跨服务「写库 + 发消息 + 改缓存」的一致性取舍，详见 分布式一致性学习；队列侧至少一次与死信见 消息队列基础 与本系列（四）。

注意点： Prompt「请谨慎写入」≠ 权限；无审计则事故无法追责；幂等键仅存在内存 → 进程重启双写。

7. 流式中断与 DLQ

场景 处理
流式中断 记录已发送字节/片段边界；续传或向用户声明截断；勿无完整重试覆盖已展示内容
毒消息 队列消费连续失败 → 进 DLQ，人工或专用修复任务处理
部分失败 多写工具已成功子集记入副作用表；补偿按依赖逆序

Event Bus / Celery 消费须幂等——展开见 工程化（四）。

总结

先分类再重试；不可重试不硬撞。

Fallback 有层级：换模型 → 缩 scope → 只读 → HITL → 明确失败。

Timeout 分层；超时走收尾而非假完成。

熔断 保护下游；幂等 保护写路径。

流式与 DLQ 是生产高频缺口，须显式设计。
