Redis学习-自检面试与对照

发表于 2026-08-05 更新于 2026-08-20 分类于 计算机
Redis 阶段自检与面试导向问答；含类型/高可用/缓存问题对照、实践 checklist 与面经参考。

完成 数据结构与核心机制 与 持久化高可用与缓存工程 后，重点不是背命令，而是能讲清为何快、类型选型、过期与淘汰、复制时序与 HA 决策、缓存三大问题与一致性窗口、锁与预热降级。本篇用自检题验收，再用公开面经高频点训练表达。

0. 使用说明

建议先遮住「推荐回答」，在 60～120 秒内口述：

  1. 先给结论（用哪种类型/HA/是否上缓存）。
  2. 讲机制（单线程执行、槽、RDB fork、旁路缓存）。
  3. 点风险（大 Key、穿透击穿雪崩、锁无过期、复制延迟）。
  4. 落到工程措施（TTL 抖动、SCAN、删缓存、监控、选型表）。

1. 学习自检

1.1 核心机制与数据结构

S1. Redis 为什么快？「单线程」还可能阻塞吗？

推荐回答： 内存、单线程执行命令避免锁竞争、IO 多路复用。6+ 可有 IO 线程加速网络，但命令仍主线程串行。慢命令、大 Key、fork 仍会堵住后续请求——单线程 ≠ 不会卡。

S2. 缓存对象用 String 整包还是 Hash？如何选？

推荐回答： 总是整读整写、结构简单 → String（JSON 等）。多字段局部更新、避免反复序列化整包 → Hash。字段极多慎用 HGETALL。

S3. List 适合做可靠消息队列吗？

推荐回答： 适合简易队列/时间线，但缺完善确认、重试与堆积运维语义。可靠投递优先专业 MQ；Stream 更强仍非完整 MQ 产品，要自管边界。

S4. ZSet 底层为何常提跳表？典型场景？

推荐回答： 常与字典配合：字典 O(1) 查成员 score，跳表支持按序区间/排名。场景：排行榜、按时间分排序。注意裁剪，防无限涨。

S5. 过期删除与内存淘汰有何区别？

推荐回答： 过期是键 TTL 到点删除（惰性+定期）。淘汰是触及 maxmemory 按策略腾空间。面试勿混；缓存实例通常设上限 + LRU/LFU 类策略。

S6. 为什么生产禁用 KEYS？用什么替代？

推荐回答： KEYS 一次扫描全库易阻塞。用 SCAN 游标渐进迭代；删大 Key 考虑分批或 UNLINK。

S7. MULTI/EXEC 是 ACID 事务吗？Pipeline 呢？

推荐回答： MULTI 只是排队后连续执行，无回滚，失败不撤销已成功命令。Pipeline 降 RTT，不原子。要服务端原子逻辑常用 Lua；集群还受同槽限制。

S8. 举三条大 Key / 热 Key 的影响或治理。

推荐回答： 大 Key：阻塞、复制与持久化变重。热 Key：单点打满。治理：拆分、本地缓存、限流、监控 MEMORY USAGE/延迟、禁止危险命令。

1.2 持久化与高可用

S9. RDB 与 AOF 怎么选？混合持久化解决什么？

推荐回答： RDB 恢复快、窗口内可能丢；AOF 更耐久、文件大。everysec 常见折中。混合（4.0+）重写时用 RDB 前缀加速恢复并保留增量。纯可重建缓存可弱化持久化。

S10. 主从复制是同步还是异步？读写分离要注意什么？

推荐回答： 默认异步；主写成功不代表从已追上。读从可能读到旧数据；断线可能全量同步冲击主库。

S11. 哨兵解决什么？解决不了什么？

推荐回答： 监控主从并自动故障转移，适合单分片 HA。不提供数据分片；单主内存容量上限仍在。哨兵自身要多实例。

S12. Cluster 的槽、MOVED/ASK 是什么？跨 key 操作为何失败？

推荐回答： 16384 槽分布数据；MOVED 固定重定向，ASK 迁移中临时重定向。多 key 事务/Lua 需同槽（可用 hash tag），否则失败。

S13. 哨兵、Cluster、云托管如何选型？

推荐回答： 单机装得下要自动切主 → 哨兵；容量/写要水平扩展 → Cluster；要少运维 → 托管并确认备份与多 AZ。不为「时髦」上 Cluster。

1.3 缓存工程与锁

S14. 口述 Cache-Aside 读写路径。

推荐回答： 读：先缓存，未命中读 DB 再回填 TTL。写：先写 DB，再删（或更新）缓存。缓存挂了仍可回源（需防击穿雪崩）。

S15. 穿透、击穿、雪崩一眼区分并各给一手段。

推荐回答： 穿透=查不存在；击穿=热点过期；雪崩=大量同时过期或缓存挂。手段：空值/布隆；互斥或逻辑过期；TTL 抖动 + HA/限流。

S16. 为何常「先更 DB 再删缓存」？能强一致吗？

推荐回答： 让下次读回源，避免长期脏缓存；删失败要补偿。仍是最终一致；跨 Redis 与 DB 的强一致不能靠缓存神话。

S17. 分布式锁最小正确要素？常见错法？

推荐回答： SET NX EX + 唯一 token；释放用 Lua 校验 token 再删；可续期。错：无过期、乱删他人锁、持锁超时无续期、当事务用。

S18. 布隆过滤器用于防穿透时要注意什么？

推荐回答： 有误判率，只能拦截「一定不存在」倾向的流量，不能当精确存在证明；容量与误差要按基数设计。

S19. 生产上你会盯哪些 Redis 指标？

推荐回答： 命中率、延迟 P99、连接数、ops、内存与碎片、复制偏移/积压、慢日志、拒绝/驱逐次数；变更后看是否回归。

S20. 纯缓存实例与「当小数据库」在持久化上有何不同口径？

推荐回答： 可重建缓存可弱持久化甚至关 AOF，靠 DB 托底。会话/关键状态丢不起则 AOF/混合 + 备份演练 + HA，并接受内存成本。

S21. 口述主从全量同步与部分同步的差别；backlog 太小会怎样？

推荐回答： 全量：快照 + 期间增量再追上，成本高。部分：断线后用 offset 从 backlog 补缺。backlog 不够就反复全量，打满主库与网络。见 第 2 篇 §4。

S22. Cluster 客户端遇到 MOVED 与 ASK 应如何处理？hash tag 做什么？

推荐回答： MOVED：更新槽表后重发。ASK：迁移中临时跟一次（常配合 ASKING）。{tag} 让相关 key 同槽以便事务/Lua；滥用会导致槽倾斜。

S23. 画一下「先更 DB 再删缓存」仍可能脏的并发窗口。

推荐回答： 读未命中→读到旧 DB→写已更新 DB 并删缓存→读又把旧值回填。延迟双删/互斥重建缩小窗口；TTL 托底；非强一致。见 §9。

S24. 生产上预热与降级开关解决什么？

推荐回答： 预热降低冷启动/大促击穿；降级在 Redis 异常时短路缓存并限流回源，保证核心链路存活。多级缓存削热 Key。见 §12。

2. 面试真题

以下题目按主题归纳、改写自公开面经与题库，用于训练表达，并非逐题对应某一场真实面试；综合参考来源见文末「参考面经与题库」。

I1. 一分钟介绍 Redis 及其常见使用场景。

推荐回答： 内存键值存储，可选持久化；常用缓存、会话、排行、限流、锁协调。快在内存与单线程执行模型；要用对类型、TTL 与容量治理。

I2. Redis 五种基础类型及底层你会怎么讲？

推荐回答： String/Hash/List/Set/ZSet，各有场景。强调有紧凑编码与转换；ZSet 常提字典+跳表。特殊类型 Bitmap/HLL/Geo/Stream 点到边界。

I3. 缓存穿透、击穿、雪崩分别是什么？怎么解？

推荐回答： 按 S15 展开，各举 2 种手段，并说明监控与限流托底。强调三者易被问且易混淆。

I4. 如何保证缓存与数据库双写一致性？

推荐回答： Cache-Aside：先更 DB 再删缓存；TTL 托底；延迟双删认名。承认最终一致；强一致换方案。

I5. RDB 与 AOF 原理与优缺点？

推荐回答： RDB 快照 fork/COW，恢复快可能丢窗口数据。AOF 追加命令，按 fsync 耐久，重写缩文件。混合兼顾。按丢失容忍度选型。

I6. 主从同步过程？全量与部分复制？

推荐回答： 首次或缓冲不够走全量（快照+增量）；否则 PSYNC 部分补齐。异步复制有延迟；全量对主压力大。

I7. 哨兵如何判断故障并选主？

推荐回答： 主观下线到客观下线（法定人数）→ 选举领导者哨兵 → 选从晋升 → 改拓扑通知客户端。适合单分片 HA。

I8. Redis Cluster 如何分片？客户端如何找到 key？

推荐回答： 16384 槽；客户端算槽，遇 MOVED/ASK 重定向并缓存槽图。扩缩容迁槽。多 key 需同槽。

I9. 如何实现分布式锁？Redisson 有何增强？

推荐回答： SET NX EX + token + Lua 释放。Redisson 等提供续期/可重入。红锁争议点到。锁≠事务。

I10. 什么是大 Key？如何发现与处理？

推荐回答： 体积或元素过多导致阻塞与运维风险。MEMORY USAGE、慢日志、厂商诊断。拆分、UNLINK、避开 KEYS、控制高峰操作。

I11. Redis 为何用跳表实现有序集合（而不是只说平衡树）？

推荐回答： 跳表实现相对简单、区间查找友好、局部性好；与字典配合满足成员查询与排序需求。面试答到「字典+跳表、编码可转换」即可。

I12. 内存满了会怎样？淘汰策略怎么选？

推荐回答： 看 maxmemory-policy：noeviction 写失败；缓存常用 allkeys-lru/lfu。永久键配 volatile-* 可能永不淘汰。要设上限。

I13. Pipeline、事务、Lua 怎么选？

推荐回答： 降 RTT 用 Pipeline；要连续执行用 MULTI（仍非回滚事务）；要原子判断+写用 Lua。Cluster 注意同槽。

I14. 如果 Redis 挂了，你的系统会怎样？架构上如何兜底？

推荐回答： 纯缓存应可回源并限流防击穿雪崩；关键状态要持久化+HA（哨兵/Cluster/托管）与降级开关。监控与演练 failover。

I15. 详细讲一次主从全量复制过程，以及为什么要有部分复制。

推荐回答： 按 S21/§4 时序讲：PSYNC 判定→BGSAVE→传 RDB→补增量→持续传播。部分复制避免短断线就全量；调 backlog。异步导致读写分离延迟。

I16. 如何讲清缓存与 DB 双写仍可能不一致？你会怎么工程兜底？

推荐回答： 用并发回填脏窗口举例；先更 DB 再删缓存；删失败补偿；延迟双删/短锁；TTL；不强行承诺强一致。

I17. ACL、危险命令、公网暴露你怎么说安全基线？

推荐回答： 私网；ACL 最小权限；rename/禁用 FLUSHALL 等；强密码/TLS 按需；监控异常命令。见第 1 篇 §11。

3. 对照与实践清单

3.1 类型与场景

类型 场景 避开
String 整对象缓存、计数、NX 锁 无 TTL 巨型 blob
Hash 对象字段 盲目 HGETALL 超大 Hash
List 时间线、简易队列 可靠 MQ 神话
Set / ZSet 去重、排行 只增不裁
特殊类型 UV/签到/Geo/流 边界不清

3.2 高可用形态

形态 关键词
单机 开发
主从+哨兵 单分片自动切主
Cluster 槽分片 + 分片 HA
托管 少运维，读 SLA/备份

3.3 缓存问题对照

问题 关键词
穿透 不存在、空值/布隆
击穿 热点过期、互斥/逻辑过期
雪崩 同时过期/缓存挂、抖动+HA

  • 口述 Cache-Aside 读写与「先更 DB 再删缓存」
  • 口述穿透/击穿/雪崩各一手段
  • 口述哨兵 vs Cluster vs 托管选型一句
  • 写出 SET NX EX + token 解锁思路
  • 能口述全量 vs 部分复制；MOVED vs ASK
  • 能讲清双写脏窗口与延迟双删定位
  • 过一遍生产上线检查清单（第 2 篇 §11）
  • 自检 S 题过半遮答通过（含 S21–S24 至少两题）；I 题至少练 5 题口述
