容器编排学习-自检面试与对照

发表于 2026-08-04 更新于 2026-08-20 分类于 计算机
Docker 与 Kubernetes 阶段自检与面试导向问答；含对照表、实践 checklist 与面经参考。

完成 Docker 与 Kubernetes 后，重点不是背命令，而是能讲清镜像与编排边界、探针与流量、资源与排障，以及有状态/HPA/PDB 与生产变更习惯。本篇用自检题验收，再用公开面经高频点训练表达，并给出对照与 checklist。

0. 使用说明

建议先遮住「推荐回答」，在 60～120 秒内口述：

  1. 先给结论（用 Docker 还是上 K8s；用哪种探针/Service）。
  2. 讲机制（分层缓存、控制器调谐、选择器）。
  3. 点风险（密钥进镜像、liveness 过严、latest 漂移）。
  4. 落到工程措施（digest、readiness、requests、RBAC）。

1. 学习自检

1.1 Docker

S1. 容器和虚拟机的核心差别是什么？

推荐回答： 虚拟机虚拟硬件并带 Guest OS；容器共享宿主机内核，用命名空间隔离、cgroup 限资源，更轻更快。容器不是更小的 VM，而是受限的进程树包装。

S2. 镜像为什么分层？构建时如何利用缓存？

推荐回答： 每层只读叠加，共享基础层省空间；构建按指令生成层，未变前缀可命中缓存。稳定依赖安装靠前，常变源码 COPY 靠后；合理合并 RUN、用 .dockerignore。

S3. CMD 与 ENTRYPOINT 如何分工？K8s 里对应什么？

推荐回答： ENTRYPOINT 偏固定入口，CMD 偏默认参数；推荐 exec 形式利于信号。K8s 中 command≈ENTRYPOINT，args≈CMD；只设其一或同时设置时覆盖规则不同，需按官方表理解。

S4. 为什么数据库数据不能只写容器可写层？Volume 怎么选？

推荐回答： 容器删则可写层丢。具名 Volume 由 Docker 管，适合持久；bind 适合开发挂代码；tmpfs 适合敏感临时。生产持久优先 Volume 或外部存储。

S5. bridge 网络里如何服务发现？为什么不要写死容器 IP？

推荐回答： 同自定义网络可用容器名 DNS。IP 会随重建变化；编排侧用 Service 名。端口用 -p 或编排暴露，容器内监听 0.0.0.0。

S6. Compose 解决什么？和 K8s 边界在哪？

推荐回答： Compose 用 YAML 声明单机多服务依赖、网络与卷，适合开发/单机。多机弹性、自愈、滚动、统一策略用 K8s。不要把 Compose 当集群编排替代品。

S7. 举三条镜像安全基线。

推荐回答： 非 root；密钥不进镜像与构建上下文；最小基础镜像 + 扫描认名；避免 latest 不可复现。

1.2 Kubernetes

S8. 为什么需要 K8s，而不只 docker run？

推荐回答： 多机下要声明副本、故障自愈、滚动发布、服务发现与统一配置。用户设期望状态，控制面调谐；不是登录节点手搓进程。

S9. Pod 与容器关系？为何生产少用裸 Pod？

推荐回答： Pod 是调度原子，可含多紧密容器，共享网络与卷。裸 Pod 无控制器重建策略；应用用 Deployment 管模板与副本。

S10. liveness / readiness / startup 各干什么？配错有何后果？

推荐回答： readiness 失败摘流量；liveness 失败重启；startup 保护慢启动并暂缓其它探针。liveness 过严 → CrashLoop；无 readiness → 未就绪已接流量。

S11. Deployment 滚动更新如何尽量不中断？回滚命令？

推荐回答： 逐步替换，配合 readiness；控制 maxUnavailable/maxSurge（点到即可）。kubectl rollout undo deploy/<name>；先 rollout status 观察。

S12. ClusterIP / NodePort / LoadBalancer 怎么选？

推荐回答： 集群内默认 ClusterIP；临时从节点端口调试可用 NodePort；云上对外 LB 用 LoadBalancer。本地 kind 常用 port-forward 或额外 Ingress 方案。

S13. request 与 limit 差别？只设 limit 有何问题？

推荐回答： request 影响调度与保证；limit 是上限（内存超常 OOMKill）。乱设或不设会导致调度失败或互相挤兑；应填合理 request，limit 按容量。

S14. ConfigMap 与 Secret 差别？Secret 是否等于加密？

推荐回答： 都是配置注入；Secret 面向敏感数据，默认多为 base64 而非加密。需 RBAC、静态加密与最小权限；仍勿把密钥打进镜像。

S15. 容器 Namespace 隔离了什么？为什么说「有容器≠安全」？

推荐回答： Namespace 隔离进程/网络等视图，cgroup 限资源，但共享宿主机内核。内核漏洞与错误配置仍可影响宿主；还需非 root、最小镜像、能力收敛。见 Docker §1。

S16. Compose 的 depends_on 是否保证依赖应用已就绪？

推荐回答： 默认只保证依赖 容器已启动，不保证监听与业务可用。即使用 service_healthy，也只是健康检查通过，仍可能有业务级竞态。K8s 用 readiness 摘流量更贴近「可服务」。

S17. 用一句话说清 K8s「调谐」；和 docker run 心智差在哪？

推荐回答： 控制器持续把 actual 拉向 desired（最终一致）。你改的是 API 期望，不是登录节点保活进程；副本丢失会再拉起，滚动中短暂不一致是常态。

S18. Docker ENTRYPOINT/CMD 与 K8s command/args 如何对应？删 PVC 要注意什么？

推荐回答： command≈ENTRYPOINT，args≈CMD，覆盖规则与镜像默认值组合有关。删 PVC 是否删底层数据取决于 reclaimPolicy 与存储实现，删前必须确认，避免当「只删声明」。

S19. StatefulSet 相对 Deployment 多解决了什么？生产上库为何常选托管/Operator？

推荐回答： 稳定 DNS 身份、有序启停、按 ordinal 的 PVC。多副本≠数据库高可用；自建要备份演练与成员管理。托管或 Operator 把 failover/备份流水线产品化，手写 STS 适合简单或已有剧本场景。见 K8s §13。

S20. Ingress 资源有了是否就一定能从外网访问？NetworkPolicy 默认怎样？

推荐回答： 必须有 Ingress Controller 实现转发；对象本身不产生数据面。无 NetworkPolicy 时多数集群 Pod 互通；写了策略后按白名单，还常要放行 DNS/Ingress。见 §14。

S21. HPA 与 PDB 各解决什么？和 readiness 怎么配合？

推荐回答： HPA 按指标调副本，依赖 metrics 与合理 requests；PDB 限制自愿中断时的不可用数，保护 drain/部分发布。readiness 决定谁进 Service；三者一起才谈得上弹性且不抽干。见 §15。

S22. 生产变更你会坚持哪些操作习惯？

推荐回答： 清单进 Git、apply 前 diff/dry-run、镜像用不可变引用、rollout status 观察、可 undo；节点维护 cordon+drain 并尊重 PDB；有状态先备份。etcd/控制面要有备份与 HA 意识。见 §16。

2. 面试真题

以下题目按主题归纳、改写自公开面经与题库，用于训练表达，并非逐题对应某一场真实面试；综合参考来源见文末「参考面经与题库」。

I1. 用一分钟讲清 Docker 镜像、容器、仓库。

推荐回答： 镜像是分层只读模板；容器是镜像加可写层的运行实例；仓库负责存储分发。一次构建多处运行，解决环境漂移；持久数据走卷，不依赖可写层。

I2. 如何优化 Dockerfile？

推荐回答： 小基础镜像；依赖与源码分层利用缓存；合并 RUN 并清理缓存；多阶段构建减小最终镜像；.dockerignore；固定版本 tag/digest。

I3. 容器与宿主机如何通信？常用网络模式？

推荐回答： 默认 bridge + 端口映射；host 共用宿主网络栈；自定义 bridge 上用服务名互通。选模式看隔离需求与性能，生产应用桥接+编排服务发现居多。

I4. Docker Compose 和 Kubernetes 怎么讲差异？

推荐回答： Compose 单机声明多容器；K8s 集群级期望状态、调度、自愈、滚动与丰富对象模型。开发用 Compose 快，上生产弹性用 K8s。镜像构建流程两者共享。

I5. K8s 有哪些探针？失败后分别怎样？

推荐回答： 存活失败重启容器；就绪失败移出 Endpoints 不接流量；启动探针护航慢启动。探测可用 HTTP/TCP/Exec，并配置 delay/period/threshold。

I6. 慢启动应用为何容易「无限重启」？startupProbe 解决什么？

推荐回答： 仅靠加大 liveness 延迟会拖慢故障发现；启动未完成就被 liveness 杀掉形成循环。startupProbe 成功前禁用其它探针，兼顾启动窗口与事后灵敏度。

I7. Service 如何把流量打到 Pod？

推荐回答： Service 用 label selector 关联 Pod，维护 ClusterIP 与 Endpoints；节点上 kube-proxy（iptables/ipvs 等）做转发。应用连 Service 名而非 Pod IP。

I8. Deployment、ReplicaSet、Pod 关系？

推荐回答： Deployment 声明应用期望并管理发布；它创建/更新 ReplicaSet；ReplicaSet 保证 Pod 副本数。日常操作 Deployment，滚动与回滚由其编排。

I9. 如何排查 ImagePullBackOff 与 CrashLoopBackOff？

推荐回答： ImagePull：镜像名、仓库权限、imagePullSecrets、网络。CrashLoop：logs/describe、启动命令、配置、探针、OOM。看 Events 时间线。

I10. request/limit 在调度和运行时各起什么作用？

推荐回答： 调度器按 request 找节点；kubelet 按 limit 限制。内存超 limit 常被杀；CPU 可节流。关乎稳定性与「Pending 资源不足」。

I11. 配置与密钥如何注入？有哪些注意点？

推荐回答： ConfigMap/Secret 经环境变量或卷挂载。敏感数据最小权限；更新后注意是否触发滚动；大文件用挂载；Secret 勿当保险箱神话。

I12. 从 Docker 单容器到 K8s 无状态服务，你怎么迁移心智？

推荐回答： Dockerfile 不变；run 参数变成 Pod 模板；副本与发布变 Deployment；端口映射变 Service；环境文件变 ConfigMap/Secret；单机 restart 变控制器调谐。先跑通 Deployment+Service+探针。

I13. 为什么容器内监听 127.0.0.1 时，宿主机 -p 仍可能访问失败？

推荐回答： 端口映射把流量导入容器网卡地址；若进程只绑 loopback，外部映射进不来。应监听 0.0.0.0（或明确网卡）。这是网络隔离视图下的常见坑。

I14. 声明式 apply 相对命令式 kubectl run 的工程价值？

推荐回答： 清单可进 Git、可审查、可重复 apply 幂等对齐；命令式快但易漂、难复现。生产变更统一 apply，并用 dry-run/diff 降低误操作。

I15. 有状态应用缩容或删 StatefulSet 后，数据还在吗？

推荐回答： 缩容通常保留对应 PVC；删 STS 默认不级联删 PVC。扩回去可能挂上旧盘。清数据要显式删 PVC 并确认回收策略；上线前要有备份与恢复演练。

I16. 节点要做内核升级，你怎么安全腾空？

推荐回答： cordon 停调度 → drain 驱逐（尊重 PDB、处理 DaemonSet/emptyDir）→ 维护 → uncordon。关注有状态卷能否在它节点挂载；非自愿宕机 PDB 挡不住，仍靠多副本与拓扑。

I17. 如何讲清 HPA 不生效的常见原因？

推荐回答： 无 metrics-server/指标；未设或乱设 requests 导致利用率无意义；min=max；权限或 API 版本不对。先 kubectl get hpa 看 AbleToScale/ScalingActive 与事件。

3. Docker↔K8s 对照与实践清单

3.1 对照表

概念 Docker / Compose Kubernetes

服务发现 容器名 / Compose 服务名 Service DNS

3.2 实践 checklist

Docker

  • 手写 Dockerfile 多阶段构建并 docker build 成功
  • run + 端口映射，用 logs/exec 排过一次问题
  • 具名 Volume 跑过带状态示意（如 postgres）
  • Compose 至少两服务（app + db）且能 up/down

Kubernetes（kind）

  • kind 集群可用，kubectl get nodes 正常
  • apply Deployment + Service + ConfigMap
  • 配 readiness（建议再加 liveness/startup 之一）
  • 做过一次镜像滚动与 rollout undo
  • 用 describe/Events 解释过一次失败
  • 读过/口述 STS+PVC 缩容与备份注意点（§13）
  • 能说明 Ingress 依赖 Controller；NetworkPolicy 白名单风险
  • 能说明 HPA 依赖指标与 requests；PDB 与 drain 关系
  • 练习过 diff/dry-run 与 rollout undo 话术；知 cordon/drain

口述

  • 对照表能不看稿讲过半
  • 自检 S 题过半遮答通过（含 S19–S22 至少两题）

Docker 管打包与单机运行；K8s 管期望状态与集群运维。无状态三件套 + 生产向 §13–§16 能口述，清单勾完即本系列阶段性毕业。
