0.1 Runtime 模块地图

1. State Management

维度 内容
运行态 当前步可见的 messages、todos、中间工具结果；可被摘要/丢弃策略触及
持久态 Checkpointer / @persist / 外存 FS 中的快照；跨请求可恢复
Schema 字段类型、谁可写、Reducer（append / merge / last）
可重放 interrupt / 故障恢复后节点可能从头执行 → 副作用须幂等

原则：

  1. 治理字段（Contract、预算、open[]/done[]、副作用记录、权限）进结构化 State，禁止当普通聊天消息交给摘要模型改写——回链 Agent（五）§2、LE 自检。
  2. 大材料走外存与证据指针，不把全文塞进 state 热路径——回链 Multi-Agent（四）Message Passing。
  3. 并行写同键必须声明 Reducer 或由 Coordinator 串行化——回链 LangGraph（二）。

场景片段： 研究流水线中 Research Worker 只写 {summary, evidence_refs[], status}；Writer 读指针；预算与 open[] 仅 Supervisor / Runtime 更新。

2. Session Management

不要把口语 Session 当作 LangGraph / LangChain 官方一等 API；生产会话单元用：

概念 含义
thread_id Checkpointer 内一条线程；多轮续聊、HITL resume 的主键
租户 / 用户前缀 Store namespace、业务表隔离；防串数据
会话边界 新业务目标是否新开 thread；过期策略（TTL / 归档）

回链 LangGraph（三）：Checkpointer ≈ 会话内短时；Store ≈ 跨 thread 长时。

隔离清单：

  1. 不同租户不得共用未加前缀的 Store 键
  2. resume 必须校验调用方对 thread_id 的所有权
  3. 日志与 Trace 带 thread_id + tenant_id，便于审计

2.1 记忆存储选型、隔离与遗忘

是什么： Session/记忆不是单一 Redis key；按寿命与权威性分层。

层 典型存储 内容 TTL / 遗忘
热会话 Checkpointer（PG）/ Redis 短缓存 messages、interrupt 点 会话 TTL；敏感字段可归档脱敏
业务记忆 DB 表（tenant_id 主键前缀） 用户偏好、工单上下文 业务过期策略；用户「忘记我」可删
语义记忆 向量库（带 tenant_id filter） 可检索摘要 过期重建；删除源须同步删向量

多租户硬闸： 读记忆与读 RAG 一样——filter/tenant 在查询前；resume 校验 thread_id 所有权。

决策表：

需求 选型
HITL 可恢复、权威状态 PostgreSQL Checkpointer
秒级热缓存、非唯一真相 Redis
「类似历史工单」检索 向量 + tenant filter
合规删除 各层按 user_id/thread_id 可级联清理

注意点： 向量记忆无 tenant filter → 串租户；只删 Chat 不删向量 →「忘了我」失败；无限保留全量 messages → 成本与隐私风险。

3. Lifecycle Management

状态 允许动作 禁止
running 步进、写 Trace 无预算继续
interrupted resume / cancel 静默当成功
cancelled / expired 只读审计 再触发写工具
budget_exceeded / partial 交付部分结果 + handoff 标 Success

4. Run ID / Invocation ID

ID 粒度 用途
Run ID 一次用户目标执行 关联日志、Trace、成本、告警
Invocation ID 单次工具/模型调用 幂等键、重试去重、副作用对账
thread_id 会话线程 恢复与 HITL

生产 API 响应应回传 run_id；写工具参数或业务表写入 invocation_id，避免重试双写。

5. 优雅收尾与 handoff note

撞预算、不可恢复错误、用户取消时：不得假完成。最低交付：

  1. Checkpoint（Contract、计划、open[]/done[]、关键 Observation、剩余/耗尽预算、副作用记录）
  2. handoff note（停止原因、已尝试策略、缺口、建议下一步）
  3. 面向用户的部分结果（明确边界）

回链 LE（二）优雅收尾 · LE（三）。续跑时从 Checkpoint 恢复，只处理 open[]，分配新的显式预算，不整段重放猜测。

总结

State： 运行态可压缩；治理字段进持久结构化 State；并行写要 Reducer。

Session： 以 thread_id 为单元；租户隔离与所有权校验。

Lifecycle： create→run→interrupt/resume→cancel→expire；部分成功不是 Success。

Identity： Run / Invocation / thread 三级 ID 贯穿观测与幂等。
