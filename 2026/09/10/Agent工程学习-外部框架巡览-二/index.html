AI-Agent工程学习-外部框架巡览(二)

发表于 2026-07-23 更新于 2026-08-20 分类于 计算机
外部框架巡览：Microsoft Agent Framework（MAF）为主；AutoGen/SK 沿革与 GroupChat/UserProxy 模式映射 Debate/Peer。

接 外部框架巡览（一）：OpenAI Agents SDK 偏工具环与交接；本篇巡览 Microsoft Agent Framework（MAF）——Microsoft 多 Agent / 企业编排的 现行默认入口；AutoGen 的 Conversation / UserProxy / GroupChat 作为 沿革与模式映射 保留认名。

0. 本篇位置

回链 Multi-Agent（三）Debate：历史落点常写 AutoGen GroupChat；产品线已收束到 MAF 后，模式仍可映射，选型入口以本篇为准。巡览级理解即可，不展开全 API。

permalink 未改（仍为 /2026/09/10/…），旧链可点；正文口径以 MAF 为准。

1. 为何从 AutoGen 升级到 MAF（必读）

这不是换时髦名字，而是 官方产品线与新项目默认入口已变：

事实 对学习/选型的影响
Microsoft 将 AutoGen 的多 Agent 编排 与 Semantic Kernel 的企业底座 收束为统一的 Microsoft Agent Framework（公开叙述约 2026-04 标 1.0/GA；仓库见 microsoft/agent-framework） 只学 AutoGen = 指向 已降级产品线
AutoGen / Semantic Kernel 多为 maintenance mode（修 bug/安全，无新功能主投入）；新项目文档指向 MAF + 迁移指南 按旧文选型会 选错默认 SDK
Conversation、UserProxy、GroupChat、Debate/Peer 映射仍有教学价值 保留为沿革与模式对照，挂在 MAF 下，不删光

canonical 口径：

AutoGen 代表的「对话式多 Agent」模式仍值得认名；但 2026 起 Microsoft 新项目默认入口是 MAF。本巡览以 MAF 为主，AutoGen/SK 仅作沿革与模式对照；主路径仍不换出 LangGraph / CrewAI。

为何不把主路径改成 MAF： MAF 偏 Microsoft / Azure / .NET+Python 企业栈；本课程默认实现线仍是开源可控的 LangGraph +（可选）CrewAI。

2. MAF 一句话定位

Microsoft Agent Framework： 面向生产的开源 Agent / 多 Agent 工作流 SDK（Python 与 .NET）——把原 AutoGen 侧的编排思路与 Semantic Kernel 侧的连接器、中间件、遥测等企业能力收进 同一套 API 表面；并认名支持 MCP 等工具接入（细节以当时文档为准）。

维度 口径
语言 Python、.NET（对等能力叙事）
强项 Azure/Microsoft 生态集成、企业治理组件、多 Agent 工作流
风险 栈绑定；图级可审计性与 Checkpoint 心智仍常对照 LangGraph
文档 以 Microsoft Learn / 仓库 README 为准；本篇不跟版号刷 API

3. 沿革：AutoGen 模式 → MAF 对照

下列概念来自 AutoGen 时代教学心智；在 MAF 中名称可能不同，但 问题形态 仍在。读文档时用「模式」对齐，勿死磕旧类名。

3.1 Conversation / 消息协作

维度 内容
形态 Agent 主要通过消息/轮次协作，而非显式 StateGraph 边
强项 快速搭多角色对话、原型辩论
风险 轮次爆炸、难审计、缺图级门禁时易假完成
对照 精细分支/恢复仍偏 LangGraph；MAF 工作流图能力以文档为准

3.2 UserProxy → HITL / 人类侧

维度 内容
历史含义 代理「用户侧」：转发人类输入，或代表用户执行代码/工具
价值 HITL 与本地执行的显式角色
对照 LangGraph interrupt / CrewAI @human_feedback / 工程化 resume API；MAF 侧看官方 HITL/审批原语
注意 人类代理执行写操作同样要幂等与权限——工程化（三）

3.3 GroupChat / Speaker selection

概念 口径
GroupChat 多 Agent 共享对话上下文，按策略选下一发言者
Speaker selection 规则、轮询或 LLM 选人
治理 max_rounds + 仲裁者；辩论摘要后再下游——回链 Multi-Agent Debate

无收敛协议的群聊 ≈ 无预算的 Peer/Swarm，生产慎用——在 MAF 中同样成立。

4. 映射 Debate / Peer

Multi-Agent 理论 落点（MAF / 沿革）
Debate 多角色协作 + 轮次上限 + 总结；历史常落 GroupChat
Peer 无中心发言者轮换；需冲突协议
Supervisor 「经理」选人可做；图级可审计性通常仍弱于 LangGraph Supervisor

5. 与主路径对照

需求 更合适
Azure/.NET 企业栈、要跟 Microsoft 默认 SDK 评估 MAF
快速多角色对话 模式 借鉴 MAF 文档 + 历史 GroupChat 心智
每步 Checkpoint / interrupt / Send 并行 LangGraph（本课默认）
Researcher→Writer 产品化流水线 CrewAI
长材料 Context 隔离 Deep Agents
新项目仍装「仅 AutoGen 0.4」当默认 不推荐（维护模式）

6. 注意点 / 反模式

  1. 把 AutoGen 当 2026 新项目默认入口。
  2. 以为改名 MAF 后主路径必须迁移——本课不强制。
  3. 群聊无 max_rounds / 仲裁 → 成本与假完成。
  4. UserProxy/代码执行写库无幂等——与框架无关的工程债。

总结

为何改： 产品线收束到 MAF；AutoGen/SK 维护模式；模式保留、入口更新。

MAF = Microsoft 现行 Agent/多 Agent SDK；沿革 = Conversation / UserProxy / GroupChat 认名。

主路径不变： LC / LG / DA / CrewAI。
