各节结构：是什么 → 机制 → 示例 → 注意点。

1. 容器 vs VM；隔离与分层

是什么： Docker 用镜像打包应用与依赖，用容器以进程级隔离运行。比虚拟机更轻，因为 共享宿主机内核，不跑完整 Guest OS。

机制要点：

技术 解决什么 不解决什么
Namespace 进程/网络/挂载等视图隔离 内核漏洞、同内核恶意逃逸面
cgroup CPU/内存等资源限制 「限了就一定够用」的容量规划
UnionFS / 分层 只读层叠加 + 可写层；写时复制 把可写层当数据库

镜像层只读；启动容器时在顶上加可写层。修改已有文件时，常先从只读层 复制到可写层再改（写时复制）。

示例直觉： 多个容器可共用同一基础镜像层，磁盘上只存一份底层；各自可写层独立。

注意点 / 反模式：

  1. 容器不是「迷你 VM」——不能假设内核模块、完整 systemd 与强隔离。
  2. 同宿主机、同内核：加固靠最小镜像、非 root、能力收敛，而非「有容器就安全」。
  3. 可写层短暂：删容器常丢可写层数据；持久化必须用卷（§7）。
  4. 口诀仍成立：Dockerfile 里稳定指令靠上，常变 COPY 靠下，利于缓存。

2. 核心命令与生命周期

是什么： CLI 管理「镜像 → 容器实例」的创建、观察、进入与销毁。命令是手段，关键是分清 镜像（不可变模板） 与 容器（一次运行）。

机制要点：

概念 含义
docker run 创建新容器并启动（可加 -d 后台）
docker start 启动 已存在 的停止容器
主进程 / PID1 容器内 PID1 收信号；进程退出则容器退出
exec 在已运行容器内再起进程，不替代主进程

示例：

注意点 / 反模式：

  1. 每次 run 都是新实例；配置应进镜像/编排，勿当长期手工「雪花机」。
  2. 主进程若非 PID1 或未正确转发信号，stop 可能变强杀、优雅退出失败——Dockerfile 推荐 exec 形式 ENTRYPOINT/CMD。
  3. exec 进容器调试可以，但不要依赖「手工改容器内文件」当发布方式。
  4. rmi 删镜像前需无容器引用；先 rm 容器。

3. Dockerfile

是什么： 构建镜像的声明式配方。目标是 可复现、可缓存、体积可控。

机制要点：

指令 作用
FROM 基础镜像
COPY/ADD 复制（一般优先 COPY；ADD 有解压/URL 副作用）
RUN 构建期执行
ARG 构建期参数，默认不进最终运行环境（除非再赋给 ENV）
ENV 运行期可见环境变量
EXPOSE 文档化端口，不会自动 -p 发布
CMD / ENTRYPOINT 默认进程；推荐 JSON exec 形式

CMD vs ENTRYPOINT： 仅 CMD 易被 docker run … override 整段替换；ENTRYPOINT+CMD 则入口固定、参数可覆盖。K8s 中对应关系见下篇：command≈ENTRYPOINT，args≈CMD。

  1. 构建上下文过大极慢——用 .dockerignore 排除 .git、依赖目录、.env。
  2. EXPOSE 了不等于宿主机能访问——仍需 -p 或编排暴露。

4. 镜像：tag、digest、推拉

是什么： 镜像要命名、分发、固定版本。tag 是指针，digest 是内容指纹。

机制要点：

概念 说明
tag 可变引用（latest 会漂）
digest @sha256:… 内容寻址，更可复现
registry 推拉仓库；私有仓需登录/凭证

示例：

注意点 / 反模式：

  1. 生产避免只钉 latest；用语义化版本或 git sha，关键环境可钉 digest。
  2. pull 失败先查：网络、仓库地址、认证、镜像名拼写。
  3. docker image prune / system prune 会删未用数据——先 system df，确认无误伤。
  4. 多架构镜像（manifest list）在 Apple Silicon / 混合节点上要注意平台匹配。

5. 生命周期与资源限制

是什么： 限制 CPU/内存防止单容器拖死宿主机；用 restart 策略处理进程退出。

机制要点：

项 含义
--memory 内存上限；超限常被 OOM 杀
--cpus CPU 配额（软限制直觉：争用时被节流）
--restart no / on-failure / always / unless-stopped

示例：

注意点 / 反模式：

  1. OOM 后进程被杀，若 always 重启，可能对「必崩配置」形成 重启死循环——先看 logs 修根因。
  2. 限制过小导致频繁 OOM；过大则失去保护——按压测设。
  3. 重要数据仍须 Volume，与 restart 无关。
  4. 退出码结合 ps -a 与 logs，不要只看「容器不见了」。

6. 网络

是什么： 容器默认在隔离网络命名空间；要对外服务或容器间通信，靠网络模式与端口发布。

机制要点：

模式 特点
bridge（默认） 虚拟桥；-p 宿主:容器 做端口映射（DNAT 到容器）
host 共用宿主网络栈（Linux），少一层隔离
none 无网
自定义 bridge 同网络内可用 容器名 DNS

示例：

注意点 / 反模式：

  1. 容器内若只监听 127.0.0.1，即使用 -p，宿主机也常常 访问不到——应监听 0.0.0.0（或明确网卡）。
  2. 勿写死容器 IP：重建即变；用名字或编排 Service。
  3. host 模式端口直接占宿主，隔离变弱，生产慎用。
  4. -p 只解决「进容器端口」；跨主机多机通信需要编排或覆盖网络，不是单机 bridge 默认能力。

7. 存储

是什么： 把数据从容器可写层拆出，使容器可扔、数据可留。

机制要点：

类型 特点
具名 Volume Docker 管理，适合持久数据
匿名卷 未命名，易乱，难管理
bind mount 挂宿主路径，开发方便、可移植性差
tmpfs 内存，停即丢，适合敏感临时

示例：

注意点 / 反模式：

  1. docker rm 容器 默认不删 具名卷；忘了会占盘——用 volume ls/prune 治理。
  2. 匿名卷更多来自 Dockerfile VOLUME 未显式命名——生产尽量具名。
  3. bind 依赖宿主绝对路径，换机器易挂；权限 UID 不对会 Permission denied。
  4. 备份责任在卷/外部存储，不在「容器还在」。

8. Compose

是什么： 用一份 YAML 声明多服务、网络、卷，把散装 docker run 变成 可版本管理的单机应用描述。适合开发与单机部署，不是集群编排器。

机制要点：

  • services / networks / volumes 一等公民。
  • depends_on 默认只保证 容器启动顺序，不保证「应用已可服务」。
  • condition: service_healthy 才接近「依赖健康后再启」（仍非业务级就绪的全部）。

示例： 见下（两服务 + healthcheck）。

注意点 / 反模式：

  1. 把 Compose 当成 K8s：没有多机调度、滚动自愈、声明式集群状态。
  2. 仅 depends_on: db 就以为 DB 已可连——竞态下 web 仍会启动失败。
  3. down -v 清空卷等于删库——生产/共享环境严禁随手加 -v。
  4. 密钥仍勿写进镜像；Compose 文件进 git 时注意脱敏与密钥注入方式。

9. 安全基线

是什么： 缩小攻击面与泄密面，使「能跑」变成「可上线一点」。

机制要点：

手段 作用
非 root（USER） 降低逃逸后权限面
最小镜像 少包 = 少 CVE
密钥运行时注入 避免进镜像层历史
capabilities Linux 能力集；默认能力可再 --cap-drop 收敛
seccomp 等 限制可用系统调用（运行时/编排侧配置，点到）
镜像扫描 Scout / Trivy 等认名

注意点 / 反模式：

  1. 构建时 ENV PASSWORD= 或 COPY .env → 进层历史，可被 history/导出层看到。
  2. 以 root 跑应用扩大逃逸与写宿主风险。
  3. 超大胖镜像 = 更多 CVE 面；slim/distroless + 少包。
  4. 扫描是信号不是过门金牌——要修高危与基础镜像来源。
  5. 「加 --privileged 先跑通」会把能力与设备几乎全打开，仅排障临时用，禁止当默认。

10. 排障清单

是什么： 固定观察顺序，避免无脑删容器重来。

机制要点（顺序）： ps -a → logs → inspect/events → 确认命令与端口监听 → stats/卷权限。

现象 先查
立刻退出 主进程、CMD/ENTRYPOINT、缺文件
端口不通 -p、是否听 0.0.0.0
构建怪 .dockerignore、缓存、--no-cache
盘满 docker system df；慎 prune
权限 挂载 UID

注意点 / 反模式：

  1. 不看 logs 就 rm -f 再 run——根因还在，只会浪费时间。
  2. 盲目 docker system prune -a --volumes 可能删掉未用镜像与卷数据。
  3. 用 exec 在容器里「修好」当发布完成——重建后修改全丢。
  4. 忽略 stats：CPU/内存打满时表现为「偶发超时」，易误判成网络问题。

11. 预习映射：Docker → Kubernetes

Docker / Compose Kubernetes
镜像 Pod 拉同一类镜像
docker run Pod 模板
Compose 服务/副本 Deployment
ports Service / Ingress
env ConfigMap / Secret
Volume PVC（认名）
Compose 单机 集群调度与自愈

注意： 概念近似 ≠ API 等价（例如 Compose healthcheck ≠ K8s 三种探针语义完全相同）。

总结

隔离靠 Namespace/cgroup，交付靠分层镜像，数据靠卷，多服务单机靠 Compose；密钥与 latest 是高频坑。下一篇进入声明式集群编排。
