官方：Agents · Tasks · Agent Capabilities

1. Agent：role / goal / backstory

Agent 是 角色化执行者，三要素决定行为边界：

字段 工程作用
role 身份与专业视角
goal 可指向的产出方向
backstory 风格、约束、领域习惯

关键参数：

参数 含义 回链
tools 可用 Tool 列表 LLM 四 Tool Calling
allow_delegation 是否委派给其他 Agent Hierarchical Process
max_iter / max_rpm 步数与速率上限 LE Budget
memory 启用 Memory Agent（三）
planning_config 执行前规划 Plan-and-Execute
guardrail Agent 级输出护栏 LE Gate

占位符： {topic} 等由 crew.jsonc 的 inputs 或 kickoff(inputs=...) 注入。

2. Task：description 与 expected_output

Task 是 可验收工作单元。工程上 expected_output 与 Guardrail 同等重要——模糊描述导致不可回归。

字段 作用
description 做什么（可含占位符）
expected_output 格式与质量标准
agent 负责人
context 依赖的前置 Task 名列表
tools 任务级工具（覆盖 Agent 默认）
output_json / output_pydantic 结构化输出
markdown 输出 Markdown
human_input 等人输入（Training 用）
async_execution 异步并行

3. Task Guardrails

Guardrail 在 Task 输出进入 下一 Task 或 Flow 下一步 前校验。

类型 写法 适用
Python Callable 自定义函数 确定性规则（Citation 对齐、JSON Schema）
LLM 字符串 自然语言描述 主观质量（语气、结构）
guardrails 列表 多个串行执行 先结构后语义

与现有路径对齐：

  • 对应 LE（一）验证门：无 Observation 支撑禁止 Success
  • 对应 Agent（四）§6：Citation Gate 失败 = BLOCK

4. 五类能力扩展

官方 Agent Capabilities 将扩展分为 动作类 与 认知注入类：

类型 解决什么 配置示例
Tools 本地/API 动作 tools=[SerperDevTool()]
MCPs 远程工具总线 mcps=["https://api.example.com/sse"]
Apps 预置集成 apps=["gmail"]
Skills 流程性指令 skills=["./skills/code-review"]
Knowledge RAG 事实库 knowledge_sources=[pdf_source]

执行时统一： Tools/MCP/Apps 解析为 BaseTool；Skills/Knowledge 注入 prompt 或预检索。

你需要… 选
搜网页 Tools
跨 IDE 复用 SEO Server MCPs（回链 MCP 系列）
公司政策 PDF Knowledge（回链 RAG 系列）
代码审查清单 Skills
搜网页 + 审查规范 Tools + Skills

MCP 注意： 接入不替代 Runtime 校验——仍须 allowlist、HITL、Injection 防御（Agent 六）。

5. JSONC vs 代码定义

方式 优点 适用
JSONC 声明式、易评审、CLI 脚手架默认 新项目、多角色配置
Python Agent/Task 类 灵活、动态逻辑 复杂工具装配、测试

6. 单 Agent kickoff vs Crew

方式 何时用
agent.kickoff() 探针、单步 QA、无 Process 需求
crew.kickoff() 多 Task、多 Agent、Process 编排

单 Agent 仍走 Tool Loop，但不享受 Crew 的 Task 链与 Process 管理。

7. 实践阶梯 L1

级别 做什么 证明
L1 1 Agent + 1 Task + 1 Tool；expected_output 含 Markdown 结构 Task 输出可机检

8. 常见坑

  1. role/goal 重叠 → Agent 抢活或互相推诿；应互斥、action-oriented
  2. expected_output 模糊 → 无法写 Guardrail 与 Scenario Rubric
  3. 全塞进 Crew → 简单 JSON 提取应直接 LLM.call（见三）
  4. Knowledge + 检索 Tool 重复 → 选一种主路径，避免双标准

本模块自检与面试

学完 CrewAI 系列五篇后，请到 CrewAI · 自检与面试。

总结

Agent：role/goal/backstory + tools/delegation/max_iter。

Task：description + expected_output + context 链 + 结构化输出。

Guardrail：Python 硬规则优先；对齐 LE Gate 与 Agent（四）§6。

能力：Tools/MCP/Apps 做动作；Skills/Knowledge 做认知注入。

配置：JSONC 声明式为主；单 Agent kickoff 用于探针。
