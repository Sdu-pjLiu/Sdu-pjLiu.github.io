AI-Agent工程学习-RAG(五)

发表于 2026-07-20 更新于 2026-07-23 分类于 计算机
RAG 生产：Ingestion/ACL/监控/索引运维；企业知识库 Agent 主线项目；收口至 MCP。

接 RAG（四）：概念与增强齐备之后，落地 企业生产知识库——Ingestion、权限、监控、索引运维，以及 文档 → RAG → Agent 问答 → 自动生成方案 完整项目。

0. 本篇位置

本篇 收口 RAG 系列，并给出可验收的主线项目；下一模块 MCP（一） 负责 外部能力标准接入（如 SEO、爬虫、第三方 API）。

1. Ingestion 管线

实践 说明
幂等 文档 content_hash 未变则 skip
增量 只 embed 新/changed chunk
删除 源下架 → 索引 delete by source_id
调度 cron / 事件驱动（webhook）

2. ACL 与多租户

检索 前 过滤（RAG 二 Metadata），非生成后补救：

与 PE 四 Injection 配合：检索结果仍不可信作 指令，只作 事实材料。

3. 监控与告警

指标 阈值示例
检索空结果率 突增 → 索引/embedding 异常
P95 检索延迟 超 SLO → 缩 K 或换库
Citation Gate 失败率 增 → Prompt 或 Rerank 退化
Faithfulness 抽检 周报回归

LangSmith / 自建 Trace：记录 query、hit_ids、scores、最终 citations。线上监控指标与 Agent（四）§6 RAG 域 Checklist 对齐。

4. 索引运维

事件 动作
Embedding 模型升级 新索引别名 → 双写 → 评测 → 切流量 → 删旧
Schema 变更 全量重建或 migration 脚本
回滚 保留 index_version 指针

5. 企业知识库 Agent 项目（主线）

5.1 目标

输入：企业内部 PDF/Markdown 政策与产品文档。
输出：可引用来源的问答 + 结构化方案草稿（如「上线检查清单」）。

5.2 架构

5.3 实现要点

  1. 索引：tenant_id + doc_type metadata；Hybrid 默认开，Rerank 可选。
  2. Agent：system prompt 要求先检索再答；Budget 检索 ≤3 次/会话。
  3. 方案生成：第二段 Tool 或同一 structured output 的 checklist[]，每项 item + citation。
  4. 验收：10+ 场景 Rubric——引用必须命中、禁止越权 doc、Budget 内完成；发版前按 Agent（四）§6 发版回归 Checklist 跑 Scenario 回归（含 RAG / Loop 域指标）。

5.4 代码骨架

5.5 与 Deep Agents 选型

长任务、多文件调研、Skills 流程 → 可换 Deep Agents + RAG Tool；标准 Q&A + 方案 LangChain create_agent 足够。

6. 全路径收口

RAG 系列覆盖：基础管线 → 增强 → Agentic → Graph → 生产。Harness 仍用 LangChain / LangGraph；RAG 是 Knowledge 层垂直能力。

本模块自检与面试

请到 RAG · 自检与面试。

总结

Ingestion：增量、幂等、版本化索引。

ACL：检索前 tenant/role 过滤。

监控：空结果、延迟、Citation Gate、Faithfulness。

企业项目：Hybrid 索引 + Agent Tool + 结构化方案 + LE 验收。
