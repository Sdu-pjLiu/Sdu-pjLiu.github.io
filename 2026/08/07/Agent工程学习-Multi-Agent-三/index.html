AI-Agent工程学习-Multi-Agent(三)

发表于 2026-07-18 更新于 2026-08-20 分类于 计算机
Role-Based / Debate / Voting / Swarm / Hierarchical 五协作模式；选型口诀与框架落点。

接 Multi-Agent（二）：五角色已定，本篇讲 五种协作模式——结构、适用场景、风险与 LangGraph / Deep Agents / CrewAI 落点。

0. 本篇位置

协作模式回答 「多个 Agent 如何一起完成任务」；与（二）角色、（四）通信正交组合。

回链 Agent（二）Hierarchical 规划）——高层阶段目标与 Multi-Agent Hierarchical 可叠加，但 不等同。

1. Role-Based Collaboration

维度 内容
结构 固定角色按序执行：Researcher → Analyst → Writer → Reviewer
适用 流水线明确、每步验收标准清晰、开放质量要求
风险 串行延迟；上游错误传导；角色「空壳」无独立 Tool
框架落点 CrewAI sequential Process（主战场）；LangGraph 线性子图链

场景片段： 内容运营——调研 Crew 输出带来源摘要 → 写作 Crew 成稿 → Guardrail 失败则回炉——角色固定，不按轮动态重组。

选型口诀： Researcher + Writer + Editor 流水线 → CrewAI sequential 或 LangGraph 线性子图。

2. Debate System

维度 内容
结构 多 Agent 正反或多视角辩论，经 N 轮后综合
适用 策略取舍、方案评审、风险辩驳
风险 Token 爆炸；争论不收敛；无仲裁者
框架落点 CrewAI 多 Task 迭代；MAF / AutoGen 沿革 GroupChat（巡览）；LangGraph 循环边 + 轮次上限

治理要点：

  1. max_rounds 硬上限
  2. 仲裁节点（Supervisor 或规则聚合）必须存在
  3. 辩论内容 摘要后 再进入下游，避免全文灌窗

3. Voting System

维度 内容
结构 N 路 Worker 独立产出 → 聚合节点（多数票 / 加权 / LLM judge）
适用 分类、评分、冗余校验、降低单点幻觉
风险 成本 × N；聚合规则不当仍错
框架落点 LangGraph Send 并行 + 聚合 Node；CrewAI 多 Agent 同 Task 不同 backstory（慎用）

场景片段： 同一 FAQ 问题 → 3 个 Worker 各检索回答 → Voting 节点选证据最充分者 → 无一致则 HITL。

4. Swarm Intelligence

维度 内容
结构 对等 Peer 自治，局部规则驱动，无中心 Supervisor
适用 探索型搜索、创意发散、去中心化任务
风险 难审计；冲突无解；重复探索
框架落点 LangGraph 核心 无内建 Swarm 一等 API；可用 langgraph-swarm 等 companion 或自建多 Peer 节点 + Store；行业模式名

回链 LangGraph 自检 I12：Swarm 仅当中心协调成瓶颈且冲突有协议时考虑；多数业务不必上。

5. Hierarchical Agent System

维度 内容
结构 多层 Supervisor：顶层分解 → 中层再分派 → 叶子 Worker
适用 企业多部门流程、大型 Research 项目
风险 层级过深 → 延迟与 Token 倍增；责任链断裂
框架落点 CrewAI hierarchical Process；LangGraph 嵌套 Subgraph + Supervisor

回链 Agent（二）分层规划：高层阶段目标可映射为顶层 Supervisor 的 open[]；层间须传 Handoff 合同。

场景片段： 顶层「行业报告」→ 中层 Supervisor 分行业 → 叶子 Research Worker 并行 → 中层汇总 → 顶层 Writer。

6. 协作模式选型表

需求 首选模式 首选框架
固定流水线、角色清晰 Role-Based CrewAI sequential / LangGraph 链
方案辩论、多视角 Debate MAF/历史 GroupChat 或 CrewAI 多轮 + 仲裁
分类/评分/冗余校验 Voting LangGraph Send + 聚合
探索发散、无中心 Swarm LangGraph Store 拓扑（高级）
企业多层级委派 Hierarchical CrewAI hierarchical / 嵌套 Subgraph
单次意图分流 非协作模式 Router（见（二））

7. 协作成本模型

Multi-Agent 不是免费抽象。粗算：

旋钮 作用
角色数 每多一角色多一套 System + 工具描述
轮次 Supervisor 多跳、Debate 多轮直接倍增
Voting N 近似线性 ×N；无收益时降 N 或改 Role-Based
预算硬顶 Runtime 总 Token/费用/墙钟——工程化（一）（二）

选型约束： Token 升而 Task Success 不变 → 减角色或退回单 Agent；Voting/Debate 须能证明指标收益。

总结

Role-Based： 固定流水线；CrewAI sequential 主战场。

Debate： 多轮视角；须 max_rounds + 仲裁。

Voting： N 路并行聚合；LangGraph Send。

Swarm： 对等自治；非默认；无独立 API。

Hierarchical： 多层委派；控制深度 ≤ 3 层为宜。
