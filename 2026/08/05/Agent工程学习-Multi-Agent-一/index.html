1. 何时需要 Multi-Agent

信号 说明 反例（不必拆）
角色异质 搜索员与写手工具集、Prompt、验收标准不同 同一 Tool 环 + Skill 切换即可
Context 隔离 子任务 Trace 会挤爆主窗（长 research） 单次检索 + 摘要 Middleware 够用
并行独立子任务 多源检索、多竞品可并行再聚合 串行 3 步固定 ETL
冲突消解 需辩论、投票、多路校验 单模型 + Reflection 一次
组织边界 不同团队维护不同 Agent 能力 单服务内 Middleware 即可

过早拆角色的代价：

  1. Context 丢失 — Handoff 不带 Goal / open[] / 硬规则 → 重复劳动或越权
  2. Token 膨胀 — 多环各自带完整 System Prompt
  3. 责任模糊 — 只有角色名、无独立工具/状态/验收 → 假完成
  4. 图维护成本 — 拓扑复杂度超过业务收益

默认策略（与 Agent（六）§4 一致）： 先把 单 Agent + 分层规划 + Skill 做稳，再按上表信号拆多 Agent。

2. 五角色 taxonomy 速查

角色 一句话 决策权 典型失败
Supervisor 分派子任务、验收、汇总 选下一个 Worker、是否结束 无限委派、丢硬规则
Worker 执行原子子任务 局部工具与推理 越权、假完成、错误不结构化
Coordinator 调度依赖与进度，非推理中心 并行门禁、重试路由 与 Supervisor 职责重叠
Router 分类分流到固定分支 选分支（通常一次或少数几次） 误路由、无降级
Peer 对等协商、互补 自治决策 冲突无解、重复劳动

与 LangGraph（六）对照：

LangGraph 概念 Multi-Agent 角色
conditional edge + 分类节点 Router
Supervisor 节点 Supervisor
子图 / create_agent Node Worker
Flow @listen 编排（CrewAI 预告） Coordinator
多节点 + Store 无中心（Swarm 预告） Peer

3. Harness / Orchestration Runtime 分层

回链 Agent（三）§6：

读法：

  • 角色与协作 是设计层，可用纸面或图表达，与具体框架无关
  • Harness 跑单 Agent 工具环；多 Worker 常 = 多个 Harness 实例或子图
  • Runtime 负责 durable、interrupt、Store——Multi-Agent 的 Handoff 与恢复依赖此层

总结

定位： LangGraph（六）之后的 Multi-Agent 理论 canonical；不重复 API 教程。

五角色： Supervisor / Worker / Coordinator / Router / Peer。

分层： 拓扑设计 → Harness → Orchestration Runtime。
