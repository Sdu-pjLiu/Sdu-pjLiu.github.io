AI-Agent工程学习-MCP(二)

发表于 2026-07-21 更新于 2026-07-23 分类于 计算机
MCP Server 开发：Tool Schema、Result Format、Resources、Prompts；单测与 L0 最小 Server。

接 MCP（一）：协议角色清晰之后，在 Server 侧 实现并暴露 Tools、Resources、Prompts——本篇用 Python MCP SDK 思路（以官方文档为准）。

0. 本篇位置

1. Server 项目结构

原则：Tool 函数薄——参数校验、调用 service、返回结构化 Result；复杂逻辑在 tools/ 模块。

2. Tool Schema 设计

对齐 LLM 四 Tool Calling：

字段 要求
name 稳定 snake_case；多 Server 时加前缀
description 何时用 / 何时不用
parameters JSON Schema：type、required、enum、范围

错误：返回 结构化 JSON { "error": "...", "code": "..." }，便于 Agent 修正而非堆栈字符串。

3. Result Format

类型 建议
短文本 直接 string
结构化 JSON string；字段稳定
长文本 摘要 + 指针 URI；防 Observation 撑爆（Agent 五）

Server 侧设 超时；Client 侧设 重试 区分瞬时/逻辑错误。

4. Resources

Resources 暴露 可读 URI：

read_resource(uri) 返回文本/二进制引用；适合 静态政策、配置、只读文档。
动态查询仍用 Tool（如 get_order(id)）。

5. Prompts

MCP Prompts = 参数化模板（与 PE Registry 类似）：

Agent 工程常用 Host 侧 system_prompt 为主；MCP Prompts 适合 跨 IDE 复用 的标准分析流程。

6. 单测与契约测试

测试 内容
Tool 单测 合法/非法参数、边界、超时
契约 Schema 与文档一致；breaking change 升版本
集成 stdio Client 启 Server 子进程跑 call_tool

无单测的 MCP Server 不宜接生产 Agent。

7. L0：最小 Server

目标： echo_tool + policy_resource 联通。

验收：list_tools 可见 1 tool；read_resource 可读 1 URI；call_tool 返回预期字符串。

本模块自检与面试

请到 MCP · 自检与面试。

总结

Server：薄 Tool + 清晰 Schema + 结构化错误。

Resources：只读 URI；Prompts：参数化模板。

测试：单测 + stdio 集成。

下一篇：MCP（三）· Client 与 Agent 框架集成。
