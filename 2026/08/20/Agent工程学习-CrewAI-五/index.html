官方：Human Feedback in Flows · Training · Production Architecture

1. Human-in-the-Loop（Flow 层）

@human_feedback 在 Flow 方法上暂停执行，展示输出供人审，并可 路由 到不同后续步骤。

要点：

  • 有 emit 时，LLM 将自由文本反馈 折叠为路由标签
  • needs_revision + @listen(or_(...)) 形成修订循环
  • 暂停时自动持久化（默认 SQLite）；kickoff() 返回 HumanFeedbackPending
  • 异步人审：resume() / resume_async() + webhook（须幂等）

与 Deep Agents interrupt_on 对照： 二者都是 Steering 层；CrewAI 在 Flow 装饰器 表达，Deep Agents 在 Middleware 配置 表达（Deep Agents（五））。

2. Training（Prompt 层持续改进）

流程：

  1. Task 设 human_input=true
  2. 收集 initial_output → 人反馈 → improved_output
  3. 会话数据 → training_data.pkl
  4. 结束生成 trained_agents_data.pkl（按 agent role 的 suggestions）
  5. 正常运行时 自动追加 suggestions 到 prompt

边界： 这是 Prompt/行为指导 积累，不是模型微调；发版仍须固定 Prompt Registry 指针（PE 三）。

官方 Production Architecture 建议：

原则：

  • Flow 是 唯一应用入口
  • Crew 保持 单一职责，不过度塞步骤
  • State 最小化；Crew inputs 显式传递

5.1 目标

输入：主题 + 受众 +（可选）目标 URL。
输出：可发布 Markdown 文章 + SEO 审计摘要 + 引用可追溯。

5.2 架构

5.3 Crew 分工

Crew Agents Process
research_crew Researcher sequential：检索 Task
writer_crew Writer, Editor sequential：写 → 审
auditor_crew SEO Auditor sequential：MCP analyze + 报告

能力：

  • Knowledge：内部 SEO/品牌规范 PDF（RAG（五） 思路）
  • MCP：crawl_url / analyze_html（MCP（四））
  • Guardrail：Citation 必须对齐 research Task 输出

5.4 验收

  1. 文章关键事实可指向 research Task 输出或 Knowledge 命中
  2. SEO 建议带 MCP Tool Observation 指针
  3. 越权 crawl 被 HITL 或 Runtime 拒绝
  4. Tracing 可回放 Task 链与 Guardrail 结果
  5. 发版前按 Agent（四）§6 跑 Scenario 回归
