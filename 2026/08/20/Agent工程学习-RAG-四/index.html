AI-Agent工程学习-RAG(四)

发表于 2026-07-20 更新于 2026-08-20 分类于 计算机
Graph RAG：Knowledge Graph、Entity Linking、Traversal、Multi-hop；向量+图混合；LangGraph 编排。

接 RAG（三）：向量 RAG 擅 语义近邻；当问题需要 实体关系、多跳推理、全局社区摘要 时，引入 Graph RAG——常与向量混合，而非完全替代。

0. 本篇位置与认名边界

定位： L2 必修（概念 + 一种混合路径）；深度图算法非入门主线。

做（认名） 不做
实体-关系、多跳、向量+图混合路径 Neo4j/图算法全书、某厂商 GraphRAG 产品教程
Entity Linking、遍历策略、LangGraph 编排骨架 生产级图谱运维与全量社区检测调参

图检索最小时序（混合）：

1. 选型：向量 vs Graph

维度 向量 RAG Graph RAG
擅长 paraphrase、段落相似 关系链、多跳、实体聚合
成本 索引 embed 为主 构图 + 遍历 + often 额外 LLM 摘要
时效 块级更新较易 实体对齐、边更新更复杂
典型问 「政策里关于 X 怎么说」 「A 公司收购 B 后对 C 供应链的影响」

信号：评测集多 「A 与 B 的关系」、链式依赖 且向量 Recall 低 → 考虑 Graph 或混合。

2. Knowledge Graph 构建（认名）

节点：人、组织、产品、概念、文档 chunk。
边：owns、regulates、mentions、parent_of 等，需 schema 设计 防爆炸。

3. Entity Linking

用户 query 中的 「苹果」 指公司还是水果？Entity Linking 把 mention 对齐到图节点 ID。

工程：词典 + 向量实体库 + 消歧 prompt；链错实体则全链答案错——需 Trace 记录 linked_entity_ids。

4. Graph Traversal

从 seed 实体出发：

策略 用途
k-hop 邻居 局部子图进 Context
最短路径 「A 如何关联到 B」
加权遍历 按边类型/置信度过滤

子图过大 → 摘要节点或 RAG 二 Compression。

5. Multi-hop Reasoning

Local-Global（GraphRAG 类模式认名）：

  • Local：实体邻域小摘要回答局部问
  • Global：社区级摘要回答「整个 corpus 主题趋势」

多跳：hop1 检索实体 → hop2 沿边扩展 → 合并 evidence → 生成；Budget 限制 hop 数。

6. 混合架构：向量 + 图

向量负责 召回入口；图负责 关系补全。多数生产系统采用混合，而非纯图。

7. LangGraph 多节点示意

State 字段示例：entities[]、subgraph_text、vector_docs[]、hop_count。与 LangGraph（二）Reducer 合并 partial update。

8. L2 实验（可选）

小型人工 KG（10–20 实体、30 边）+ 3 个 必须多跳 的评测问；对比 纯向量 vs 混合 的 Task Success。

本模块自检与面试

请到 RAG · 自检与面试。

总结

Graph RAG：实体-关系-遍历-多跳；成本高、擅关系问。

Entity Linking：消歧是质量关键。

混合：向量初检 + 图扩展为主流落地。

LangGraph：extract → traverse → merge 可审计。
