AI-Agent工程学习-MCP(自检与面试)

发表于 2026-07-21 更新于 2026-08-20 分类于 计算机
MCP 四篇正文的学习自检与面试导向问答；覆盖架构、Server、Client 集成、安全与 SEO 项目。

本文是 MCP（一）～（四）的阶段性验收。目标不是背协议字段，而是能 设计 MCP Server、把能力安全挂进 LangChain/Deep Agents，并解释 MCP 与 Function Calling、Runtime 的分工。

0. 使用说明

建议先遮住「推荐回答」，60～120 秒内口述。重点检查：

  1. MCP vs Function Calling vs Runtime 三者边界
  2. Tools / Resources / Prompts 何时用哪个
  3. allowlist、HITL、恶意 Result 治理
  4. SEO 项目 能否说清四 Tool 职责与验收

1. 学习自检

1.1 架构与协议（一）

S1. MCP Host、Client、Server 各负责什么？

推荐回答： Host 是承载 Agent 的应用（IDE、控制台）。Client 实现 MCP 协议，连接 Server、发现能力、转发 call_tool/read_resource。Server 暴露 Tools/Resources/Prompts 并执行真实业务逻辑。Agent Loop 仍在 Host 的 Harness 中：模型 Proposal → Client 调 Server → Result 写回 ToolMessage。

S2. MCP 与自建 @tool、OpenAPI 如何选型？

推荐回答： 单应用、无复用逻辑用 @tool 最直接。已有 REST 用 OpenAPI。需跨 IDE/多 Agent 复用、第三方能力包、统一发现与描述时用 MCP Server。MCP 不替代 Runtime 校验与权限；只是能力接入标准。

S3. Tools、Resources、Prompts 在 Server 侧如何区分？

推荐回答： Tools 是可调用动作，走 tool_call 闭环，适合动态查询与副作用。Resources 是 URI 可读内容，常由 Host 预读注入 Context，不一定经过 tool_call。Prompts 是参数化模板，供 Host 复用标准分析流程。Agent 工程最常见是 Tools；Resources 适合 robots、政策等只读材料。

S4. STDIO 与 HTTP 传输各适合什么场景？

推荐回答： STDIO 用于本地子进程 Server，开发、CLI、Inspector 联调简单。Streamable HTTP 用于远程、生产、多租户，配合 Auth 与限流。SSE 多为兼容认名，新项目以官方当前 Transport 文档为准。Deep Agents 示例常用 HTTP URL；SEO 本地开发常用 stdio。

S5. MCP 能力如何映射到 Harness Tool 层？

推荐回答： MCP Server 暴露 Schema → Client 转为 LangChain Tools → 注册到 create_agent/create_deep_agent → 模型 tool_calls → Client call_tool → ToolMessage。MCP 在 Tool 层之下的标准总线；循环、Budget、HITL 仍在 Harness/Runtime。与 Agent（三）§6 分层一致。

1.2 Server 开发（二）

S6. MCP Tool Schema 应如何写才能降低误用？

推荐回答： name 稳定；description 写何时用与何时不用；parameters 用 JSON Schema 定义 type、required、enum、范围。错误返回结构化 code/message，而非长堆栈。长结果摘要或截断，防 Observation 撑爆。与 LLM 四 Tool Calling 要求一致。

S7. Resource 与 Tool 何时互换、何时不可互换？

推荐回答： 静态、只读、URI 稳定内容适合 Resource（robots、sitemap、政策包）。需参数、副作用、动态查询适合 Tool（crawl_url、check_gsc）。不要把应用指令放在 Resource 里冒充数据；Resource 仍须 tenant 与 URI allowlist 校验。

S8. MCP Server 发布前应做哪些测试？

推荐回答： Tool 单测覆盖合法/非法参数与超时；Schema 与实现契约一致；stdio 集成测试 Client 子进程 list_tools/call_tool；breaking change 升版本。无单测不宜接生产 Agent。

1.3 Client 与框架集成（三）

S9. 如何把 MCP 挂到 create_agent？

推荐回答： MultiServerMCPClient 连接 Server → get_tools() 得 LangChain tools → 与本地 tools 合并 → create_agent(model, tools=…, system_prompt=…)。invoke 走标准 messages 闭环。可选 allowlist 过滤；写操作配 HumanInTheLoopMiddleware 或 Deep Agents interrupt_on。

S10. Deep Agents 与 LangChain 挂载 MCP 有何异同？

推荐回答： 同是 get_tools 后传入 create_*_agent。Deep Agents 另有默认 FS/Todo/Summarization 栈，MCP tools 并列注册；大结果可 offloading；写工具更常配 interrupt_on。LangChain 薄 harness 适合 Tool 较少的 SEO/运维 Agent。底层均可通过 langchain-mcp-adapters。

S11. 多 MCP Server 同时连接时如何处理工具名冲突？

推荐回答： Client 配置多 server key；工具名加前缀如 seo__crawl_url；或按 Server 拆不同 Agent 实例。Trace 记录 server 与 tool 全名。allowlist 按业务只暴露必要工具，减少冲突与攻击面。

S12. Resources 注入 Context 时要注意什么？

推荐回答： read_resource 结果当数据非指令；校验 URI 与 tenant；长度预算；恶意 Server 返回 Injection 时 sanitize。Resources 不经 tool_call 时更须 Runtime 控制可见 URI 集合，不能由模型自选任意 URI。

1.4 安全与 SEO 项目（四）

S13. MCP Authentication 工程上如何存放凭证？

推荐回答： API Key/OAuth token 放 Server 或 Client 侧安全存储，经环境变量或密钥管理注入；不进 Prompt、不进 Tool Schema、不进 Trace 明文。Server HTTP 校验 Header；OAuth 刷新 token 由 Server 负责。失败返回 401 结构化错误。

S14. 如何防止恶意 MCP Server 或 Tool Result 诱导 Agent 越权？

推荐回答： 只连可信 Server；allowlist 限制可见 tools；Result 进 Context 前 sanitize，不把 Result 当系统指令；Resource URI allowlist；写操作 HITL；租户隔离。Prompt 禁止不能替代 Runtime 硬拦。扩写 Agent 自检 I9。

S15. SEO MCP Server 四个 Tool 各解决什么？

推荐回答： crawl_url 抓取页面事实；analyze_html 诊断结构/ meta 问题；check_gsc 读 Search Console 指标（或 mock）；analyze_keyword 给关键词竞争/建议。可选 robots/sitemap Resource 减少重复 crawl。Agent 结论须引用各 Tool Observation。

S16. SEO Agent 项目的验收标准是什么？

推荐回答： 四 Tool Schema 与单测通过；Agent 对测试 URL 输出带 Observation 指针的建议；越权或批量 crawl 被 HITL/Runtime 拒绝；LangSmith Trace 可回放 tool 参数与结果摘要。可与 RAG 内部 SEO 规范组合：RAG 查政策，MCP 查 live 页。

2. 面试题

I1. 请说明 MCP、Function Calling 和 Agent Runtime 的关系。

推荐回答： MCP 标准化 Client 与 Server 间发现与调用 Tools/Resources/Prompts。Function Calling 是模型输出 tool name 与结构化参数的交互机制。Runtime/Harness 连接二者：过滤 allowlist、校验参数、经 Client call_tool、处理超时、写 ToolMessage、Budget 与 HITL。MCP 是接入层，不是执行授权；鉴权、审计、租户隔离仍由 Client、Server 与 Runtime 共同完成。

I2. 何时应该自建 MCP Server，何时继续用本地 @tool？

推荐回答： 能力需跨应用复用、独立进程/团队维护、IDE 与 Agent 统一接入、或第三方按 MCP 交付时用 Server。单应用、逻辑简单、无复用需求时 @tool 成本更低。已有 REST 可包一层 MCP Server 或直接 OpenAPI Tool。选型看复用与边界，非看功能多少。

I3. 设计 SEO MCP Server 时，读写与风险如何分级？

推荐回答： analyze_html、analyze_keyword 只读可自动。crawl_url 可能触发封禁或负载，需 rate limit、robots 尊重、批量 HITL。check_gsc 涉及 OAuth 与租户数据，需 Auth 与 tenant 校验。Resource robots/sitemap 只读预检。Agent 侧 allowlist + Trace；结论必须引用 tool 结果，禁止无 Observation 的断言。
