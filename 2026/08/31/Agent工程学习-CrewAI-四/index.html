AI-Agent工程学习-CrewAI(四)

发表于 2026-07-22 更新于 2026-08-20 分类于 计算机
CrewAI Knowledge/Memory、MCP 集成、Event Listeners、Tracing 与外部观测；与 RAG/MCP/LangSmith 对齐。

接 CrewAI（三）：编排主线已会；本篇讲 知道什么（Knowledge/Memory）、连什么（MCP）、怎么看（Tracing/Events）——与 RAG、MCP、Agent（四）评测口径对齐。

0. 本篇位置

  • （一）～（三）：架构、Agent/Task、Crew/Flow
  • 本篇：Knowledge / Memory / MCP / 观测
  • （五）：HITL / Training / 生产项目

官方：Knowledge · Memory · Tracing · Event Listeners

1. Knowledge（RAG 层）

Knowledge 让 Agent 预加载外部事实，检索在框架内完成——Agent 不必再写「何时调用检索 Tool」的 persona。

1.1 Agent 级 vs Crew 级

级别 范围
Agent 级 单 Agent 专属文档
Crew 级 全 Crew 共享

与 RAG（一） 两种挂法对照：Knowledge ≈ Runtime 预注入；Retriever Tool ≈ 工具化按需检索（CrewAI 侧以 Knowledge 为主路径）。

1.2 数据源与存储

  • 支持 PDF、CSV、URL 等
  • 默认 ChromaDB 向量存储；可换 Qdrant 等
  • 默认 embedding 常为 OpenAI text-embedding-3-small（即使 LLM 换厂商也需注意一致）
  • Query Rewriting：检索前自动改写 query 提升召回

1.3 与 RAG 系列分工

主题 RAG 系列 CrewAI Knowledge
Chunk/Index 策略 深讲 内置，可配置
Recall@K 评测 §8 指标 须自建评测集验证
Citation Gate LE + structured output Task Guardrail
企业生产 Ingestion RAG（五） 可外置 job + Knowledge 刷新

发版： embedding/index 版本须固定；指标对齐 Agent（四）§6 RAG 域。

2. Memory 统一系统

CrewAI v1.15+ 提供统一 Memory API，替代分散的 short/long/entity 类型。

2.1 四种使用方式

方式 场景
独立 Memory() 脚本、笔记本
Crew(memory=True) 全员共享，继承 crew embedder
Agent 独立 memory 覆盖 Crew 默认
Flow 内置 self.remember() / self.recall() / self.extract_memories()

2.2 核心机制

  • Scope 树：/, /project/alpha, /researcher/findings
  • 保存时 LLM 分析：推断 scope、categories、importance
  • 召回评分：语义相似 + 时效 + 重要性
  • extract_memories：长输出拆成原子事实再 remember()

与 Agent（五）§3 对齐： 防写污染（无 Observation 不持久化）、scope 隔离、污染 fixture 回归。

3. MCP 集成

Agent 配置：

与 MCP 系列 对齐：

  • MCP 提供发现与 Schema；执行闭环仍是 tool_call → Result
  • 仍须 allowlist、HITL、恶意 Result sanitize
  • 可与 MCP（四）SEO 项目 四 Tool 组合：RAG 查内部规范，MCP 查 live 页

4. Event Listeners

基于 CrewAIEventsBus + BaseEventListener，监听执行生命周期事件。

典型事件类：

类别 示例
Crew kickoff 开始/结束
Task 完成、失败
Tool 调用
Flow 输入请求、HITL
Training train 开始

用途： 自定义审计日志、指标上报、webhook、与内部工单系统对接。

5. Tracing 内置观测

5.1 启用（三选一）

5.2 可见内容

  • Agent 决策与 Task 时间线
  • Tool 调用与结果摘要
  • LLM 请求、Token、成本
  • 错误栈

Dashboard：CrewAI AMP（crewai deploy 可部署到企业平台）。

5.3 与 LangSmith / Agent（四）对照

概念 CrewAI Tracing 你路径中的对应
单次排障 Trace 时间线 LangSmith trace
批量回归 需自建 Dataset + Scenario LangSmith Experiment + Agent（四）§6
字段 tool 名、Task 输出 tool_calls, Gate 记录

Eval 流水线 不在 CrewAI 系列展开分步教程——发版 canonical 清单仍为 Agent（四）§6。

5.4 外部观测

  • OTLP 导出 → Grafana / 自建 Collector（AMP Enterprise）
  • Datadog 直连 OTLP intake
  • Langtrace 等第三方：成本、延迟、Prompt 版本 A/B

6. 集成架构示意

7. 实践要点

  1. Knowledge 与 MCP 不要重复造 RAG 管线——复杂 Ingestion 仍用 RAG（五）job，CrewAI 消费刷新后的源
  2. Memory scope 设计先于上线——否则跨项目污染
  3. Tracing 与 Guardrail 失败率一起告警
  4. MCP Tool 名冲突——多 Server 加前缀（回链 MCP 自检 S11）

本模块自检与面试

学完 CrewAI 系列五篇后，请到 CrewAI · 自检与面试。

总结

Knowledge：Agent/Crew 级 RAG；Query rewrite；版本与 RAG 域 Checklist 对齐。

Memory：统一 API + scope；extract_memories 防 blob 污染。

MCP：mcps=[...]；不替代 Runtime 校验。

Events：Bus + Listener 做审计与集成。

Tracing：AMP 一等公民；批量回归回链 Agent（四）§6。
