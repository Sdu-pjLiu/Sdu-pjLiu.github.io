1. Crew：Agents + Tasks + Process

Crew 定义 谁做什么、按什么顺序协作。

属性 说明
agents 参与 Agent 列表
tasks Task 列表（可 JSONC 内嵌）
process sequential（默认）或 hierarchical
verbose / memory / cache / max_rpm Crew 级治理
planning / planning_llm Crew 级先规划再执行
manager_llm / manager_agent hierarchical 必需
tracing 内置追踪

2. Process：sequential vs hierarchical

2.1 Sequential（流水线）

Task 严格按序执行；后一 Task 通过 context 读前一 Task 输出。

适用： 步骤依赖清晰、质量链式传递（Research Agent 地图，见 Agent 四）。

crew.jsonc 片段：

2.2 Hierarchical（Manager 委派）

Manager Agent/LLM 动态分配 Task、验收结果再继续。

要求： 必须提供 manager_llm 或 manager_agent。

适用： 子任务边界运行时才能确定、需 Manager 质检（类似 LangGraph Supervisor，但声明在 Crew 层）。

对比 Sequential Hierarchical
顺序 固定 Manager 决定
可预测性 高 中
与 LangGraph 类似固定边 类似 Supervisor 节点

3. Flow：事件驱动编排

Flow 是 应用入口——管状态、分支、持久化，并在合适步骤调用 Crew。

3.1 装饰器

装饰器 作用
@start() 流程入口
@listen(fn) 监听某步完成后执行
@listen(or_(a, b)) 多条件触发（修订循环）
@router() 按返回值分支
@persist 状态持久化

3.2 State（Pydantic）

原则（官方 Production Architecture）：

  • State 尽量小——只存跨步必需字段
  • 避免无结构大 dict
  • 传入 Crew 的 inputs 从 state 显式提取

3.3 三种交互模式混用

不必把 JSON 提取、文件 IO 都塞进 Crew——这是 Flow 的核心价值。

5. 持久化与恢复

@persist 将 Flow state 写入存储（默认可 SQLite），支持长任务与人审暂停后续跑。

场景： 崩溃恢复、HITL 等待、A/B 实验 fork。

与 LangGraph Checkpoint 对照： 二者都解决 durable state；CrewAI Flow 装饰器更偏 应用层 表达，LangGraph 更偏 Runtime 通道。

6. 路由与并行（认名）

  • @router：上一步返回值决定下一监听者
  • and_() / or_()：复合触发——修订循环常用 or_("start", "needs_revision")
  • 独立 section 可并行 kickoff Crew（需注意 API 速率与成本）

Conversational Flows（ChatSession、kickoff per message）属进阶——多轮聊天式应用，本篇认名即可。

7. Crew 级回调

回调 用途
before_kickoff_callbacks 注入 inputs、鉴权
after_kickoff_callbacks 写库、发 webhook

Flow 层亦可纯 Python 接 API——生产入口推荐 Flow 接 HTTP，内部 kickoff Crew。

8. 实践阶梯 L1 → L2（编排篇）

级别 做什么 证明
L1 Sequential Crew：Researcher → Writer → Editor，3 Task + context 链式输出可追溯
L2 Guide Creator 式 Flow：outline LLM + 循环 kickoff Crew + 拼装 md crewai flow plot 可视化

9. 与 Loop Engineering 对齐

LE 概念 CrewAI 落点
Contract / Done Task expected_output + Guardrail
Budget max_iter、max_rpm、Flow 层循环次数
轨迹回归 Tracing + Task Success Scenario（五）
假完成 Guardrail 无引用即 fail

完整发版指标见 Agent（四）§6；LE（三）§3 轨迹指标可映射到 Crew 重复 Task / Guardrail 失败率。

总结

Crew：agents + tasks + process；sequential 流水线 / hierarchical Manager。

Flow：@start/@listen/@router + Pydantic state；Python / LLM / Crew 混用。

Guide Creator：outline → 逐节 Crew → 拼装——标准 Flow+Crew 模式。

持久化：@persist + kickoff(id) / restore_from_state_id。
