AI-Agent工程学习-RAG(三)

发表于 2026-07-20 更新于 2026-08-20 分类于 计算机
Agentic RAG：Tool/Planning/Iterative/Self-RAG/Adaptive；create_agent + Citation Gate + LangGraph 示意。

接 RAG（二）：固定「检索一次 → 生成」不够时，把检索交给 Agent 环——模型决定 是否检、检什么、检几次，Runtime 负责 Budget 与 Citation Gate。

0. 本篇位置

回链：LangChain（四）§5、LangChain（五）create_agent、LE（一）验证门。

1. Tool-based Retrieval

与 LangChain（四）同一模式；Agentic 差异在 多步决策 与 与其他 Tool 组合。

要点：Tool description 限制滥用；Observation 长度上限；空结果结构化返回。

2. Query Planning

复杂问题先 拆 sub-query，再分别检索、合并：

可由模型在 Thought 中规划，或 LangGraph 专用 plan 节点 输出 structured sub-queries。

3. Iterative Retrieval

每次检索写回 ToolMessage（Observation）；Budget 限制最大轮数（Agent 三）。避免无限「再查一下」烧 Token。

4. Self-RAG（认名）

论文/产品术语：模型或专用节点自评——

  • 当前 context 是否足够 回答？
  • 答案 是否有检索支撑？
  • 是否需要 再检索 或 拒答？

工程落地：不必训练 Self-RAG 模型；用 结构化 grade（相关/不相关/需重写）+ LangGraph 条件边即可（§7）。

5. Adaptive RAG（认名）

按问题类型 路由 不同检索策略：

路由 策略
无需外库 直接生成（或拒答）
单跳事实 一次 Retriever Tool
多跳 / 对比 Iterative 或 Graph（RAG 四）
结构化报表 LCEL 预检索 + Agent 总结

可用轻量 classifier 或 LLM 路由节点；记录路由决策到 Trace 便于评测。

6. Citation Gate 与 Budget

对齐 LE（一）：

  1. 合同：最终答案含 citations[]，每项至少含 source_id（进阶可加 quote 片段或内容 hash，便于人工抽检）。
  2. Gate：每条 citation 的 source_id 必须在当轮 ToolMessage 或 State 检索结果中存在。
  3. Budget：检索 Tool 调用次数上限；超预算 → 软着陆摘要或转人工。

8. L1 实验

create_agent + search_knowledge_base + 结构化 CitedAnswer；评测集含 必须检索 与 不应检索 两类题，测 Unnecessary Tool Calls 与 Citation 正确率。

总结

Agentic：检索是 Tool 决策，非固定管道。

Planning / Iterative：拆 query、多轮检；受 Budget 约束。

Self / Adaptive：认名；工程上用 grade + 路由实现。

Citation Gate：LE 合同 + 结构化 citations。

LangGraph：多跳检索状态机显式化。
