发表于 2026-07-22 更新于 2026-07-20 分类于 计算机
LangChain / LangGraph / Deep Agents / CrewAI 官方定位与工程选型对比；四条实现线 canonical 参考。

接 CrewAI · 自检与面试：四条实现线（LangChain / LangGraph / Deep Agents / CrewAI）均已学完；本篇自上而下汇总 定位、抽象、控制流、多 Agent、持久化、Context、Tool/MCP、HITL、观测、选型，作为 canonical 对比文档——各系列正文只回链此处，不重写完整对比长文。

1. 一句话定位（官方口径）

框架 官方定位 文档
LangChain minimal, highly configurable agent harness（最小化、高度可配置的 Agent Harness）：create_agent = Model + Tools + Prompt + Middleware LangChain overview
LangGraph Low-level orchestration framework and runtime（底层编排框架与运行时）：durable execution、streaming、HITL、persistence（持久化执行、流式、人机协同、状态持久） LangGraph overview
Deep Agents Pre-assembled thick harness on LangGraph（基于 LangGraph 的预组装厚 Harness）：planning、filesystem、subagents、memory 开箱（规划、虚拟文件系统、子代理、记忆开箱即用） Deep Agents overview
CrewAI Flow（backbone）+ Crew（intelligence）（Flow 流程骨架 + Crew 协作智能）：Use a Flow to define structure; use a Crew for complex collaborative tasks（用 Flow 定义应用结构，复杂协作委派 Crew） CrewAI Introduction

生态关系（关键）：

  • Deep Agents ⊂ LangChain + LangGraph 生态（编译为 LangGraph Runnable）
  • CrewAI 是 并行实现线，不建立在 LangGraph 之上
  • LangGraph 是 LangChain 生态内的 编排 Runtime 底座

1.1 LangChain 官方三层产品 taxonomy

LangChain 文档 Frameworks, runtimes, and harnesses 将生态拆为三层——与上表「一句话定位」一一对应：

官方称谓 对应产品 中文含义
Agent framework LangChain Agent 开发框架：Model / Tool / Prompt / Middleware 组装
Agent runtime LangGraph Agent 运行时：状态图、持久执行、HITL、Checkpoint
Agent harness LangChain create_agent（薄）· Deep Agents（厚） 完整 Agent 工作环境：loop + 治理栈开箱程度不同

读法： Framework 提供零件；Runtime 提供编排引擎；Harness 把零件 + 引擎打包成可跑 Agent。CrewAI 不在此三层内，是并行应用框架。

1.2 一句话记忆（选型速查）

框架 记忆口诀
LangChain Agent 开发工具箱（薄 Harness）
LangGraph Agent 工作流运行时 / 状态机引擎
Deep Agents 开箱长任务厚 Harness
CrewAI AI 团队 + 应用 Flow 框架

2. 分层架构（自上而下）

先澄清常见误区： 四框架 不是「哪个更好」的平级竞争，而是 不同抽象层的组合件。LangGraph 管编排；LangChain / Deep Agents 管 Harness；CrewAI 走并行路线（Flow + Crew），不建立在 LangGraph 之上。

读图口诀：

  • 要 精细图 + 确定性步骤 → 下沉 LangGraph
  • 要 单 Agent 可控外壳 → LangChain
  • 要 长任务开箱治理 → Deep Agents
  • 要 多角色产品化应用 → CrewAI Flow + Crew

3.1 开发体验与复杂度（定性）

不采用主观星级；用 心智负担 与 典型代码量 描述（各系列首篇有完整示例，本篇不重复教程）：

目标 上手最快 复杂系统可控性最高 典型代码量（单 Agent 闭环）
简单单 Agent + 少量 Tool CrewAI / LangChain LangChain LangChain ~10 行；CrewAI ~20–50 行
复杂多步 + 分支 + 恢复 — LangGraph LangGraph ~100–300 行（State/Node/Edge/Checkpoint）
长任务开箱（FS/规划/Subagent） Deep Agents Deep Agents（抽象换治理） Deep Agents ~50 行起
多角色产品化应用 CrewAI CrewAI Flow 层 Flow + Crew 视任务而定

原则： 简单步骤用 Python / 直接 LLM.call，不必塞进厚 Agent 或 Crew——见 CrewAI（一）§1。

4. 控制流与执行模型

4.1 默认执行形态

框架 默认循环
LangChain Model → tool_calls → execute → ToolMessage → Model → …
LangGraph 按边遍历 Node；每 Node 可含 LLM、工具、校验、DB
Deep Agents planning → tools → FS offload → 可选 subagent → 汇总
CrewAI Flow @start/@listen 驱动；子步 crew.kickoff()

4.2 三种交互模式（CrewAI Flow 亦适用）

模式 适用 典型框架
普通 Python 校验、IO、DB、API LangGraph Node / CrewAI Flow
直接 LLM.call 单次结构化输出（JSON 大纲） CrewAI Flow / LangGraph Node
Agent/Crew 协作 开放质量、多步推理 四框架均可；CrewAI 最自然

原则： 简单步骤不必塞进 Crew 或厚 Agent——见 CrewAI（一）§1。

4.3 Middleware / Hooks 位置

  • LangChain：Middleware 插在 agent loop 各步（model 前/后、tool 前/后）
  • LangGraph：Middleware 编译进 agent 节点；图级逻辑用 Node/Edge
  • Deep Agents：默认 Middleware 栈（TodoList、FS、Summarization、SubAgent…）
  • CrewAI：Guardrail / callback 在 Task 级；Flow 装饰器在应用级

5. 多 Agent 模式对比

框架 多 Agent 表达 典型模式 强项
LangChain 非主战场 多 agent + 外部 LangGraph 编排 单 Agent 闭环
LangGraph Supervisor / Subgraph / Handoff 图级显式路由 控制最细、可审计
Deep Agents task() Subagent 委派 + context quarantine 长材料隔离
CrewAI Role + Task + Process sequential / hierarchical 团队 角色化协作

对照（不重复正文）：

  • Deep Agents Subagent vs LangGraph Supervisor → Deep Agents（四）
  • CrewAI hierarchical vs LangGraph Supervisor → CrewAI 自检 I2

选型口诀：

  • 每步图级门禁、复杂 handoff 合同 → LangGraph
  • 快速委托重 research、主 context 要干净 → Deep Agents Subagent
  • Researcher + Writer + Editor 流水线 → CrewAI sequential Crew

6. 状态、持久化、恢复

框架 机制 关键概念 强度
LangGraph Checkpointer thread_id、interrupt()、Command(resume=…) 最强
LangChain 透传 checkpointer create_agent(..., checkpointer=…) 可用
Deep Agents 消费 LangGraph Runtime 用户关注 FS/subagent，少手动画图 借底层
CrewAI Flow @persist kickoff(inputs={"id":…})、restore_from_state_id 应用层

LangGraph 恢复注意： interrupt 后节点从函数开头重跑，前半段须幂等——见 LangGraph Interrupts。

CrewAI HITL： @human_feedback 暂停时自动 persist（默认 SQLite）——见 Human Feedback in Flows。

7. Context / Memory / Knowledge

框架 Context 治理 Memory Knowledge/RAG
LangChain 自选 Middleware（Summarization 等） 可接 checkpointer/store Retriever Tool / 链
LangGraph state/store 容器，策略自建 Store + thread state 节点内接 RAG
Deep Agents Summarization + FS + subagent 隔离 AGENTS.md / memory 参数 作 Tool 或 memory
CrewAI Flow state + Task 输出 统一 Memory API + scope 内置 Knowledge

理论回链： Agent（五）§2 Context · RAG 系列 · CrewAI（四）

选型：

  • 长任务 context 爆炸 → Deep Agents（FS + subagent quarantine）
  • 企业文档预加载 → CrewAI Knowledge 或 RAG 系列 + 任一 Harness
  • 完全自定义压缩策略 → LangChain Middleware 或 LangGraph 自建节点

8. Tools / MCP / Structured Output

能力 LangChain LangGraph Deep Agents CrewAI
Tool 集成 最强（@tool、StructuredTool） 节点内调用 继承 + 默认 FS/subagent tools Tools/MCP/Apps
MCP LangChain MCP 经 agent 节点 MultiServerMCPClient mcps=[...]
Structured output response_format Provider/ToolStrategy 节点内 LLM 继承 LangChain Task output_json/pydantic
Skills Deep Agents skills 自建 内置 skills 目录 skills=[...]

MCP 共性： 提供发现与 Schema；不替代 Runtime 校验、allowlist、HITL（MCP（四））。

9. Human-in-the-Loop 对比

框架 机制 表达层级 典型场景
LangGraph interrupt() + checkpointer Runtime 节点级精确暂停
LangChain HumanInTheLoopMiddleware Middleware 工具调用前审批
Deep Agents interrupt_on Harness 写文件/危险 tool 前
CrewAI @human_feedback + emit 路由 Flow 审稿/修订循环

组合： 硬副作用用 Runtime/Harness 拦截；内容质量用人审 Flow 或 LLM Guardrail。

总结

不是同层竞争：Framework / Runtime / Harness / 应用框架处于不同抽象层，按场景 组合 而非单选。

一句话记忆（详见 §1.2）：

框架 口诀
LangChain Agent 开发工具箱（薄 Harness）
LangGraph Agent 工作流运行时 / 状态机引擎
Deep Agents 开箱长任务厚 Harness
CrewAI AI 团队 + 应用 Flow 框架

分层：CrewAI 并行于 LangGraph 生态；Deep Agents 基于 LangChain+LangGraph。

选型：单 Agent→LangChain；精细图→LangGraph；长任务→Deep Agents；角色团队→CrewAI；企业生产见 §10.3、§11.4 双路径。

治理：LE Gate + Agent（四）§6 为 universal；HITL 各框架表达不同。
