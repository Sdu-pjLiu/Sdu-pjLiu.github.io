AI-Agent工程学习-RAG(自检与面试)

发表于 2026-07-20 更新于 2026-08-20 分类于 计算机
RAG 五篇正文的学习自检与面试导向问答；覆盖基础管线、增强、Agentic、Graph 与企业项目。

本文是 RAG（一）～（五）的阶段性验收。目标不是背检索名词，而是能 选型 Chain/Tool/Graph、按评测驱动叠加增强、设计可审计的 Agentic RAG，并落地企业生产知识库。

0. 使用说明

建议先遮住「推荐回答」，90～120 秒内口述。合格答案含：概念边界、选型条件、主要风险、工程措施。另请自检：能否说清 LCEL 固定 RAG vs Retriever Tool vs LangGraph 多跳 的分工。

1. 学习自检

1.1 基础管线（一）

S1. RAG 系列与 LangChain（四）如何分工？

推荐回答： LangChain（四）讲 Document、VectorStore、Retriever 积木、LCEL 链与 @tool 挂载入门。RAG 系列在相同 LangChain 实现上深化 Chunk/Index 策略、评测指标、高级增强、Agentic/Graph 与生产 Ingestion/ACL。理论挂法在 Agent（三）；Citation 验收在 LE（一）与 Agent（四）。不应在两处重复展开相同 LCEL 教程，RAG（一）强调评测驱动与 metadata 设计。

S2. Embedding 模型更换时索引如何处理？

推荐回答： 换 embedding 模型通常需 重建索引，因向量空间不兼容。工程上索引名或 metadata 应记录 embedding_model_id 与 index_version；升级流程为新索引双写、评测对比 Recall/Faithfulness、切流量、删旧索引。查询与索引必须使用同一模型与同一归一化策略。

S3. Chunk 过粗与过细各有什么症状？metadata 最小应含什么？

推荐回答： 过粗导致检索命中段落噪声大、难精确定位；过细丢失上下文、引用难读、Recall 碎片化。metadata 至少含 source_id、标题或章节、租户/权限字段、更新时间、doc_type，供过滤、引用与 ACL。结构感知切块适合手册类文档。

S4. 空检索结果时 Agent 应如何行为？

推荐回答： 不应编造答案。Tool 应返回结构化 NO_HITS 或类似信号；Agent 明确告知文档未覆盖，或触发 Query 改写/二次检索（受 Budget 限制）。与 LE 验证门一致：无 Observation 支撑的关键事实不得进入 Final Answer。低分阈值拒答优于硬生成。

S5. Recall@K 与 Citation 正确率分别衡量什么？

推荐回答： Recall@K 衡量标准答案所需 chunk 是否出现在 Top-K 检索结果中，反映检索召回。Citation 正确率衡量最终答案引用的 source_id 是否对应真实命中 chunk，反映生成是否 grounded。应先优化 Recall，再优化 Rerank 与 Prompt；Citation 错常来自检索错或模型忽视 context。

1.2 高级检索（二）

S6. Hybrid Search 与 Reranker 分别解决哪类失败？

推荐回答： Hybrid 结合 BM25/关键词与向量，解决专名、编号、SKU 等 exact match 召回不足。Reranker 对初检较大 K 的候选精排，解决「召回了但 Top-K 噪声大」。二者可组合：Hybrid 提高召回，Rerank 提高精度。应保留降级：Rerank 超时则回退初检 Top-K。

S7. Query Rewrite 与 Multi-Query Retrieval 有何异同？

推荐回答： 二者都缓解用户问法与文档措辞不一致。Rewrite 生成一条更检索友好的 query；Multi-Query 生成多条 query 分别检索后去重合并，Recall 更高但成本更大。都增加 LLM 调用，需计入 Budget。不应在无评测增益时默认开启。

S8. Parent Document Retrieval 适用什么场景？

推荐回答： 索引用小 chunk 提高定位精度，生成时取 parent 大段（整节/页）补上下文。适用于法条、API 文档等「定位细、理解需上下文」的场景。metadata 需 parent 指针；注意 parent 过大时要 Compression 或截断。

S9. Metadata Filtering 为何必须在检索前而非生成后？

推荐回答： 生成后过滤无法阻止越权内容进入 Context，存在泄露与 Injection 风险。检索前按 tenant_id、role、doc_type、有效期 filter，使模型根本看不到无权限 chunk。与 RAG（五）ACL 一致；filter 条件须来自可信会话而非模型自填。

S10. 增强模式失败时的降级策略是什么？

推荐回答： Rerank 失败用初检 Top-K；Hybrid 一路空则纯向量；Rewrite 失败用原问；全链路无 chunk 过阈值则拒答或转人工。增强是插件，不能成为单点故障。每次只加一种增强并在同一评测集验证，避免不可归因的复杂度堆叠。

1.3 Agentic RAG（三）

S11. 何时用 LCEL 链，何时用 Retriever Tool？

推荐回答： 每个问题固定「检索一次再生成」、路径确定时用 LCEL，延迟与成本可控。当是否检索、检索几次、是否结合其他 Tool 需模型根据中间结果决定时，用 Retriever Tool 交给 create_agent。复杂多跳、grade/rewrite 环用 LangGraph 显式状态机。选型看控制流是否需模型动态决策。

S12. Iterative Retrieval 的主要风险与治理？

推荐回答： 风险是无限检索烧 Token、重复检相同 query、Observation 撑爆 Context。治理：Runtime Budget 限制检索次数；结构化记录已检 query 防重复；Observation 长度上限与 Compression；Citation Gate 确保最终答案有据。部分失败时软着陆而非继续空转。

S13. Self-RAG 与 Adaptive RAG 在工程中如何落地（不必训练专用模型）？

推荐回答： Self-RAG 认名：自评 context 是否够、答案是否有据、是否再检——可用 LangGraph grade 节点 + 条件边实现。Adaptive RAG 认名：按问题路由不检/单检/多跳/Graph——可用轻量 classifier 或 LLM 路由节点，决策写入 Trace。核心是 可观测路由 与 Budget，非名词本身。

S14. Citation Gate 与 LE 验证门如何配合？

推荐回答： LE 定义可机检合同：Final Answer 含 citations 且每条对应有效 Observation/检索 chunk。Gate 在生成后或结构化输出校验时执行：source_id 存在于当轮 ToolMessage；无支撑陈述判失败并 retry 或拒答。RAG 不能替代 Runtime 硬校验；低温与 Prompt 不能单独扛 Gate。

1.4 Graph RAG（四）

S15. 何时值得引入 Graph RAG 而非仅向量 RAG？

推荐回答： 当评测集多关系链、多跳、实体聚合问且向量 Recall 低时考虑。纯语义段落问仍优先向量。Graph 成本在构图、Entity Linking、遍历与维护；常见落地是 向量初检 + 图扩展 混合。无清晰 entity/relation schema 时不宜强行上图。

S16. Entity Linking 错误会导致什么后果？

推荐回答： query 中 mention 链到错误图节点，后续遍历与生成全基于错误实体，表现为「流畅但事实链错」。需词典、实体向量库、消歧规则与 Trace 记录 linked_ids；关键场景人工抽检多跳链。

S17. Local-Global（GraphRAG 类）模式各回答什么类型问题？

推荐回答： Local 用实体邻域摘要答具体实体问；Global 用社区级摘要答 corpus 整体主题/趋势问。Multi-hop 沿边扩展补关系证据。与向量 chunk 互补；社区摘要需离线构建与版本管理。

1.5 生产与企业项目（五）

S18. Ingestion 管线应保证哪些工程属性？

推荐回答： 幂等（content_hash 不变则 skip）、增量更新、源删除同步索引删除、embedding/index 版本登记、调度可观测。Loader 后清洗 PII 与 boilerplate；metadata 写 ACL 与 tenant。失败重试与 dead letter 队列避免 silent 丢文档。

S19. 企业知识库 Agent 项目的最小验收标准是什么？

推荐回答： 固定评测集上：Task Success 达 Rubric（含引用可追溯、checklist 项有 citation）；无越权 doc 进入 Context；检索 Budget 内完成；Faithfulness 抽检通过；P95 延迟与成本在 SLO 内。须保存 query、hit_ids、 citations 到 Trace 可回归。

S20. RAG 监控应告警哪些信号？

推荐回答： 空结果率突增、P95 检索延迟、Citation Gate 失败率上升、Faithfulness 抽检下降、embedding/index 版本不一致。关联索引发布与模型变更事件。空结果可能是索引损坏、filter 过严或 query 分布漂移。

S21. 企业项目何时用 Deep Agents 而非 LangChain create_agent？

推荐回答： 标准 Q&A + 结构化方案 + 少量检索 Tool 时 create_agent 足够。需要长任务 todo、多文件 FS、Skills 流程、Subagent 隔离大材料或厚 Summarization 时换 Deep Agents，RAG 仍可作为 Tool 接入。选型看 Context 治理复杂度而非文档数量 alone。

S22. RAGAS/DeepEval 与文内 Recall@K、Faithfulness 如何映射？何时仍用自建 Scenario？

推荐回答： 文内指标是工程口径：Recall@K 需 gold chunk id；Faithfulness 查断言↔检索 context；Citation 正确率多靠自建 Rubric + structured output。RAGAS 的 context_recall、faithfulness 等是自动化实现，须保证 K 值、chunk 边界与 Trace 字段一致，不能当作第二套标准。DeepEval/TruLens 同类。发版五域 Checklist 仍以 Agent（四）§6 为准。Citation 对齐、越权 doc、Budget、记忆污染等 工程 Rubric 无通用开箱指标时，仍用自建 Scenario + LangSmith Dataset；工具只负责批量算分，不替代 Rubric 设计。见 RAG（一）§9。

S23. 源文档更新后线上仍引用旧段落，可能原因与治理？

推荐回答： Ingestion 未跑、hash 未变、删源未删索引、别名未切、答案缓存未带 index_version。治理：事件/对账驱动增量 upsert/delete；读别名切换；缓存键含版本。见 RAG（五）§4.1。

S24. 黄金集与「跑通一次评测」差在哪？坏例如何处理？

推荐回答： 黄金集是版本化、含 gold_chunk/越权负例、可回归的集合；一次性评测无守门。坏例修复后必须入库并进入发版必跑集。见 RAG（一）§8.1。

S25. 为何多租户 filter 必须在检索前？如何验收？

推荐回答： 生成侧约束不可靠且已泄漏进 Context。验收：租户 A 账号问 B 机密 → 命中集为空或无 B 的 source_id；黄金集含串读负例。见 RAG（五）§2.1。

2. 面试题

I1. 请设计一个企业知识库 RAG，说明 LangChain 在每层承担什么。

推荐回答： Loader/Splitter/Embed/VectorStore/Retriever 用 LangChain；Hybrid+Rerank 作 Retriever 组合；Q&A 用 create_agent + @tool 或 LCEL 固定链；Citation 用 structured output + LE Gate；评测用固定集算 Recall 与 Task Success；Ingestion 可独立 job 调 LangChain Document API。LangGraph 仅在多跳 grade/rewrite 时引入。

I2. Agentic RAG 与固定 RAG 链的本质区别是什么？

推荐回答： 固定链程序决定「每问必检一次」；Agentic 由模型在 Loop 中决定是否检索、query 改写、多次检索及与其他 Tool 协作。代价是 Budget、Unnecessary Tool Calls 与 Trace 复杂度上升；收益是复杂、多步、需中间推理的问题。不应为简单 FAQ 默认 Agentic。

I3. 如何定位 RAG 答案「看起来对其实幻觉」？

推荐回答： 拆断言对照 citations 与 ToolMessage；算 Faithfulness/Hallucination Rate；查是否空检索仍生成、是否引用错误 source_id、是否 Compression 压掉否定词。轨迹级看检索是否发生、命中是否相关。修复方向：阈值拒答、Rerank、Gate、Prompt 合同——非单纯换更大模型。

I4. 向量 RAG 与 Graph RAG 如何混合？

推荐回答： 向量 Retriever 得 Top chunks 并抽取 mention 实体 → Entity Linking → 图上游 1–2 hop 扩子图 → 合并 vector 与 graph 文本 → LangChain 生成 → Citation Gate。向量保召回入口，图补关系；Budget 限 hop；评测对比纯向量 Task Success。

I5. 如何设计 RAG 发版回归，避免「只测模型手感」？

推荐回答： 黄金集含 gold_chunk、越权负例、rubric；发版跑全量 Recall/Citation/Faithfulness 抽检；改 embedding/索引必须重建或双写切换；坏例入库。工具（RAGAS 等）只自动化计分，不替代 Rubric。

I6. 生产默认开 Hybrid+Rerank 吗？何时降级？

推荐回答： 默认 filter 硬开 + Hybrid；Rerank 按延迟/成本可选。降级：Rerank 超时→仅 Hybrid→纯向量→拒答。用黄金集验证关 Rerank 的质量损失。见 RAG（二）§8.1。
