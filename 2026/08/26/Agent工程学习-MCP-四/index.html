AI-Agent工程学习-MCP(四)

发表于 2026-07-21 更新于 2026-08-20 分类于 计算机
MCP Auth/Permission/安全；SEO MCP Server 四工具项目；Agent 集成；全路径收口。

接 MCP（三）：Client 与 Agent 集成会跑之后，补齐 生产安全，并完成 SEO MCP Server 主线项目——crawl_url / analyze_html / check_gsc / analyze_keyword。

0. 本篇位置

本篇 收口 MCP 系列；下一模块进入 CrewAI（一）——用 Flow + Crew 把多角色与应用编排产品化（仍须 Runtime Gate / allowlist，MCP 不替代权限）。

1. Authentication（认名）

方式 场景
API Key Server-to-server；HTTP Header；简单内部服务
OAuth 2.1 用户委托访问第三方 SaaS（如 GSC）；与 API Key 不是同一信任模型
mTLS 企业内网

MCP Client 配置携带 token；密钥不进 Prompt、不进 Tool Schema、不进明文 Trace。Server 校验失败返回 401 结构化错误。轮换密钥时同步更新 Client 配置与密钥管理，勿硬编码进仓库。

2. Permission 与 Agent（六）三档对齐

档 MCP 示例
自动 analyze_html 只读
确认 crawl_url 批量、写本地缓存
禁止 未授权 tenant 的 check_gsc

Runtime 硬拦；Prompt「请勿越权」不能替代（PE 四）。

2.1 工具危险级与人审门（认名）

危险级 示例 门禁
L0 只读 查文档、分析 HTML 可自动；仍要 tenant filter
L1 可逆写 写草稿、本地缓存 确认或审计后自动
L2 难逆/资金 下单、改权限、对外发信 人审门（HITL） 默认开；禁止静默成功

人审门 = interrupt → 人工决策载荷 → resume；与 Agent 工程化（一） Lifecycle、工程化（三） 写工具审计同口径。

3. 恶意 Server 与 Tool Result Injection

扩写 Agent 自检 I9：

风险 措施
恶意 Tool description 仅连接可信 Server；allowlist
Result 内假指令 Result 当 数据 非 指令；sanitize 再进 Context
越权 URI Resource URI allowlist + tenant 校验
过大 Result 截断 + 摘要

4. stdio 开发 vs HTTP 生产

环境 传输
本地开发 stdio 子进程
生产 Streamable HTTP + Auth + 限流

SEO Server 开发用 stdio；部署可包 Docker + HTTP 反向代理。

5. SEO MCP Server 项目（主线）

5.1 Tools

Tool 职责
crawl_url(url) 抓取 HTML（遵守 robots）；返回 status、title、meta
analyze_html(html_or_url) 标题结构、H1、meta description、canonical 问题
check_gsc(site_url) 查询 Search Console 指标（或 mock + 契约）
analyze_keyword(keyword, locale) 竞争度/建议（或接内部 API）

5.2 Resources（可选）

  • robots://{host} — robots.txt 内容
  • sitemap://{host} — sitemap 索引

供 Agent 预读，减少重复 crawl。
