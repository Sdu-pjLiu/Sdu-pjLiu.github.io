AI-Agent工程学习-Multi-Agent(四)

发表于 2026-07-18 更新于 2026-08-20 分类于 计算机
Message Passing / Shared Memory / Event Bus / Blackboard 四通信机制；并发、污染与框架映射。

接 Multi-Agent（三）：协作模式已定，本篇讲 Agent 间 如何交换信息——四种通信机制、并发风险与 LangGraph / Deep Agents / CrewAI 映射。

0. 本篇位置

角色（Who）+ 协作（How）+ 通信（Talk）= 可实现的 Multi-Agent 拓扑。治理层（Budget、LE Gate、HITL）贯穿各机制，不单独立篇——回链 Agent（四）§6。

原则： 通信 ≠ 把全文塞进 messages；大材料走外存、FS、证据指针（Agent（五）§2）。

1. Message Passing

维度 内容
数据形态 结构化 Handoff payload（Goal、open[]/done[]、证据指针、错误态）
强项 Context 隔离好；边界清晰；易审计
弱项 序列化设计成本；字段演进需版本化
框架映射 LangGraph state 字段更新；Deep Agents subagent 摘要返回；CrewAI Task context / output

场景片段： Research Worker 完成 → 只向 state 写入 {summary, evidence_refs[], status} → Writer Worker 从 state 读取，不读取 Research 完整 Trace。

与 Subagent 关系： Message Passing 是 Subagent Context Isolation 的 工程实现（回链 Agent（六）§4）。

2. Shared Memory

维度 内容
数据形态 全局 State、LangGraph Store、Flow Pydantic State、共享 KV
强项 多 Agent 低延迟读写同一事实
弱项 并发写冲突；租户串数据；脏读
框架映射 LangGraph Store + Reducer；Deep Agents FS + memory；CrewAI Flow State + Memory API

并发治理：

问题 措施
并行写同键 Reducer（append / merge）或 Coordinator 串行化写
租户隔离 Store namespace / thread_id / 租户前缀
脏读 版本号、时间戳、来源字段；读取侧权限过滤

回链 LangGraph（二）Reducer · LangGraph（三）Store。

3. Event Bus

维度 内容
数据形态 发布/订阅事件（research_done、guardrail_failed）
强项 发布者与订阅者解耦；易扩展新步骤
弱项 顺序保证难；重复投递需幂等
框架映射 CrewAI Flow @start / @listen / @router；跨服务见 §3.1 与 Agent工程化（四）

场景片段： Flow 发布 outline_ready → 监听方 kickoff Writer Crew → 失败发布 retry_outline → Router 决定回退或 HITL。

与 Coordinator 关系： Event Bus 常是 Coordinator 的 实现手段——Coordinator 监听事件驱动下一步，不替代 Supervisor 的内容验收。

3.1 图内事件 vs 跨服务 MQ

图内 / Flow 事件 跨服务 MQ
示例 @listen、LangGraph 边 / Command Redis Pub/Sub、Celery、Kafka
范围 单应用编排 多服务解耦
须注意 不等于生产总线 幂等消费、顺序、死信、分区键

生产落地见 Agent 工程化（四）§7。

4. Blackboard Architecture

维度 内容
数据形态 公共「黑板」：多 Worker 读写假设、证据、中间结论
强项 多源证据汇聚；适合 Research 黑板模式
弱项 写污染（猜测当事实）；脏读；黑板过大
框架映射 LangGraph Store + 结构化 schema；RAG 外存作只读事实层；Deep Agents FS 作材料黑板

与 Shared Memory 区别： Blackboard 强调 多专家贡献同一演化知识结构；Shared Memory 偏通用 KV。工程上可共用 Store，但 Blackboard 须 字段级权限与来源标注。

场景片段： 竞品 Research——搜索员写 evidence[]、分析员写 claims[]（须带 source）、写作员只读已验证 claims[] 成稿。

5. 通信机制选型表

需求 首选机制 注意
子任务隔离、Handoff 清晰 Message Passing 默认首选
多 Agent 共享任务 state Shared Memory Reducer + 租户 namespace
应用流程解耦、事件驱动 Event Bus 幂等 + 顺序策略
多源 Research 汇聚 Blackboard 来源标注 + 防写污染
长材料传递 ** none 全文 ** 外存 / FS + 指针

6. 通信 × 协作 组合示例

拓扑 协作模式 通信组合
研究流水线 Role-Based Message Passing 链式 Handoff
并行多源检索 Voting Shared Memory 写入 + 聚合节点读取
内容运营 Flow Role-Based + HITL Event Bus 驱动 Crew
竞品黑板 Hierarchical + Research Blackboard Store + Message Passing 给 Writer

总结

Message Passing： 默认首选；Handoff 合同；Subagent 摘要。

Shared Memory： Store + Reducer；防并发与串租户。

Event Bus： Flow 事件；跨服务用 MQ；须幂等——见 §3.1。

Blackboard： 多源汇聚；防写污染与脏读。

原则： 大材料不进 messages；证据用指针。
