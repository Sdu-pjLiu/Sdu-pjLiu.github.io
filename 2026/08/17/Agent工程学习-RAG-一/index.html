AI-Agent工程学习-RAG(一)

发表于 2026-07-20 更新于 2026-08-20 分类于 计算机
RAG 开篇：Embedding/Chunk/Index/Retrieve/Generate 评测驱动管线；LangChain 实现；与 LangChain（四）分工。

接 Deep Agents · 自检与面试：Harness 与长任务 Context 治理已学；当 Agent 需要 企业文档、政策手册、产品知识 等外存事实时，进入 RAG 系统 垂直模块——用 LangChain 把检索管线做深、做可测、做可运维。

1. 选型：Chain vs Tool vs Graph

形态 何时用 LangChain 入口
LCEL 确定性链 每问必检一次；路径固定 retriever | prompt | model（见 LangChain 四）
Retriever Tool 是否检索、检几次由模型决定 @tool + create_agent
LangGraph 编排 多跳、评分、改写、分支 StateGraph（见 RAG 三、四）

回链 Agent（三）：预注入适合「每次必查固定库」；Tool 适合「按需检索」。

2. Embedding

LLM（一） 已讲向量语义；工程上额外关注：

维度 建议
模型 与语料语言一致；中英文混库选多语 embedding
维度 高维未必更好；与向量库、延迟、成本权衡
版本 embedding_model_id 写入索引 metadata；换模型通常需重建索引
归一化 部分库要求 L2 归一化；查询与索引侧一致

LangChain 侧：OpenAIEmbeddings、HuggingFaceEmbeddings 等，与 LangChain（一） 同一接口。

3. Chunking

策略 特点 适用
固定长度 实现简单 均质文本
递归分隔 按 \n\n、句号等切 Markdown / 技术文档
结构感知 按标题、章节、表格边界 手册、Wiki
语义切块 按 embedding 相似度合并句 长叙述、论文（成本更高）

metadata 最小集（供过滤与引用）：

切块过 粗：检索命中段落过大、噪声多；过 细：丢失上下文、引用难读。先用 dev 集扫 chunk_size / overlap（常见 512–1024 token，overlap 10%–20%）。

4. Indexing

组件 认名
VectorStore 内存 / Chroma / PGVector / 云向量库
HNSW / IVF 近似最近邻索引结构（库内实现，换库需读文档）
增量 新文档 add；删改需 delete + 重 embed 或版本号字段
全量重建 embedding 模型升级、schema 变更时的标准操作

工程习惯：索引名含 {corpus}_{embed_model}_{date}，避免 silent 混版本。

5. Retrieval

Retriever 统一接口：invoke(query) -> list[Document]。

方法 作用
similarity_search Top-K 余弦/内积近邻
similarity_search_with_score 带分数，可设 阈值 拒答
MMR 最大边际相关性，减近重复块

空结果策略： 不硬生成——返回「未找到依据」或触发 Query 改写（见 RAG 二）；与 LE Gate 对齐。

8. RAG 评测入门

先测 检索，再测 生成：

指标 含义
Recall@K 标准答案所需 chunk 是否出现在 Top-K
MRR 第一个正确 chunk 的排名倒数均值
Citation 正确率 答案引用是否指向真实命中 chunk
Faithfulness 答案陈述是否有 Observation/检索支撑
Task Success 端到端 Rubric（回链 Agent 四）

L0 实验： 准备 20–50 页语料 + 10 问评测集（含标准引用 doc_id）；跑朴素 RAG，记录 Recall@4 与人工 Faithfulness，作为后续增强的 baseline。

8.1 黄金集与回归节奏（生产）

是什么： 「跑通一次评测」≠「可持续守住质量」。黄金集是固定、可版本化的问答与 gold 引用，用于发版回归。

字段（最小） 作用
question 用户问法（可含改写变体 ID）
gold_chunk_ids / gold_source_ids 检索必须命中的证据
must_cite 生成必须引用的 source
forbidden_docs 越权/无关文档（多租户用例）
rubric Task Success 要点（可勾选）

节奏：

注意点 / 反模式：

  1. 只测「模型觉得答案好」不测 gold chunk → 检索退化发现不了。
  2. 黄金集从不更新 → 与真实 query 分布脱节。
  3. 坏例修完不入库 → 同一幻觉反复上线。

9. 评测工具认名

原则： 本篇 §8 与 Agent（四）§6 中的指标是 工程口径；RAGAS / DeepEval / TruLens 等是 自动化实现，不是第二套标准。选型时看：能否输出与 Trace 字段一致的 Recall、Faithfulness、Citation 结果。

文内指标 RAGAS / 同类 说明
Recall@K context_recall 等 不完全同构：文内 Recall@K 需 gold chunk id 且 K 一致；RAGAS 多为陈述级/LLM 评判，勿直接横比
Faithfulness faithfulness / groundedness 断言 ↔ 检索 context
Citation 正确率 自建 Rubric + structured output 无通用开箱指标，以 doc_id 对齐为准
Task Success dataset run / 自定义 Scenario 回链 Agent（四）§6 Scenario 集

安全提醒： 检索正文同样是不可信 Context——知识库投毒 / 片段内指令注入见 PE（四），RAG 层至少做来源隔离与 Citation Gate。

DeepEval / TruLens 与 RAGAS 同类：批量跑断言级指标。若已用 LangSmith Dataset + Experiment，优先与 LangChain（六）§4 对齐，避免同一发版跑两套不互通的报表。

发版回归的完整五域 Checklist 见 Agent（四）§6；RAG 域指标与本节 §8 一致。

总结

定位：RAG 系列 = LangChain 实现 + 评测驱动的检索垂直深化；LangChain（四）为预习。

管线：Embed → Chunk（metadata）→ Index → Retrieve（阈值/MMR）→ Grounded Generate。

选型：固定路径用 LCEL；按需检索用 Tool；多跳用 LangGraph。

评测：Recall@K、引用正确率先于堆增强；§9 工具认名（文内指标为主）。
