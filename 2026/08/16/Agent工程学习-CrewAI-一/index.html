AI-Agent工程学习-CrewAI(一)

发表于 2026-07-22 更新于 2026-07-20 分类于 计算机
CrewAI 开篇：Flow/Crew 双层架构、Role/Task 模型、与 LangGraph/Deep Agents 选型；CLI 脚手架。

接 MCP · 自检与面试：外部能力经 MCP 标准接入后，多角色协作编排进入 CrewAI——官方 v1.15+ 以 Flow（流程骨架）+ Crew（协作团队） 组织生产级多 Agent 应用；本篇讲定位与模块地图。

0. 本系列在学习路径中的位置

理论已学：

  • Agent（二）规划式 / Hierarchical — 任务分解与委派
  • LangGraph（六）Supervisor / Router — 图级 Multi-Agent 拓扑
  • Deep Agents（四）Subagent — 厚 Harness 内委托与 Context 隔离
  • Agent（四）§6 发版 Checklist — 评测与回归口径

本系列分工： LangGraph = 显式图编排 Runtime；Deep Agents = 预装 FS/Skills/Subagent 的厚 Harness；CrewAI = 角色驱动 Crew + 事件驱动 Flow 的产品化多 Agent 框架。

产品/框架 本路径角色
LangGraph StateGraph、Checkpoint、Interrupt
Deep Agents create_deep_agent 长任务厚栈
CrewAI Flow 应用骨架 + Crew 协作单元

官方：CrewAI Introduction · First Flow · Production Architecture

0.1 CrewAI 模块地图

官方架构：Flow 是 backbone，Crew 是 intelligence。

本系列五篇分工：

篇 覆盖
（一） 定位、双层架构、选型、CLI
（二） Agent / Task / 五类能力扩展
（三） Crew / Process / Flow 编排
（四） Knowledge / Memory / MCP / 观测
（五） HITL / Training / 生产项目 / 全路径收口

生产建议（官方）： 任何生产应用 先从 Flow 开始；需要创意协作的子步骤再委派 Crew。

1. Flow vs Crew：何时用哪个

需求 用 Flow 用 Crew
管状态、分支、持久化、接 API ✓
多角色辩论、写作+审稿协作 ✓
单次结构化 LLM 输出（大纲 JSON） 直接 LLM.call 过重
10 步固定 ETL Python 任务链 过重
调研→分析→成稿（开放质量） Flow 编排 Crew 执行

协作六步（官方）：

  1. Flow 触发事件
  2. Flow 管理状态、决定下一步
  3. Flow 委派复杂任务给 Crew
  4. Crew 内 Agent 协作完成
  5. Crew 返回结果给 Flow
  6. Flow 继续后续逻辑

2. 与 LangGraph / Deep Agents 选型

维度 LangGraph Deep Agents CrewAI
编排表达 Node/Edge 显式图 编译图 + 默认 Middleware Flow 装饰器 + Crew 声明
多 Agent Supervisor/Subgraph task() Subagent Role + Process
配置风格 Python 为主 Python + Profiles JSONC + Python
长任务 Context 自建 Middleware 预装 Summarization/FS Memory + Flow state
适合 精细拓扑、混合确定性步骤 长任务 coding/research 角色化团队、快速产品化

回链 Agent（六）§7： CrewAI 是 Multi-Agent 协作框架 的一种实现，不替代 Loop Contract 与 Runtime Gate——仍须 Budget、Citation、越权拦截（见 LE、Agent 四）。

默认组合建议：

  • 企业流程 步骤固定 → LangGraph 或 Flow 内 Python
  • 长材料 + FS + Subagent 隔离 → Deep Agents
  • Researcher + Writer + Editor 角色团队 → CrewAI Crew

3. 核心概念速查

概念 一句话
Agent 带 role/goal/backstory 的执行者
Task 可验收工作单元 + expected_output
Crew Agent 团队 + Task 列表 + Process
Process sequential（流水线）/ hierarchical（Manager 委派）
Flow 事件驱动工作流 + 状态 + 控制流
Guardrail Task 输出校验，失败可重试
Knowledge 预加载 RAG 事实库
Memory 跨 run 统一记忆 API

4. CLI 与项目脚手架

典型目录（Flow 项目）：

v1.15+ 新项目推荐 JSONC 配置 Agent/Task/Crew；老项目常见 Python + YAML，读源码时需两种都认。

5. LLM 与 Provider 认名

  • 模型字符串格式：provider/model-id（如 openai/gpt-4o-mini）
  • 底层经 LiteLLM 统一多厂商
  • .env 配置各厂商 API Key
  • Crew 级可设 llm；Agent 级可覆盖；另有 function_calling_llm 专用于 tool call

与 LangChain 路径关系： CrewAI 是 独立框架，不编译为 LangGraph Runnable；可与 LangChain Tool/MCP 概念对照，但 API 不混用。

本模块自检与面试

学完 CrewAI 系列五篇后，请到 CrewAI · 自检与面试。

总结

定位：CrewAI = Flow（控制流 + 状态）+ Crew（角色协作）；接 MCP 后的 Multi-Agent 产品化路径。

架构：生产应用先 Flow；复杂子问题再 Crew；轻量步骤用 Python/直接 LLM。

选型：精细图 → LangGraph；长任务厚栈 → Deep Agents；角色团队 → CrewAI。

CLI：create flow → add-crew → run / plot / traces。
