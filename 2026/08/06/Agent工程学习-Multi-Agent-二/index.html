AI-Agent工程学习-Multi-Agent(二)

发表于 2026-07-18 更新于 2026-08-20 分类于 计算机
Supervisor / Worker / Coordinator / Router / Peer 五角色深讲；Handoff 合同与实现映射预告。

接 Multi-Agent（一）：五角色速查之后，本篇逐角色讲清 职责、决策权、失败模式、Handoff 合同 与三框架一行映射（不展开 API）。

0. 本篇位置

（一）已给 taxonomy 与分水岭；（二）角色深讲；（三）协作模式；（四）通信；（五）拓扑与 canonical 映射表。

Handoff 合同（全系列 universal）： 任意角色交接须携带——

字段 说明
Goal 摘要 用户目标与当前子目标
done[] / open[] 已完成与未完成项
硬规则引用 安全、引用、格式、租户边界
证据指针 URL / chunk_id / 文件路径，非全文
剩余预算提示（可选） steps/tokens 余量，避免子 Agent 不知何时收尾
错误态（Worker 返回时） 无结果 / 限流 / 权限 / 不可恢复

与官方 taxonomy： LangChain 多 Agent 文档常写 Subagents / Handoffs / Skills / Router。本系列用「角色 × 协作 × 通信」展开；其中 Handoff 既是合同字段，也对应官方「控制权在 Agent 间转移」的 Handoffs 拓扑（可经 Supervisor 回流，也可专员直接对用户）。Skills 是「不拆多 Agent」的官方替代——单 Agent + Skill 优先于过早拆角色。

回链 Agent（六）§4 · LangGraph（六）§2

1. Supervisor

维度 内容
职责 分解任务、选择 Worker、验收子结果、决定继续或结束
决策权 下一跳 Worker；是否触发 HITL；是否宣告完成
不做 替代 Worker 做全部工具调用（否则退化为单 Agent）
失败模式 无限委派；丢硬规则；无预算/步数上限；验收流于形式
框架映射 LangGraph Supervisor 节点；CrewAI hierarchical Manager；Deep Agents 主 Agent 委派

场景片段： 输入「调研 A、B 两家竞品并写对比报告」→ Supervisor 分派 Research Worker（A）、Research Worker（B）→ 验收证据覆盖率 → 分派 Writer Worker → Final Gate。

治理要点：

  1. 可选 Worker 集合 白名单化，禁止模型任意「发明」新角色
  2. 每轮分派 写入 Trace，含理由与预算消耗
  3. 结束条件 对齐 LE Gate，非「Supervisor 说完了」

2. Worker

维度 内容
职责 在 bounded 子目标内完成推理与工具调用
决策权 局部 query 改写、工具参数、重试策略（在沙箱内）
失败模式 越权调用；假完成；把猜测当事实 Handoff；错误不结构化
框架映射 LangGraph 子图 / create_agent Node；Deep Agents task() Subagent；CrewAI Agent + Task

Context Isolation（必守）： Worker 的完整 Trace 不得无限灌回主窗；只 Handoff 摘要 + 证据指针（回链 Agent（五）§2）。

结构化错误返回（生产必做）：

Supervisor 据此决定改 query、换 Worker、降级或 Interrupt——见 LangGraph 自检 I13。

3. Coordinator

维度 内容
职责 管理步骤依赖、并行门禁、超时与重试路由；不负责内容推理
决策权 何时启动下一步；是否并行 Send；失败子路径降级
与 Supervisor 区别 Coordinator 管 流程时钟；Supervisor 管 任务分解与质量验收
失败模式 与 Supervisor 合并导致「一个节点又协调又写报告」；并行无 Reducer 冲突
框架映射 CrewAI Flow @start / @listen；LangGraph 纯 Python 节点 + 边

场景片段： Flow 监听 research_done 事件 → 并行 kickoff 两个 Crew → 全部完成后触发 merge 节点——Coordinator 不写研报，只保证顺序与并发安全。

4. Router

维度 内容
职责 按意图/租户/模型能力将请求送入 固定分支
决策权 选分支（通常一次或少数几次分类）
失败模式 误分类无降级；分支过多导致维护地狱
框架映射 LangGraph conditional edge + 分类节点；CrewAI Flow @router

与 Supervisor 分水岭： 分支彼此 独立、无多轮协调 → Router；任务需 多轮分派与验收 → Supervisor（回链 LangGraph 自检 S21）。

场景片段： 用户输入含「退款」关键词 → Router 进客服子图；含「写代码」→ 进编码子图——两路径不再回到中心协调者。

5. Peer

维度 内容
职责 对等协商、互补专长；无默认中心
决策权 各自自治；冲突靠辩论/投票/协议
失败模式 重复劳动；争论不收敛；责任不清
框架映射 LangGraph 多节点 + Store（无中心拓扑）；外部框架巡览 · MAF / AutoGen 沿革 GroupChat 模式

何时考虑： 中心 Supervisor 已成瓶颈，且各 Agent 能自治、冲突有 收敛协议（Debate 轮次上限、Voting 聚合）——多数业务从 Router 或单 Supervisor 起步更可控。

5.1 冲突消解（并行必读）

多 Worker / Peer 同时写共享事实或争夺下一跳时，须预先选定策略，禁止「谁先写谁赢」的隐式行为：

策略 适用 说明
仲裁节点 Debate / 分歧汇总 Supervisor 或独立 Judge 聚合；须 max_rounds
优先级 角色权重不同 如合规 Worker > 文案 Worker；写 Store 带 priority
锁 / 串行化 同键关键写 Coordinator 串行写或分区键互斥
Last-write + 版本 可覆盖的草稿 必须带 version/updated_at/source；读者校验版本
Voting 聚合 冗余校验 N 路独立产出后规则或 LLM judge——见（三）

失败模式： 无策略并行写同键 → 非确定性合并；无仲裁 Debate → Token 爆炸且不收敛。

6. 角色组合速查

拓扑 角色组合 协作模式预告
意图分流 Router + Worker 见（三）Role-Based 变体
研究流水线 Supervisor + Worker×N Role-Based / Hierarchical
企业 Flow Coordinator + Crew CrewAI Flow + Crew
方案评审 Peer×N + Voting 聚合 Debate / Voting
探索发散 Peer + Shared Memory Swarm

总结

Supervisor： 分派与验收；须白名单、预算、LE 结束条件。

Worker： 原子子任务；Context 隔离 + 结构化错误返回。

Coordinator： 流程时钟；≠ Supervisor。

Router： 一次分流；简单意图首选。

Peer： 对等自治；需收敛协议；非默认首选。

Handoff： Goal、open[]/done[]、硬规则、证据指针 universal。
